# ATableSpec — ТЗ: поле «Стойки» и многослойные фильтры
Проект на согласование · 08.07.2026 · Денис / Алексей / Соколов

## Часть 1. Поле «Стойки» (по замечанию Алексея 08.07)

Проблема: поле «Стойки:» и подсказка к нему видны во всех отчётах, хотя нужны
только штапикам — пользователя это смущает.

Решение — видимость по контексту:
1. Поле «Стойки:» (с подсказкой) видно ТОЛЬКО когда активен шаблон «Штапики»
   (выбран в «Заголовке» или таблица штапиков открыта через ATSPECEDIT).
   Во всех остальных шаблонах поля на форме НЕТ.
2. При появлении поле сразу заполнено «RF-стойки» (текущий стандарт слоёв) —
   в типовом сценарии его не нужно даже трогать.
3. Если слоя «RF-стойки» в чертеже нет (чужой чертёж, другие стандарты) — поле
   остаётся видимым и пустым с пометкой «выберите слой стоек»: универсальность
   сохраняется без жёсткой зашивки имени.
4. Смена шаблона со «Штапиков» на любой другой скрывает поле И СБРАСЫВАЕТ его —
   чтобы настройка стоек не «уезжала» в определение обычной спецификации.

Итог для пользователя: в спецификациях/раскрое/заполнениях поля больше нет;
в штапиках оно есть, заполнено само и объяснено подсказкой.

## Часть 2. Многослойные фильтры

### Зачем (сценарии из практики)

С1. Сводная спецификация профилей: стойки + ригеля + створки ОДНИМ отчётом —
    сквозная нумерация, общая группировка по марке. Сейчас — только тремя
    отдельными секциями с раздельной нумерацией.
С2. «Всё, кроме»: рамкой весь витраж, отчёт по всем элементам, исключая
    служебные слои (0, _АР_..., ШТАПИК-РАЗРЕЗ).
С3. ИЛИ по значениям поля: «МАРКИРОВКА = Сп1 или Сп2 или Вр1». Сегодня такое
    собирается только инверсией через «не содержит», и то не всегда.
С4. Раскрой по двум слоям: доборники + крышки одного артикула в общий хлыст.

### Правило (вся новая логика — два предложения)

**Строки условий в гриде — как и раньше, «И».
Внутри «Значения» несколько вариантов пишутся через «;» — это «ИЛИ».**

Уточнения семантики:
- для «=» и «содержит» список значит «любое из»: `МАРКИРОВКА = Сп1;Сп2;Вр1`;
- для «≠» и «не содержит» список значит «ни одно из»: `Слой ≠ 0;_АР_ВИТРАЖ_БЛОКИ`
  (читается как «кроме этих» — ровно так, как говорят);
- для «>», «<», «≥», «≤» список НЕ допускается — форма не даст его ввести и
  подскажет; если такой фильтр попадёт в определение иным путём, движок возьмёт
  первое значение и не уронит таблицу;
- пробелы вокруг «;» игнорируются, пустые элементы («Сп1;;Сп2») отбрасываются;
- символ «;» зарезервирован как разделитель: значения, содержащие «;»,
  не поддерживаются (в маркировках КМД таких нет).

### Источник из нескольких слоёв

«Источник» секции — это и есть условие «Слой = ...», поэтому мультислойность
не требует новых понятий:
- в поле «Источник» можно перечислить слои через «;»:
  `RF-стойки; RF-ригеля; RF-створки` (сценарий С1, С4);
- рядом с пипеткой — кнопка «Несколько слоёв...»: окно со списком слоёв чертежа
  и галочками, отмеченные складываются в поле;
- «всё, кроме» (С2): «Источник» пустой + строка условия `Слой ≠ 0;_АР_...`
  («Слой» доступен в списке полей наравне с атрибутами);
- подсказки полей и значений при нескольких слоях — объединение по всем
  выбранным слоям; если у части блоков поля нет — ячейка пуста (как в СПДС),
  группа с разъехавшимися значениями подписывается «..., разн.» (как сейчас).

### Совместимость и защита от коллизий

- Уже построенные таблицы не меняются ни на волос: старый формат определения
  читается как прежде.
- Таблица с новым фильтром, открытая СТАРОЙ версией плагина, даст пустой отчёт
  С ОКНОМ ПРИЧИН (защита 07.07) — деградация видимая, тихой порчи строк нет.
- ATSPECEDIT-реверс возвращает списки в поля в том же виде «через ;».
- Нумерация, ИТОГ, объединённые шапки, мм-ширины — без изменений.

### Вне объёма v1 (сознательно)

- «ИЛИ» между РАЗНЫМИ полями (МАРКИРОВКА = X или Слой = Y) — усложняет модель;
  вернёмся только при реальном кейсе от Соколова.
- Условия «блок относительно соседнего блока» — это территория специальных
  препроцессоров (как разрезные штапики), не универсального фильтра.

### Приёмка (чек-лист Алексея на своём чертеже)

П1. Сводная спецификация трёх слоёв профилей: сквозные №, группа по марке.
П2. Отчёт «всё, кроме 0 и _АР_...»: служебных блоков в строках нет.
П3. Фильтр `МАРКИРОВКА = ...;...` из трёх марок: в отчёте только они.
П4. `не содержит Вр;Бг`: обе серии исключены одной строкой.
П5. Старая таблица (до обновления) пересчитывается без изменений раскладки.
П6. ATSPECEDIT новой таблицы: списки вернулись в поля как были.

### Этапность

Э1 — движок: списки значений в фильтре + полный набор юнит- и аудит-тестов.
Э2 — форма: ввод «;», окно «Несколько слоёв...», запрет списка на > < ≥ ≤,
     поле «Слой» в условиях, реверс.
Э3 — «Стойки» по Части 1.
Э4 — страница в мануал (полстраницы: правило «И/ИЛИ» + примеры С1–С4).

Э1–Э3 — один заход; сборка и проверка Алексеем — по готовности.
