# AClad — состояние и хэндофф (ЧИТАТЬ ПЕРВЫМ)

> **Это проект AClad — раскладка облицовки НВФ (этап 2 фасадного
> направления), ОТДЕЛЬНЫЙ бандл. НЕ путать с LD/физикой.** Выделен из
> Facades 22.07 по просьбе Германа: боевой этап 1 (AFacades: зоны/
> ведомости) ставится один раз, раскладка переустанавливается при
> каждой итерации. Грабли среды/сборки/push — `ATableSpec/docs/NEXT.md`
> (обязательны), методика фидбэка — `ABlockGen/docs/NEXT.md`, история
> направления и этапа 1 — `Facades/docs/NEXT.md`. Ветка общая:
> `feat/auto-reactor`; `main` — только по «Пушим».

## TL;DR
- **Что:** команда **ATCLAD** — раскладка облицовки универсальным
  блоком (кассетой) по зонам ATFZONE и/или замкнутым полилиниям.
  Гибрид: тонкий C# (`ACladPlugin.dll`) + замороженный движок
  (`clad_engine.exe`); бандл `AClad.bundle` в релизе `latest`.
- **Действующее ТЗ — письмо Германа 22.07** (дословно + статус:
  `docs/CLADDING.md` §ТЗ 22.07). Оно ЗАМЕНЯЕТ прежние В1–В8 при
  противоречиях: п.1.2 (целая по центру простенка, в обе стороны,
  кусок <300 — сдвиг на полплиты) вместо В5; режимов «Проемы/Край»
  больше нет — алгоритм один.
- **Связка с AFacades:** контракт данных общий (Xrecord «ATFZONE» на
  штриховках/марках читаем, свой ключ «ATCLAD» пишем;
  `<dwg>_fzones.json` — геометрия зон), реализация продублирована
  СОЗНАТЕЛЬНО (модули развязаны, обновляются независимо).
- **Статус на 07.08 (шапка обновлена — прежняя 22.07 врала «сборка
  не выкладывалась»):** ATCLAD и ATCLADDIM — боевой пилот у Германа,
  бандл в `latest` со сборки №12; несколько кругов фидбэка отработано
  (журнал — §Статус ниже). Движок `cladding_plan` 58 юнитов + CLI 12
  + краш-аудит 124 сценария — зелёные; допуск ортогональности
  контура `ortho_snap` 5 мм (04.08e). НЕ реализовано из ТЗ 22.07:
  **1.4/2.6** (точки горизонтальных рустов → локальные вертикальные
  датумы над окнами) и **1.3-хвост** (целая шире окна с перекрытием
  соседних пролётов).

## Файлы
- `engine/cladding_plan.py` — правила раскладки (ТЗ 22.07 в
  докстринге); `engine/clad_engine.py` — CLI (op=cladding, группировка
  голых контуров по вложенности — своя, от facade_zones НЕ зависит);
  `engine/test_*.py` — юниты (`PYTHONUTF8=1`, запуск из engine).
- `src/ACladPlugin/CladCommand.cs` — ATCLAD (диалог ТЗ 2.1–2.5,
  вставки, метка «ATCLAD» с параметрами и хэндлами, перегенерация
  удалением прежних); `Plugin.cs` — BuildStamp; сборка — build.yml
  (бандл 4-й), проверка — check.yml.
- `docs/CLADDING.md` — ТЗ дословно + модель данных/алгоритм;
  `docs/ATCLAD_manual.md` — инструкция Герману.

  `ortho_tol` (дефолт 5 мм, поле запроса), два прохода — второй ловит
  рёбра, ставшие ортогональными после сдвига соседа. Реально наклонные
  (скос, арка) отклоняются, но нота называет отклонение и допуск.

  **Осталось из фидбэка:** ATCLADDIM ставит размеры по всему чертежу
  вместо заданной области (Р-1) и не даёт выбрать слой из списка
  существующих (Р-2) — следующий заход, нужна форма.
- **04.08c — БАГ ATCLADDIM «панель <1250 — размер ерунда» (Денис):
  причина найдена в коде, фикс + встроенная диагностика.**
  `ATCLADDIM` брал габарит камня сырым `br.GeometricExtents`, а он
  возвращает ВСЁ содержимое вставки, не только контур: тексты
  атрибутов (с 01.08b ATCLAD дописывает в кассету МАРКИРОВКА/ЗАХВАТКА),
  заливки-видимости, вспомогательную графику. Разбор универсального
  блока `testdata/dxf/facades/blocks/Universalny_blok_oblitsovki_kasseta2.dwg`
  (aspose напрямую): контур камня — ОДНА LWPOLYLINE, в базовом
  определении 1240×1377, в растянутом представлении `*U4` — 1150×1205,
  то есть контур растягивается корректно; рядом лежат ATTDEF
  МАРКИРОВКА (h=130, поз. 597.9/616.5) + ЗАХВАТКА (h=50, поз. 0/0) и
  12 объектов на слоях «цвет 2..12» (aspose их не разбирает). Габарит,
  залипший на ~1240, объясняет ровно наблюдаемый порог: пока камень
  КРУПНЕЕ залипшего — размер верный, как только мельче — размер
  показывает залипшую величину; попутно полоса отбора ряда (строится
  по габариту кликнутого) начинает цеплять камни соседних рядов.
  **Фикс:** `CellExtents` — габарит только по КРИВЫМ (`Curve`) текущего
  (уже растянутого) определения, трансформированным `BlockTransform`;
  тексты/атрибуты/размеры/штриховки/солиды в габарит камня не входят.
  Фолбэк — сырой extents, если кривых в блоке нет. Белый список вместо
  чёрного (в ATableSpec.AddGab та же грабля ловилась чёрным). Заменены
  оба места: габарит кликнутого (полоса ряда) и габарит каждого камня.
  **Диагностика:** ATCLADDIM печатает «камень по контуру W x H; весь
  блок (с текстами/заливками) W2 x H2» — файл Дениса в чат не влезает,
  поэтому точную причину назовёт сам AutoCAD (разница = виновник).
  ATFRAMEDIM проверен — там координаты берутся из `Position`, той же
  болезни нет. `mcs --parse` чист; полная компиляция — CI.
