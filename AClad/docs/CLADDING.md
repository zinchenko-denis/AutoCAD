## ТЗ Германа 22.07 (дословно) и статус реализации

Раскладка в 90% случаев:
- **1.1** Точка старта; раскладка снизу вверх. ✓ (origin.y = низ
  первого ряда; ниже не кладём).
- **1.2** Простенки: целая плитка ПО ЦЕНТРУ, раскладка в обе стороны
  от центра; подрезка у окна < 300 мм — смещение на половину плиты.
  ✓ (_seg_centered: блок целых центрирован, равные куски; кусок <300
  — блок на одну целую меньше, куски +полшага ≥300).
- **1.3** Над/под окнами тот же анализ; камень шире окна — целая
  над/под окном. ✓ частично: пролёт над/под окном центрируется; хвост
  «целая ШИРЕ окна» (перекрытие соседних пролётов с подрезкой их
  камней) — НЕ РЕАЛИЗОВАН (вопрос Г2, план в NEXT).
- **1.4** Привязка по высоте к верху окон: над каждым окном своя
  точка старта (целая над окном, подрезка у верха следующего окна).
  ⏳ НЕ РЕАЛИЗОВАН (включается точками 2.6; план в NEXT).
- **1.5** Вокруг всех внутренних замкнутых областей — руст. ✓ (швы
  вокруг проёмов со всех сторон: гв слева/справа на всю высоту,
  гориз. руст сверху/снизу).
- **1.6** Внешний угол на участке — раскладка от угла типовыми
  (целыми). ✓ (_seg_from_corner: сегмент край-шов идёт целыми от
  края контура, подрезка у шва проёма).

Диалог перед раскладкой:
- **2.1** Наименование облицовки → слой, универсальный блок в него. ✓
- **2.2** Максимальные размеры (ширина/высота) → блок изменяется,
  раскладка типовыми размерами. ✓ (запрос с дефолтом с образца;
  размеры выставляются и образцу).
- **2.3** Выбор контуров или маркеров. ✓ (штриховки/марки ATFZONE
  и/или замкнутые полилинии).
- **2.4** Точка старта — общий горизонт (горизонтальные русты всех
  участков совпадают). ✓
- **2.5** Точки, через которые точно пройдёт вертикальный руст. ✓
  (vjoints: ось шва по точке, на всю высоту всех участков).
- **2.6** Точки горизонтального руста → режим 1.4. ⏳ НЕ РЕАЛИЗОВАН.

## Сценарий пользователя (Денис, 20.07 — дословно по шагам)

1. Запрос вида облицовки (пример: «керамогранит 600х600»).
2. Слой `Облицовка <вид>`; вставки универсального блока на этом слое;
   в блоке выставляются максимальные размеры камня (600×600 или заданные).
3. Запрос высотной отметки старта облицовки — ОБЩИЙ ГОРИЗОНТ: во всех
   контурах горизонтальные швы на одних отметках (глобальная сетка рядов).
4. Выбор контуров раскладки ИЛИ «меток, сделанных ранее» (см. §Метки).
5. Запрос вертикального и горизонтального руста (швов).
6. Запрос способа раскладки:
   - **«от проёмов»** — вертикальные швы совпадают с границами
     оконных/дверных проёмов, подрезка уводится от проёмов;
   - **«от края»** — слева направо целыми камнями, у примыкания к
     проёму и у правого края вертикальный ряд подрезается.

## Модель данных (вход движка, JSON)

```json
{
  "op": "cladding",
  "tile": {"w": 600.0, "h": 600.0},
  "gap":  {"v": 8.0, "h": 8.0},
  "datum": 0.0,
  "mode": "edge",
  "min_cut": 20.0,
  "contours": [
    {"outer": [[x,y], ...],
     "holes": [[[x,y], ...], ...]}
  ],
  "block": {"name": "Универсальный блок облицовки"},
  "layer": "Облицовка керамогранит 600х600"
}
```

- `gap.v` — ВЕРТИКАЛЬНЫЙ руст (шов между соседними камнями в ряду):
  шаг по X = w + gap.v. `gap.h` — горизонтальный руст (между рядами):
  шаг по Y = h + gap.h.
- `origin` {x, y} — ТОЧКА ПРИВЯЗКИ СЕТКИ РУСТОВ (фидбэк Германа
  21.07-2 п.3): левый нижний угол камня сетки. origin.y — низ первого
  ряда (сетка рядов глобальная: y_i = origin.y + i·(h+gap.h), одна
  для всех контуров; ниже origin.y не кладём — В1). origin.x —
  вертикальная грань камня: модульная сетка столбцов в режиме «edge»
  и в пролётах без проёмов режима «openings». `datum` — синоним
  origin.y (обратная совместимость); без origin.x столбцы от левого
  края контура.
- ШВЫ ВОКРУГ ПРОЁМОВ (фидбэк 21.07-2 п.4): камень отступает от
  граней проёма на руст со всех сторон — слева/справа gap.v,
  сверху/снизу gap.h (вертикальные отступы probe-точкой в центре
  камня). В «openings» вертикальные швы у граней проёмов действуют
  на всю высоту контура (В2) — русты сквозные, стыков «камень в
  камень» не бывает.
- `contours[].outer` — замкнутая ОРТОГОНАЛЬНАЯ полилиния (все рёбра
  парал. осям); `holes` — проёмы (окна/двери) внутри контура.
  В C#-команде вложенность вычисляется автоматически: замкнутая
  полилиния внутри другой = проём (even-odd), отдельного запроса
  «укажите окна» нет.
- Выход: `inserts[] = {x, y, w, h}` (левый-низ камня, w/h — фактические,
  подрезанные ≤ tile), `summary` (целых/подрезанных/рядов), `notes`.

## Алгоритм

### Ряды и подполосы (вертикаль)

Ряд i занимает полосу [y_i, y_i + h]. Горизонтальные рёбра контура,
попадающие ВНУТРЬ полосы, режут её на подполосы; в каждой подполосе
X-интервалы внутренности постоянны (чётно-нечётное правило по
вертикальным рёбрам outer+holes). Камень подполосы имеет высоту
подполосы — так верхний ряд и ступени контура дают ПОДРЕЗКУ ПО ВЫСОТЕ
автоматически, без спецслучаев. Подполоса ниже `min_cut` — note, камни
не ставятся.

Ниже `datum` камни НЕ кладутся (отметка — СТАРТ облицовки); контур,
уходящий ниже, получает note «контур ниже отметки старта на N мм»
(→ вопрос В1).

### Раскладка в X-интервале [a, b] подполосы

- **mode="edge"**: модульная сетка от ЛЕВОГО КРАЯ КОНТУРА (x_min
  outer, общий для всех рядов контура — швы соосны по всей высоте):
  столбец j — [x_min + j·(w+gap.v), … + w]. Камень сетки, целиком
  попавший в [a,b] — целый; частично — подрезается по границе
  интервала (примыкание к проёму, правый край). Остаток < min_cut —
  note, не ставится.
- **mode="openings"** (правила уточнены ответами Германа В2/В5,
  20.07): якоря = X-границы ВСЕХ проёмов контура и действуют на ВСЮ
  его высоту — вертикальные швы простенков продолжаются в рядах
  над/под проёмами (В2). Интервал режется внутренними якорями на
  сегменты. Сегмент между двумя якорями (простенок, в т.ч.
  «виртуальный» над/под проёмом): целые от обеих границ навстречу,
  остаток rem: **rem ≥ 300 — ОДИН подрезной в середине; rem < 300 —
  ЦЕЛАЯ плитка в середине (блок n−1 целых центрируется), по краям два
  равных подрезных (rem+w)/2, при 600-м камне всегда ≥300** (В5).
  Якорь с одной стороны: целые от него, подрезка у противоположного
  (контурного) края. Совсем без якорей (контур без проёмов):
  раскладка от левого края интервала.

### Метки (§4 сценария — «выбрать метки, сделанные ранее»)

Рабочая гипотеза: после раскладки программа записывает на контур
XData (вид облицовки, tile, датум, русты, режим) — «метка». Повторный
запуск: «выбрать метки» = выбрать помеченные контуры, параметры
берутся из метки (перегенерация в том же горизонте без повторного
диалога). → вопрос В3.

## Контракт блока — ФАКТЫ из DWG (20.07, tools/dwg_probe.py)

Блок **«кассета 2»** (в чертеже — анонимные *U-представления):

- **База (0,0) = левый-нижний угол** замкнутого контура LWPOLYLINE —
  вставка левым низом ПОДТВЕРЖДЕНА (как у витражных заполнений).
- Определение нарисовано 1240×1377; вставка в файле растянута до
  1150×1205 — **обе линейные растяжки живые** (BLOCKLINEARPARAMETER +
  BLOCKSTRETCHACTION/BLOCKMOVEACTION по таблице классов).
- **BLOCKVISIBILITYPARAMETER ЕСТЬ** — у кассеты есть переключение
  видимости (что переключает — вопрос В8).
- ATTDEF (переменные, дефолт пуст, слой «маркировка кассет»):
  **МАРКИРОВКА** (prompt «маркировка», h=130) и **ЗАХВАТКА**
  (prompt «ввести номер захватки», h=50).
- Графика: контур + 12 HATCH (заливка кассеты).
- **Имена динпараметров из DWG не извлекаемы** (прокси-объекты; грабля
  в tools/dwg_probe.py) → C#-команда читает имена с УКАЗАННОГО ОБРАЗЦА
  в рантайме (DynamicBlockReferencePropertyCollection): числовые
  линейные — растяжки (пара ширина/высота), параметр с AllowedValues —
  видимость; движку имена передаются в запросе (паттерн body_w/fold
  витражей). Вопрос В7 — подтвердить имена для дока.

Спецификация камней потом снимается ATableSpec (блочный контракт —
та же связка, что у витражей); ЗАХВАТКА дружит с захватками Facades.
