# Мелкоштучная раскладка по образцу (команда ATTILE, модуль AClad)

> Третья команда AClad (после ATCLAD/ATCLADDIM). Родилась из задания
> Германа 09.09: бетонная плитка 290×82, руст 7 мм, шахматный порядок
> со смещением рядов на полплиты, раскраска по типовой схеме 6×10.
> ATCLAD (кассеты) и ATTILE (мелкая плитка) — РАЗНЫЕ алгоритмы, общий
> движок `clad_engine.exe`, общий бандл AClad.

## Чем отличается от ATCLAD

| | ATCLAD (кассеты) | ATTILE (мелкая плитка) |
|---|---|---|
| Камень | крупная кассета/панель | плитка/кирпич (напр. 290×82) |
| Рисунок | целые от центра/угла простенка (ТЗ Германа 1.2) | перевязка со сдвигом рядов + РАСКРАСКА по образцу |
| Цвет | один тип | 3–6 типов, узор задаёт нарисованный образец |
| Датум | точка старта + общий горизонт | угол габарита (дефолт, В1 Германа) / угол стены / точка |
| Подрезка | у проёмов, min_cut по ширине | у проёмов/кромок; полоски < порога поглощает руст; заготовки — раскроем |

## Поток команды (ATTILE)

1. **Выбрать образец** — крашеные плитки (замкнутые полилинии или
   штриховки). Тип плитки = слой объекта, цвет типа = цвет слоя.
   Движок по сетке образца строит раппорт: число столбцов/рядов,
   порядок цветов (снизу вверх, слева направо) и сдвиг каждого ряда
   в долях модуля.
2. **Размеры плитки и русты** (дефолты — с образца и 7 мм).
3. **Порог полоски** (дефолт 10 мм) и **пропил раскроя** (дефолт 3 мм).
   Кусок, у которого меньший габарит меньше порога, ПОГЛОЩАЕТСЯ рустом
   (ответ Германа В3): в раскладку не идёт, в чертёж не рисуется, в
   счёт не входит — только строка в сводке (сколько и какой площади).
   Кусок тоньше 0.1 мм — численный мусор, отбрасывается всегда.
4. **Датум** — откуда вести раскладку:
   - **Габарит** (ДЕФОЛТ — ответ Германа В1, «как у GPT»): правый-низ
     габарита зоны (Xmax, Ymin) — буквальное «справа налево, снизу
     вверх». Датум может лечь вне контура (на выступе/«ножке»).
   - **Стена**: правый нижний угол ОСНОВНОЙ стены — доминирующее (по
     суммарной длине) правое вертикальное и нижнее горизонтальное
     ребро наружной кромки. Целые плитки садятся на стену, подрезка
     уходит на выступы/«ножки»/откосы.
   - **Точка**: общая точка для всех зон = общий горизонт рядов
     (горизонтальные русты всех участков совпадают).
5. **Смежные контуры — одна плоскость?** (дефолт Да — ответ Германа
   В2: стены Б4–Б7 не независимы). Контуры, касающиеся по ребру
   (стык ≤ 1 мм), объединяются в одну зону с общей сеткой; плитка
   через шов — целая. «Нет» — каждый контур со своим датумом.
6. **Выбрать зоны** — штриховки/марки ATFZONE (контракт AFacades)
   и/или замкнутые полилинии (вложенная полилиния = проём).
7. Движок раскладывает; команда рисует: целые плитки — блоки
   `Плитка_<тип>` по слоям типов (цвет из образца), подрезка — контуры
   с заливкой на `Плитка_<тип>_ПОДРЕЗКА`. Метка `ATTILE` с параметрами
   и хэндлами — на объекты зоны (повторный запуск удаляет прежние
   плитки — перегенерация).
8. Сводка в командную строку: целых, кусков, поглощённых полосок,
   **заготовок на подрезку по раскрою**, итого плиток, минимум по
   площади, отходы раскроя в %. Спецификация по типам — командой
   **ATSPEC** по слоям `Плитка_*` (целые плитки INSERT'ами по типам —
   блочный контракт ATableSpec); заготовки и отходы — из сводки.

## Модель данных (вход движка, op="tile_pattern")

```json
{
  "op": "tile_pattern",
  "tile": {"w": 290.0, "h": 82.0},
  "gap":  {"v": 7.0, "h": 7.0},
  "sample":  [{"x0","y0","x1","y1","type"}, ...],
  "pattern": {"rows": [["T1","T2",...], ...],
              "row_shifts": [0.0, 0.5, ...]},
  "datum":   {"mode": "bbox"|"wall"|"point", "x"?, "y"?},
  "min_piece": 10.0, "tiny_mode": "absorb"|"layer",
  "kerf": 3.0, "merge_touching": true, "merge_tol": 1.0,
  "ortho_tol": 5.0,
  "zones":    [{"zone_id", "zone": {facade_zone/1}}, ...],
  "contours": [{"id", "pts", "bulges"?}, ...]
}
```

- `sample` ИЛИ `pattern` — одно из двух. С `sample` движок строит
  раппорт сам (`tile_pattern.pattern_from_sample`): `rows` снизу вверх,
  плитки слева направо; `row_shifts[j]` — сдвиг ряда `j` относительно
  нижнего, в долях модуля `w+gap.v`, приведён к [0, 1) (для шахматки
  0, 0.5, 0, 0.5 …).
- `gap.v` — вертикальный руст (шаг по X = `w+gap.v`), `gap.h` —
  горизонтальный (шаг по Y = `h+gap.h`).
- `datum.mode` — см. п.4 (дефолт `bbox`). При `point` (или
  переопределении `x`/`y`) сетка всех зон отсчитывается от одной
  точки — общий горизонт.
- `merge_touching` — смежные контуры (стык по ребру ≤ `merge_tol`)
  объединяются в одну зону; координаты стыка сводятся к общему
  значению, иначе slab-декомпозиция оставит щель и порежет плитки
  через шов (ровно это случилось у GPT: щель 0.056 мм → −1520 целых).
- `min_piece`/`tiny_mode` — полоски: `absorb` (дефолт) — поглощены
  рустами, в выходе их нет, только `absorbed{count,area}` по зоне;
  `layer` — прежнее поведение (кусок с флагом `tiny`).
- `kerf` — пропил при раскрое подрезки.
- `zones` — геометрия `facade_zone/1` из `<dwg>_fzones.json` (контракт
  AFacades); `contours` — плоские замкнутые полилинии (вложенность
  outer/проёмы движок разбирает сам, как в op="cladding").
- `ortho_tol` (дефолт 5 мм): почти ортогональные рёбра контура из АР
  выпрямляются; остаточная невязка (сотые мм) сводится кластеризацией
  координат к точным орто-значениям. Реально наклонный контур (скос,
  арка) отклоняется с note.

Выход: `pieces[] = {i, j, type, full, x, y, w, h, rect, tiny, area,
rings?}` (`rings` — только у фигурных Г-образных кусков у углов
проёмов; у прямоугольных x/y/w/h), `per_zone[]` (датум, площади,
поглощённые полоски, счёт и раскрой по типам), `summary` — по типам
и итого: `full`, `cut` (кусков), `blanks_cut` (заготовок на подрезку
по раскрою), `tiles_total = full + blanks_cut`, `tiles_by_area`
(минимум по площади), `waste_area`/`waste_pct` (отходы раскроя),
`absorbed`, раппорт; `notes`.

## Правила раскладки (движок tile_pattern.py)

- Сетка: модуль `MX = w+gap.v` по X, `MY = h+gap.h` по Y. Плитка `(i,j)`
  ряда `j` (от датума вверх) и столбца `i` (от правой кромки влево):
  `x1 = R − i·MX + row_shifts[j]·MX`, `y0 = B + j·MY`, где `(R, B)` —
  датум. Ниже и правее датума сетка тоже определена — выступы под
  стеной и правее её получают ту же сетку.
- Цвет: `type(i,j) = rows[j mod NR][(NC−1) − (i mod NC)]` — раппорт
  периодичен по обеим осям. Проверено: прямоугольник NC×NR у датума
  воспроизводит образец один в один, включая относительный сдвиг рядов.
- Клиппинг: зона режется на вертикальные полосы по X всех вершин
  (slab-декомпозиция), покрытие полосы — Y-интервалы по чёт-нечёт
  горизонтальных рёбер. Плитка ∩ зона: целая — если полосы покрывают
  всю плитку; иначе куски = компоненты связности прямоугольников,
  контур куска — объединение прямоугольников (Г-образный у угла окна).
- Раскрой (ответ Германа 09.09: «делался ли раскрой, как учтены
  обрезки и отходы» — раньше считалось «плитка на кусок», что давало
  +12% к площади и ~10% лишних против его расчёта): заготовки под
  подрезку = укладка кусков в целые плитки по зоне и типу
  (`nest_pieces`): полосы полной высоты — по ширине (first-fit-
  decreasing, пропил `kerf`), полосы полной ширины — по высоте,
  куски, резаные в обоих направлениях, — как полосы полной высоты
  (второй рез не переиспользуем), фигурные — плитка на кусок.
  Отходы = площадь заготовок − площадь кусков, отдельной строкой.
  Запас на бой/брак — параметр проектировщика, в движок не входит.

## Проверки

- `engine/test_tile_pattern.py` — 91 юнит (ручной счёт: чистая сетка,
  датумы bbox/wall/point и дефолт, половинки, раскраска по образцу,
  проём и фигурная подрезка, раскрой с пропилом, общий горизонт,
  объединение смежных контуров со щелью, поглощение полосок,
  восстановление раппорта из образца, CLI через файлы, метры,
  неортогональный контур). В CI (check.yml).
- Живой эталон (бетон 290×82, 20 зон, 3717 м²) с правилами Германа
  09.09 (датум габарит, Б4–Б7 одной плоскостью, полоски в русты):
  движок воспроизводит расчёт GPT-6 Astra **до штуки в 14 зонах из
  17**; три расхождения — дефекты GPT: в объединённой B04 они оставили
  щель 0.056 мм и ею порезали каждую плитку через шов (у нас +1520
  целых), на «ножках» Т3/Т5 микроскос рёбер давал им микронные куски
  вместо целых (+71/+59). Итог с раскроем: **118 627 целых, 41 342
  куска, 143 803 плитки всего (минимум по площади 140 639), отходы
  раскроя 2.2 %** — против 158 230 (плитка на кусок) и 162 036 у GPT.
  Фикстура: `tools/testdata/tiles290/tiles290_input.dxf`; обкатка без
  AutoCAD — `tools/tile_pattern_dxf.py` (ezdxf, пишет DXF + xlsx).

## Ответы Германа 09.09 (применены)

1. **Датум** — как у GPT: правый-низ габарита зоны («Габарит», дефолт).
2. **Смежные стены** — не независимы: одна плоскость, общая сетка
   (`merge_touching`, дефолт Да).
3. **Полоски** — поглощать рустами, в раскладке не учитывать
   (`tiny_mode=absorb`, порог 10 мм — предложение Логоса, Герман не
   возразил; параметр в диалоге).
4. **Раскрой/отходы** — «делался ли раскрой, как учтены обрезки»:
   прежний счёт «плитка на кусок» давал ~10 % лишних против расчёта
   Германа; введён раскрой кусков из целых плиток с пропилом и
   отдельной строкой отходов (см. §Правила). Порог полоски и пропил —
   в диалоге ATTILE.
