# Мелкоштучная раскладка по образцу (команда ATTILE, модуль AClad)

> Третья команда AClad (после ATCLAD/ATCLADDIM). Родилась из задания
> Германа 09.09: бетонная плитка 290×82, руст 7 мм, шахматный порядок
> со смещением рядов на полплиты, раскраска по типовой схеме 6×10.
> ATCLAD (кассеты) и ATTILE (мелкая плитка) — РАЗНЫЕ алгоритмы, общий
> движок `clad_engine.exe`, общий бандл AClad.

## Чем отличается от ATCLAD

| | ATCLAD (кассеты) | ATTILE (мелкая плитка) |
|---|---|---|
| Камень | крупная кассета/панель | плитка/кирпич (напр. 290×82) |
| Рисунок | целые от центра/угла простенка (ТЗ Германа 1.2) | перевязка со сдвигом рядов + РАСКРАСКА по образцу |
| Цвет | один тип | 3–6 типов, узор задаёт нарисованный образец |
| Датум | точка старта + общий горизонт | угол ОСНОВНОЙ стены (целые на стену) / габарит / точка |
| Подрезка | у проёмов, min_cut по ширине | у проёмов/кромок; полоски < порога — на свой слой |

## Поток команды (ATTILE)

1. **Выбрать образец** — крашеные плитки (замкнутые полилинии или
   штриховки). Тип плитки = слой объекта, цвет типа = цвет слоя.
   Движок по сетке образца строит раппорт: число столбцов/рядов,
   порядок цветов (снизу вверх, слева направо) и сдвиг каждого ряда
   в долях модуля.
2. **Размеры плитки и русты** (дефолты — с образца и 7 мм).
3. **Порог тонкой полоски** (дефолт 10 мм): кусок, у которого меньший
   габарит меньше порога, идёт на слой `Плитка_<тип>_ПОЛОСКИ` и в счёт
   плиток НЕ входит (на объекте поглощается рустами). Кусок тоньше
   0.1 мм — численный мусор, отбрасывается.
4. **Датум** — откуда вести раскладку:
   - **Стена** (дефолт): правый нижний угол ОСНОВНОЙ стены —
     доминирующее (по суммарной длине) правое вертикальное и нижнее
     горизонтальное ребро контура. Целые плитки садятся на стену,
     подрезка уходит на выступы/«ножки»/откосы.
   - **Габарит**: угол Xmax/Ymin габарита зоны — буквальное «справа
     налево, снизу вверх». Датум может лечь вне контура (на выступе).
   - **Точка**: общая точка для всех зон = общий горизонт рядов
     (горизонтальные русты всех участков совпадают).
5. **Выбрать зоны** — штриховки/марки ATFZONE (контракт AFacades)
   и/или замкнутые полилинии (вложенная полилиния = проём).
6. Движок раскладывает; команда рисует: целые плитки — блоки
   `Плитка_<тип>` по слоям типов (цвет из образца), подрезка — контуры
   с заливкой на `Плитка_<тип>_ПОДРЕЗКА`, полоски — на `_ПОЛОСКИ`.
   Метка `ATTILE` с параметрами и хэндлами — на объекты зоны
   (повторный запуск удаляет прежние плитки — перегенерация).
7. Спецификация — командой **ATSPEC** по слоям `Плитка_*` (целые
   плитки INSERT'ами по типам — блочный контракт ATableSpec). Сводка
   по типам и заготовкам печатается в командную строку.

## Модель данных (вход движка, op="tile_pattern")

```json
{
  "op": "tile_pattern",
  "tile": {"w": 290.0, "h": 82.0},
  "gap":  {"v": 7.0, "h": 7.0},
  "sample":  [{"x0","y0","x1","y1","type"}, ...],
  "pattern": {"rows": [["T1","T2",...], ...],
              "row_shifts": [0.0, 0.5, ...]},
  "datum":   {"mode": "wall"|"bbox"|"point", "x"?, "y"?},
  "min_piece": 10.0,
  "ortho_tol": 5.0,
  "zones":    [{"zone_id", "zone": {facade_zone/1}}, ...],
  "contours": [{"id", "pts", "bulges"?}, ...]
}
```

- `sample` ИЛИ `pattern` — одно из двух. С `sample` движок строит
  раппорт сам (`tile_pattern.pattern_from_sample`): `rows` снизу вверх,
  плитки слева направо; `row_shifts[j]` — сдвиг ряда `j` относительно
  нижнего, в долях модуля `w+gap.v`, приведён к [0, 1) (для шахматки
  0, 0.5, 0, 0.5 …).
- `gap.v` — вертикальный руст (шаг по X = `w+gap.v`), `gap.h` —
  горизонтальный (шаг по Y = `h+gap.h`).
- `datum.mode` — см. п.4. При `point` (или переопределении `x`/`y`)
  сетка всех зон отсчитывается от одной точки — общий горизонт.
- `zones` — геометрия `facade_zone/1` из `<dwg>_fzones.json` (контракт
  AFacades); `contours` — плоские замкнутые полилинии (вложенность
  outer/проёмы движок разбирает сам, как в op="cladding").
- `ortho_tol` (дефолт 5 мм): почти ортогональные рёбра контура из АР
  выпрямляются; остаточная невязка (сотые мм) сводится кластеризацией
  координат к точным орто-значениям. Реально наклонный контур (скос,
  арка) отклоняется с note.

Выход: `pieces[] = {i, j, type, full, x, y, w, h, rect, tiny, area,
rings?}` (`rings` — только у фигурных Г-образных кусков у углов
проёмов; у прямоугольных x/y/w/h), `per_zone[]` (датум, площади,
счёт по типам), `summary` (итоги, заготовки, раппорт), `notes`.

## Правила раскладки (движок tile_pattern.py)

- Сетка: модуль `MX = w+gap.v` по X, `MY = h+gap.h` по Y. Плитка `(i,j)`
  ряда `j` (от датума вверх) и столбца `i` (от правой кромки влево):
  `x1 = R − i·MX + row_shifts[j]·MX`, `y0 = B + j·MY`, где `(R, B)` —
  датум. Ниже и правее датума сетка тоже определена — выступы под
  стеной и правее её получают ту же сетку.
- Цвет: `type(i,j) = rows[j mod NR][(NC−1) − (i mod NC)]` — раппорт
  периодичен по обеим осям. Проверено: прямоугольник NC×NR у датума
  воспроизводит образец один в один, включая относительный сдвиг рядов.
- Клиппинг: зона режется на вертикальные полосы по X всех вершин
  (slab-декомпозиция), покрытие полосы — Y-интервалы по чёт-нечёт
  горизонтальных рёбер. Плитка ∩ зона: целая — если полосы покрывают
  всю плитку; иначе куски = компоненты связности прямоугольников,
  контур куска — объединение прямоугольников (Г-образный у угла окна).
- Заготовки: 1 плитка на кусок; половинки высотой в плитку и шириной
  `w − |shift|·MX` (от смещения рядов) — 2 из одной плитки; полоски
  меньше порога — вне счёта.

## Открытые вопросы Герману

1. **Датум по умолчанию** — угол основной стены (реализовано, «Стена»)
   или угол габарита («Габарит»)? На зонах-«ножках» это даёт полоску
   24 мм по низу стены (габарит) против целого ряда (стена).
2. **Смежные стены одного контура** (несколько плоскостей в одном
   REGION) — одна общая сетка или независимые участки с углами?
3. **Полоски** — порог (10 мм?) и что с ними: поглощать рустами,
   сдвигать фазу сетки, оставлять в счёте.
4. **Подбор фазы сетки** под минимум подрезки (перебор 0…MX по X,
   0…MY по Y на зону) — надо ли; это выходит за буквальное
   «справа налево, снизу вверх», но убирает большинство узких кусков.
5. **Раппорт**: где граница повторения образца, если образец крупнее
   6×10? Сейчас берётся весь образец как раппорт.
