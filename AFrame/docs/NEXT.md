# AFrame — состояние и хэндофф (ЧИТАТЬ ПЕРВЫМ)

> **Это проект AFrame — подсистема НВФ (этап 3 фасадного направления):
> кронштейны + направляющие + кляммеры по согласованной раскладке
> AClad. НЕ путать с LD/физикой.** Концепт и решения —
> `Facades/docs/STAGE3_FRAME.md` (В13–В20 закрыты Денисом/фактами
> боевого DWG 24.07). Грабли среды/сборки — `ATableSpec/docs/NEXT.md`;
> методика фидбэка — `ABlockGen/docs/NEXT.md`. Ветка общая
> `feat/auto-reactor`; `main` — только по «Пушим».

## TL;DR
- **Что:** команда **ATFRAME** (этап Э2, ещё не написана) — монтажные
  схемы подсистемы по зонам с меткой ATCLAD: стойки по осям
  вертикальных рустов, несущие кронштейны на отметках перекрытий
  (центр — В15), рядовые равномерно (В16), кляммеры по горизонтальным
  швам; условные знаки СВОИ (В13: DWG блоков Герман даст позже),
  слои Германа `_01_ПС_*` (В19).
- **Порядок целевой (Денис 24.07): расчёт несущей способности → шаги
  → расстановка.** Пока расчёта нет — шаги из справочника систем
  (systems.json: Вектор-1 / Standart / Межэтажная) с подтверждением
  конструктором; модуль расчёта (этап 4) встанет ПЕРЕД движком и
  заменит дефолты.
- **Статус (24.07, Э1 ГОТОВ):** движок `engine/frame_plan.py`
  (op=frame: стойки рвутся проёмами по bbox, сегменты режутся
  отметками перекрытий, стык направляющих центрован на отметке с
  зазором системы; несущие/рядовые/кляммеры; summary с м.п. и
  прикидкой хлыстов) + `systems.json` + **22 юнита** (FR1–FR6 —
  числа руками; FR-D — факты боевого эталона
  `atspec-testdata/dxf/facades/frame_lenprospekt/frame_ps.json`:
  кляммеры 605, кронштейн ~300+~950, стойки 602.5–605). C#/бандла НЕТ.

## Файлы
- `engine/frame_plan.py` — движок Э1 (докстринг = модель данных);
- `engine/systems.json` — справочник систем (правила = атрибуты

- `engine/test_frame_plan.py` — 22 проверки (`PYTHONUTF8=1`, из

## Дальше (порядок ценности)
1. **Э2 — команда ATFRAME + бандл AFrame 5-м в build.yml**: чтение
   метки ATCLAD (оси из кромок камней; в метку AClad дописать
   joints_x[]/rows_y[] при ближайшей правке), диалог (система,
   отметки перекрытий кликами, подтверждение шагов), блоки-знаки в
   бандле (квадрат/ромб с крестом в круге r75 — по образу Германа,
   какой знак несущий — спросить), вставки на слои `_01_ПС_*`, метка
   «ATFRAME», перегенерация, clad_engine-паттерн CLI (frame_engine.py).
2. Прогон Германа на его фасаде → фидбэк → правки; его ручной эталон
   подсистемы на нашем тестовом фасаде → полная D-сверка.
3. Ведомость подсистемы через ATableSpec (блочный контракт:
   МАРКИРОВКА/ЗАХВАТКА у знаков).
4. Этап 4 — модуль расчёта (методики от Дениса) → шаги считаются.
