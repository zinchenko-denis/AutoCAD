# Блочный контракт VitrageGen ↔ ATableSpec

Эталон: `atspec-testdata/dxf/Проба_штапики_2.dxf` (разбор 13.07, ezdxf).
Генератор обязан выпускать РОВНО эту номенклатуру — тогда ATableSpec ест
результат без правок («сгенерил витраж — сразу спецификация и раскрой»).
Контракт доказан числами: `engine/test_vitrage_plan.py` строит план по
параметрам эталона и сверяет с живым DXF — 33 сверки (позиции ≤0.5 мм,
ДЛИНА и РАЗМЕР_ЗАП байт-в-байт).

## Номенклатура эталона

| Слой | Исходное определение | ATTRIB вставки | Динсвойства |
|---|---|---|---|
| RF-стойки | `17_07_24` | ИМЯ, ПРОФ, ДЛИНА (+R/L/DOBR/DOBL/UGR/UGL/KLR/KLL — деталировка, «0») | «Длина» (linear), «Марка» (видимость: С маркировкой/Без) |
| RF-ригеля | `17_06_01` | ИМЯ, ПРОФ, ДЛИНА (+KLR/KLL/UGR/UGL/DOBR/DOBL; в def ещё ЗАПИЛ/ШИРИНА) | «Длина», «Марка» |
| RF-заполнения | `СТП` | МАРКИРОВКА, РАЗМЕР_ЗАП | XY-параметр (→ «Ширина»/«Высота»), Visibility1 «Тип заполнения» (Тип 1/2/3) |
| RF-створки | `Створки` | МАРКИРОВКА (л1/п1/п2…) | XY («Ширина»/«Высота»), Visibility1 (Левое/Правое поворотное / поворотно-откидное) |
| RF-доборники | `Оц.уг.20х20` | ПРОФ (+ПРИВЯЗКА в В-13) | «Длина» |
| RF-кронштейны | (крепёж) | ИМЯ (П1/К/П6…), ДЛИНА и АРТИКУЛ пустые | — |

Все вставки в чертеже — анонимно-динамические (`*U…`, AcDbBlockRepresentation);
это результат установки динсвойств на вхождении исходного определения.
Плагин вставляет вхождение исходного определения и задаёт динсвойства —
анонимное представление AutoCAD создаёт сам.

## Геометрические правила (доказаны эталоном)

- **Стойка:** insert = (ось X, низ Y), rot=0. Тело в определении ±27.2 от оси
  (54.4 мм), базовая длина 1000, растяжка динсвойством «Длина».
  Атрибут ДЛИНА — текст `F2`: «2715.00».
- **Ригель:** insert = (ось ЛЕВОЙ стойки пролёта, ось ригеля Y), rot=270,
  «Длина» = ОСЕВОЙ шаг пролёта (705). Тело в определении с отступами 27.2
  (= полширины тела стойки) от концов → в чертеже само ложится в свет
  между телами стоек. Тело ригеля 45.6 (±22.8 от оси).
  Атрибут ДЛИНА = осевой шаг: «705.00».
- **Заполнение:** insert = (левый край света, низ света), rot=0;
  «Ширина»/«Высота» = свет (шаг − тело стойки; межосевое − тело ригеля).
  **РАЗМЕР_ЗАП = «{округл(светШ)+15}Х{округл(светВ)+15}»** — заход в фальц
  15 мм на ось, разделитель — КИРИЛЛИЧЕСКАЯ Х (U+0425).
  Подтверждено: Сп1 666Х519 (свет 650.6×504.4), Вр1/Эм1 666Х329 (…×314.4),
  Сп4 666Х1459 (…×1444.4), Сп2 666Х719 (…×704.4).
- **Осевая арифметика:** ширина проёма = n_пролётов × шаг + тело стойки
  (эталон: 2169.4 = 3×705 + 54.4); ось крайней стойки = край проёма + тело/2.
- **Ярусы стоек:** стык с зазором 10 мм (терморазрыв, «м/э зона»):
  ярус 2715 + 10 + ярус 2990. Ригели в зазор не ставятся.
  Эталонный стек — 11 ярусов, отметки ригелей периодичны
  (45/595/955, 2445/2805, 3555/3915, 5445/5805, …).
- **Марки эталона:** стойки С1л/С2п/С2л/С3п (л/п — исполнение, номер —
  типоразмер), ригели Р1/Р1-1/Р1н, заполнения Сп№/Вр№/Эм№ (префикс = тип
  заполнения). v1 генератора маркирует по типоразмерам (С1, С2… / Р1… /
  Сп1…) — суффиксы л/п и префиксы типов см. «Развилки» в NEXT.md.

## Что генератор НЕ делает (v1)

- Не выдумывает свои определения блоков — только вхождения существующих
  (выбор в диалоге, предвыбор эталонных имён).
- Створки, доборники, кронштейны, опоры — не генерируются (Э1 — сетка
  стойки/ригели/заполнения). Слои в модели плана заведены.
- Профильные системы/фрезеровки/запилы — вне v1 (унификация Алексея:
  безсистемная геометрия, сечение подбирается по жёсткости позже).

## АР-слои эталона (наблюдение для Э2/Э3)

В том же файле есть АР-представление витража: блоки на `_АР_ВИТРАЖ_БЛОКИ`
(секции по осям с тем же шагом 705), внутри — структурированные слои
`_АР_ВИТРАЖ_РИГЕЛЬ_`, `_АР_ВИТРАЖ_СТЕКЛОПАКЕТ`, `_АР_ВИТРАЖ_СТВОРКА_ИМПОСТ`,
`_АР_ВИТРАЖ_ИСПОСТ` (sic), `_АР_ВИТРАЖ_УПЛОТНИТЕЛИ`, вложенные вставки
(`_АР_ВИТРАЖ_ИМПОСТ`, ручки, петли). Если реальные АР приходят в таком виде —
Э3 (членение по импостам) реализуем чтением этих слоёв. Но это ОДИН источник;
вердикт по Э2/Э3 — только после 2–3 реальных АР от Алексея.
