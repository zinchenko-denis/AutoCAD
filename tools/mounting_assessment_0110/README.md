# Монтажная диагностика выбранного пилота

Проверить реальное чистое C# ядро, прежние численные эталоны и границы отказов:

```bash
python3 tools/mounting_assessment_0110/test_core.py --out /tmp/mounting-core
```

Нужны Mono/mcs на Linux либо .NET SDK с net48 references на Windows. Раннер использует общий `probe_runtime.py`. Приватные альбомы не требуются для повторения синтетики; инженерные выводы и локаторы опубликованы в `docs/mounting_assessment_0110/source_facts.json`.

Воспроизвести исходный пробел на точных исходниках `29dd386` без переключения рабочего дерева:

```bash
python3 tools/mounting_assessment_0110/reproduce_baseline.py --out /tmp/mounting-before
```

Скрипт читает через `git show` три старых файла C#, компилирует их отдельно и повторяет пять входов из публичного `baseline.json`. Требуется наличие коммита в локальном git; скрипт ничего не скачивает и не меняет в репозитории. Результаты и хеши должны совпасть с опубликованным воспроизведением. Разные пары длин, номиналов и исполнений сохраняют локальный просвет 20 мм. Это пробел монтажной диагностики, а не доказательство пригодности или непригодности этих пар.

Новый тест проверяет независимость статусов локальной геометрии и монтажа, запрет автоподбора, точные первичные локаторы, несовпадающий выбор и источник, неизменяемость результата, сохранность старых дайджестов и численных границ, обработку положительных проектных b/c за пределами decimal и стабильность повторов. Замеры относятся только к чистому ядру; они не подтверждают скорость живого AutoCAD.

Уточнение номинальной цепи проверяется тем же раннером. На одинаковых
заявленных плоскостях длины КР2 50/200/350 дают номинальные свободные
торцы 52/202/352 мм от основания: ПП добавляет 2 мм один раз, толщина
стенки КР2 повторно не прибавляется. Все 31 разрешённое значение L
проверяются без округления. Для УК 100/150 меняется только постоянная
часть тождества `x пятки УК = 2 + L КР2 + L УК − h`; численное h,
допустимый перехлёст и ход не назначаются. Координата ГП, её b/c,
номиналы изделий, исполнения и вынос облицовки не замыкают эту связь.
Тест отдельно проверяет точные локаторы и условия номинального вывода,
неизменяемость новых DTO, частичное подтверждение первых двух
зависимостей и сохранение общего `not_confirmed`/запрета автоподбора.
Результаты шести наглядных сочетаний сохраняются в `nominal_datums`
локального manifest. Схемы DWG, planes/2 и их прежние дайджесты
не изменяются.

Размерный перехлёст min30 той же пары КР2–УК на PDF 34/37/44/46
(листы 5.5/5.7/6.5/6.7) сохраняется как факт других узлов типов 2/3.
Отдельный тест не позволяет перепутать его с узлом 4.1 и пластинами У2/У
или превратить в подтверждённую нижнюю границу/ход пилота 4.2.1.

Первый локальный запуск теста ошибочно ожидал, что nullable-поля b/c можно оставить пустыми: тип DTO это допускает, но действующий строгий валидатор выбора требует положительное число. Был исправлен тест, а не расширен продуктовый контракт; повтор проверяет одинаковый отказ старого и нового пути. Отрицательный результат и его причина сохранены в протоколе этапа.
