# Проверки геометрического снимка

Этот набор компилирует настоящий `Common/GeometryFingerprint.cs` вместе с независимым C# driver. Он проверяет алгоритм сравнения контуров без Autodesk DLL, CAD doubles и запущенного AutoCAD.

Linux с доступными `mcs` и `mono`:

```sh
python tools/fixes_3009/test_zone_geometry.py --out /tmp/zone-geometry
```

Windows / CI:

```powershell
dotnet build tools/fixes_3009/GeometrySafetyCheck.csproj -c Release -o artifacts/geometry-check
artifacts/geometry-check/GeometrySafetyCheck.exe --report artifacts/geometry-check/cases.json
```

Код возврата native driver: `0` — все проверки пройдены, `1` — есть ошибка, `2` — неверные аргументы. Python wrapper возвращает `2`, если исходник или Mono недоступны, и сохраняет `manifest.json` с SHA256 использованных исходников, `cases.json` с результатом каждого случая и логи компиляции/запуска. Отсутствие среды не считается успешной проверкой.

Проверки включают:

- Разные вырезы с одинаковыми площадью **35 000 000 мм²**, bbox **6000 × 6000 мм** и периметром **26 000 мм**. Независимые формулы площади и длины в driver проверяют условия fixture до вызова production helper.
- Перенос окна при неизменной чистой площади; перенос всего снимка; изменение одного из нескольких объединённых контуров.
- Все начальные вершины и оба направления замкнутого контура; правильный перенос и смену знака bulge при обращении дуговых рёбер; обнаружение неправильного обращения bulge и замены дуг хордами. Отдельный случай: замыкающий участок с хордой 0,4 мм и bulge 10 000 имеет стрелу дуги 2000 мм, поэтому удалять его как незначительный хвост нельзя. Для этого исключительного входа допускается явный отказ с диагностикой, но не равенство прямолинейному контуру.
- Перестановку отверстий и частей; различие ролей; пропуск или дублирование части/отверстия. Положительные контроли запрещают считать любой отказ успешным обнаружением изменения.
- Численную эквивалентность в пределах заявленного `CoordinateTolerance` и обнаружение переноса выше него; открытый путь сохраняет значимость направления по контракту helper.
- Явную закрывающую вершину, линейную промежуточную вершину, NaN/Infinity, неверную размерность точек, длину массива bulges и отсутствующую роль.

Граница доказательства: этот набор **не** проверяет чтение Hatch/Polyline, ассоциативное обновление Hatch, remapping ObjectId при COPY, перенос MText, полноту AutoCAD-группы, reactor/Undo и работу команд внутри AutoCAD. Случаи нескольких частей доказывают полноту входного списка pure helper; включение всех источников в этот список проверяется отдельно в адаптере. Для guards необходимы отдельная компиляция с официальным SDK и приёмка в AutoCAD. Успешный pure test не является подтверждением этих интеграций.

## Отдельные проверки адаптера

`test_zone_geometry_adapter.py` компилирует **неизменённые production** `ZoneGeometryGuard.cs`, `LayoutGeometryGuard.cs` и `GeometryFingerprint.cs` с минимальной моделью CAD API из `test_zone_geometry_cad_doubles.cs`. Python wrapper получает отчёты, окна, группы и `zones_full` из настоящего `facades_engine.op_zones`; driver использует их при `Capture` и `Verify`. Так положительные контроли проверяют совместимость реальной схемы движка, сериализации Xrecord и общего алгоритма.

```sh
python tools/fixes_3009/test_zone_geometry_adapter.py --out /tmp/zone-geometry-adapter
```

Windows / CI:

```powershell
dotnet build tools/fixes_3009/test_zone_geometry_adapter.csproj -c Release -o artifacts/zone-adapter
python tools/fixes_3009/test_zone_geometry_adapter.py --exe artifacts/zone-adapter/ZoneGeometryAdapterCheck.exe --out artifacts/zone-adapter-report
```

Проверяются свежая зона с окном и объединённая зона из двух частей с двумя окнами через Hatch и марку; перенос окна до и после явного изменения массива границы Hatch при прежней площади; пропуск части sidecar, изменение геометрии окна в sidecar, повреждение метаданных/ссылок, удалённый контур, изменённый отчёт и неподдерживаемый сегмент/плоскость. Контуры из отдельных LineSegment2d, полукруглая верхняя дуга окна с независимыми известными endpoints/углами, перестановка loops вместе с их associated ids и смена начальной вершины имеют положительные контроли. Изменения направления дуги, HatchStyle и LoopType должны быть обнаружены.

Для `LayoutGeometryGuard` проверяются `Capture → Store → Verify` исходного контура вместе с отверстием и зоны через Hatch/марку. Перенос исходного отверстия должен дать отказ. Повторный `Capture` на неизменной геометрии с теми же осями должен создать новую ревизию раскладки: новый Hatch принимается, прежняя марка отвергается. Отдельно проверяются смена ключа команды ATTILE/ATCLAD, отсутствие и повреждение метаданных канонической штриховки. Удаление ATFZONE у старой марки при сохранённых ATTILE/ATTILE_GEOMETRY также не должно обходить проверку ревизии. Layout payload в этих adapter cases минимален и проверяет связь/ревизию/digest; расчёт самих осей не проверяется.

Тест скопированного носителя создаёт новый объект с другим handle, вручную переносит его Xrecord и оставляет ссылки на исходные объекты. Это проверяет решение guard для конкретного состояния метаданных. Модель **не выполняет AutoCAD COPY**, не моделирует автоматический remapping, ассоциативное обновление, транзакционную изоляцию, оценку площади Hatch, reactors или Undo. Площадь в модели задана из отчёта движка; источник изменения доказывается перемещёнными координатами. Сегменты модели предоставляют явно заданные endpoints; правильность предоставления этих свойств настоящим Autodesk SDK остаётся отдельной интеграционной проверкой.

Wrapper сохраняет `fixtures.json` реального движка, `cases.json`, `manifest.json` с SHA256 C# и Python исходников/fixtures и логи. При `--exe` дополнительно записывается SHA256 готового executable; этот режим предполагает, что CI собрал его из текущих исходников.
