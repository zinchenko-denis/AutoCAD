# Проверка динамического блока в Autodesk APS

Текущий статус подключения и выполненных запусков — только
[CURRENT_MILESTONES](../../docs/CURRENT_MILESTONES.md).

Здесь находится узкий исполняемый тест для настоящего AutoCAD Core в облаке.
Аккаунт ChatGPT и компьютер Германа для него не нужны. Эта проба исследует
готовое динамическое определение DWG; она не заменяет полную команду ATTILE,
установку модулей, работу диалога или автора библиотеки через BEDIT/COM.

## Проверяемый результат

Первый пилот использует конкретный приватный DWG, его SHA-256, handle вставки,
точные имена свойств и слой контура. Эти значения не угадываются и не берутся
из первого найденного блока. Исходный файл и подробные результаты остаются
приватными. Публичный репозиторий содержит только код стенда.

1. `ATPROBE` создаёт отдельные тестовые вставки, записывает ширину/высоту и
   фиксирует реальные кандидаты, исходные исключения, промежуточные значения
   и окончательную пару. Используется исходный `LayoutSafety.SetNumberChecked`
   из производственного проекта без переписывания его алгоритма.
2. После обеих записей независимо измеряется геометрия: четыре вершины
   замкнутого прямолинейного контура сопоставляются с запрошенным прямоугольником.
   Ожидаемые габариты не выводятся из readback или измеренного результата.
3. Сверяется сохранность исходной вставки. Тестовый DWG сохраняется отдельно.
4. Второе задание запускает `ATREOPENVERIFY` в новом процессе на сохранённом
   DWG. Оно повторно проверяет свойства, геометрию и исходную вставку, не
   присваивая размеры заново и не исправляя открытый чертёж.

| Наблюдение | Итог |
|---|---|
| Сервис Autodesk успешно исполнил задание | Только успех доставки/исполнения; ещё не PASS геометрии |
| Все заявленные случаи и повторное открытие прошли контракты | PASS ограниченной Core-пробы |
| Обычный дробный размер отклонён или округлён | FAIL; не превращать в ожидаемый успешный отказ |
| Не совпали файл, конфиг, DLL, случаи или связность двух запусков | FAIL проверки протокола |
| Нет доступа APS, engine, результатов либо запуск не состоялся | BLOCKED/NOT_RUN; не PASS |
| Проверен setter отдельной пробой | Не означает проверку MakeDynRef, батчей ATTILE или GUI |

На первом этапе сравниваются целые контрольные и проблемные дробные размеры,
режимы sample/definition и разные порядки записи. Массовые серии запускаются
после первого доказанного облачного выполнения и проверки его протокола.
Массовость не компенсирует неправильный ожидаемый результат или неверный DWG.

## Сборка без установленного AutoCAD

Windows с .NET SDK:

```powershell
python tools/aps_autocad/build_probe.py --out C:\AF-QA\aps-build
```

Linux с Mono/Roslyn и распакованными официальными NuGet reference assemblies:

```sh
python3 tools/aps_autocad/build_probe.py --references /path/to/nuget-refs --out /path/to/new-output
```

Папка результата должна быть новой или пустой. SDK-проект ссылается только
на Core/Model API и net48. `FacadeCoreProbe.zip` содержит нашу DLL, описание
пакета и manifest исходников; Autodesk DLL в архив не включаются. Успешная
сборка записывает `BUILD_PASS` и `native_execution=NOT_RUN`.

Manifest содержит Git SHA, хэши фактических исходников и DLL, отметку локальных
изменений. Нельзя выдавать сборку изменённой рабочей копии за точный чистый SHA.
CI компилирует пакет и проверяет протокол, но без доступа APS не запускает
облачный AutoCAD. Диагностический AppBundle не является установочным выпуском
трёх фасадных модулей.

## Подключение Autodesk

Нужны Autodesk APS Developer Hub, приложение с доступом к Automation и
Object Storage, разрешённое использование сервиса и его вычислений.
Авторизация Automation требует OAuth `code:all`; для приватной передачи
DWG через OSS требуются соответствующие data/bucket scopes.

Client ID/Client Secret задаются через защищённые настройки среды выполнения
или secrets закрытого GitHub-репозитория. Не вставлять их в чат, файлы проекта,
URL, аргументы команд или журналы. Переменные клиента — `APS_CLIENT_ID` и
`APS_CLIENT_SECRET`. Вход владельца на сайт и API-доступ приложения — разные
действия: один успешный вход в браузере ещё не подключает этот CLI.

Первая проверка API должна получить доступные engines и явно подтвердить
`Autodesk.AutoCAD+24_3`. Нельзя молча переключаться на latest: другие engine
имеют другую версию AutoCAD/.NET. Облачный engine 2024 также не доказывает
совпадение всех обновлений настольного AutoCAD Германа.

Загрузка пакета/создание Activity и запуск WorkItem выполняются только явными
командами клиента. Автоматическая покупка тарифа и бесконтрольные повторные
WorkItem не допускаются. При неоднозначном ответе на POST сначала проверить
состояние задания, не отправлять дубликат для получения зелёного результата.

## Запуск подготовленного клиента

До подключения можно проверить сам стенд локально:

```sh
python3 -m unittest discover -s tools/aps_autocad -p 'test_*.py'
python3 tools/aps_autocad/test_probe_contract.py --out /private/new-helper-check
python3 tools/aps_autocad/aps_client.py preflight
```

Последняя команда без `--execute` не обращается в сеть, не проверяет секреты
и входные файлы; её результат — только план `NOT_RUN`. C# helper-тест исполняет
извлечённые из `Probe.cs` методы JSON/геометрии/сравнения, без AutoCAD.

После защищённой настройки существующего APS-приложения, подтверждения доступа
и разрешения вычислений выполняются команды ниже. Пути и имя закрытого OSS
bucket подставляются для конкретного стенда; в примере нет исходников проекта.

```sh
python3 tools/aps_autocad/aps_client.py --region us-east preflight --execute
python3 tools/aps_autocad/aps_client.py --region us-east publish --bundle /private/aps-build/FacadeCoreProbe.zip --receipt /private/deployment.json --execute
python3 tools/aps_autocad/aps_client.py --region us-east run --deployment /private/deployment.json --input /private/input.dwg --config /private/config.json --bucket project-private-qa --create-bucket --output-dir /private/new-run --reopen --execute
```

`publish` создаёт версии AppBundle и двух Activity с новым отдельным alias;
`run --reopen` отправляет максимум два WorkItem. По умолчанию лимит обработки
каждого — 120 секунд, ожидания — 900 секунд. Истечение ожидания не означает
отмену удалённого задания: сохраняется его ID и неопределённость исполнения.
Повторная отправка не автоматическая. Папка результата должна быть новой.
Параметры команд: `aps_client.py <команда> --help`.

Закрытый config имеет `schema_version=1`, новый UUID `run_id`, `fixture_id`,
`input_sha256`, `source_handle`, `width_property`, `height_property`,
`outline_layer`, `tolerance` и массив `cases`. Каждый case явно задаёт `id`,
`mode` (`sample`/`definition`), `order` (`production`/`width_height`/`height_width`),
`width`, `height`, `x`, `y`. Допуск не больше 0,0001 мм; до 1000 случаев на
один запуск. Это технические тестовые параметры, не инженерные характеристики.

Первый набор: целый контроль и дробный случай × два режима × три порядка
записи = 12 случаев. Исходный SHA и handle берутся из уже сохранённых закрытых
данных. Старый образец нельзя выдавать за точный DWG с нового снимка Германа.
Для массовых серий каждый новый запуск получает отдельный `run_id`; сначала
проверяется целый контроль, затем фиксируется воспроизведение дробного отказа.

Основной результат — `summary.json`, результаты двух команд, отдельный
`output.dwg`, квитанции с ID заданий и очищенные от URL/секретов журналы APS.
Все эти файлы остаются закрытыми: удаление URL не делает чертёж публичным.
Публичный CI выдаёт только диагностический пакет и сведения о его сборке.

## Граница следующего расширения

После кассеты: отделить Core-совместимый CAD-слой производственного пути,
добавить независимые проверки готового узла «три из пяти», размеров/марок и
массовых серий. Не выдавать отдельный setter за весь этот уже реализованный
контур. Полная пользовательская приёмка сохраняется отдельно: UI, установка,
COM/редактор блоков, работа ручками и обычные пользовательские Undo/COPY.
