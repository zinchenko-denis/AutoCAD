# Дополнительная проверка проверочного выпуска пилота

`verify_release_extension.py` дополняет неизменённый
`tools/release_0110/verify_bundles.py`: прежний инспектор проверяет пять бандлов,
публикацию, SHA, совпадение `latest`/`build-N`, полный состав ZIP и базовые PE/CLR/PYZ.
Это дополнение проверяет функции пилота, появившиеся после build-104.
Выпуск запускается только после отдельной команды Дениса «Собираем».

Сначала выполнить прежний инспектор и получить его `PASS` JSON. Затем:

```sh
python tools/pilot_release_0110/verify_release_extension.py --downloads /path/to/downloads --build 105 --source-sha FULL_BUILT_COMMIT_SHA --base-receipt /path/to/base_receipt.json --out /path/to/pilot_extension_receipt.json
```

В папке загрузок должны находиться `latest/` и `build-105/` с исходными
скачанными архивами. SHA — полный коммит **фактической сборки**, включая
разрешённый trigger-патч, если он применялся. Инспектор использует `git show`
этого коммита; изменения рабочего дерева не подменяют его исходники.
Зависимости те же: Python 3.12, PyInstaller 6.22.3, dnfile 0.18.0.

Дополнение проверяет:

- совпадение трёх фасадных архивов с успешной базовой квитанцией и между тегами;
- реальные `TypeDef` CLR для проектных параметров, исключений зон, геометрии
  узла, сохранения/отрисовки узла и монтажного отчёта;
- реальные `CustomAttribute` методов: декодирует
  `Autodesk.AutoCAD.Runtime.CommandMethodAttribute(string, CommandFlags)`
  из таблиц CLR, включая имя, тип/метод и флаги. Обязательны `ATFPROJECT`,
  `ATFZONEPARAMS`, `ATFNODE`. Сохраняет полный список команд трёх фасадных DLL
  и проверяет совпадение **имён команд** с `PackageContents.xml` и атрибутами
  исходного SHA. Флаги, типы и методы декодируются и записываются; их
  эквивалентность исходникам не утверждается;
- наличие и непустое содержимое `frame_solution_selection` и
  `frame_solution_catalog` именно в таблице встроенного PYZ `frame_engine.exe`.
  Декомпрессия возвращает исходные байты bytecode и их SHA256. Это не поиск
  текстовых подстрок в EXE.

DLL не загружаются, EXE и Python-модули не запускаются. Штатный reader
декодирует оглавление PYZ через `marshal`; байткод модулей извлекается с
`raw=True`, без размаршаливания объектов кода, импорта или исполнения.
Квитанция явно **не утверждает** побайтовую эквивалентность Python bytecode
исходному `.py`: она сохраняет оба хеша и связывает комплект с ранее проверенными
архивом, build-info и workflow. Проверка структуры/комплектности не заменяет
Windows smoke или приёмку в AutoCAD и не подтверждает монтаж/расчёт/автоподбор.

Поддержан фактически используемый конструктор атрибута с двумя аргументами
и без именованных параметров. Новый формат отклоняется явно, а не угадывается.
При любой ошибке сохраняется `FAIL`, код завершения ненулевой. Архивы,
извлечённые DLL/EXE не следует добавлять в репозиторий.
