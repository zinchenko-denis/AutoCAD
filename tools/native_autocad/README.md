# Нативная проверка в AutoCAD 2024

Этот стенд запускает **полный `acad.exe` 24.3** на копии приватного DWG и вызывает
реальный `MakeDynRef` из проверяемой `ACladPlugin.dll`. Он нужен для ошибок
переоценки динамического блока, которые не видны CAD doubles. Это отдельная
проверка адаптера, **не полный проход команды ATTILE и не приёмка автора узла**.

Статус при добавлении: Windows runner и AutoCAD harness ещё не исполнялись
в установленном AutoCAD. Компиляция, разбор PowerShell и синтетические проверки
этого инструмента не изменяют этот статус. Готового доказательства нативного PASS
в репозитории нет; `full_native_gate` остаётся `NOT_RUN` даже при PASS адаптера.

## Что подготовить один раз

1. Выделить Windows-компьютер/VM с установленным и законно активированным **полным
   AutoCAD 2024**. Для пользовательской приёмки нужна русская локализация и тот же
   update build, что у Германа; точный build записывается в отчёте.
2. Использовать отдельную интерактивную тестовую сессию. Windows service/session 0
   не подходит для полного GUI. Нельзя подменять установку AutoCAD NuGet references,
   RealDWG, ODA, Wine, Python-эмулятором или GitHub runner без AutoCAD.
3. В AutoCAD заранее создать отдельный профиль `AutoCAD-QA-2024` без старых
   фасадных бандлов в автозагрузке. Runner только
   проверяет наличие профиля в ветке R24.3 и выбирает его; рабочий профиль
   проектировщика не меняет. Для сравнения чистого запуска и установки модулей
   нужны отдельные тестовые профили.
4. Подготовить приватный рабочий каталог, например `C:\AF-QA\runs`. Только для
   выделенного тестового профиля администратор стенда настраивает доверие к
   каталогу `payload` внутри запусков согласно действующей политике AutoCAD.
   Важно разрешить именно фактические пути загружаемых копий, а не только каталог
   исходной сборки. Скрипт
   **не меняет `SECURELOAD`, `TRUSTEDPATHS`, реестр профиля или системную защиту**.
   Заблокированная загрузка приводит к отсутствию отчёта/таймауту, а не к PASS.
5. Собрать производственную AClad DLL и QA DLL из одного проверяемого коммита.
   Передать реальные fixture DWG и явный конфиг случаев. Handle, названия свойств
   и размеры берутся из приватного исходника/сценария Германа, не угадываются.

Ни покупка лицензии, ни регистрация APS, ни платные вычисления автоматически
не выполняются. Тестовый компьютер должен быть подключён к нашему процессу
разработки до отправки очередного комплекта конструктору.

## Запуск диагностического адаптера

Собрать проект `AutoCAD.NativeAdapterCheck.csproj` в этой папке и производственный
`AClad/src/ACladPlugin/ACladPlugin.csproj` в конфигурации Release. Имена и формат
проверочных случаев описаны в `fixture-config.template.json`. Этот шаблон намеренно
не запускается: нужно заполнить его по конкретному приватному DWG. Пример вызова PowerShell:

```powershell
& .\tools\native_autocad\run.ps1 `
  -AcadExe 'C:\Program Files\Autodesk\AutoCAD 2024\acad.exe' `
  -InputDwg 'C:\AF-QA\fixtures\private-cassette.dwg' `
  -ACladDll 'C:\AF-QA\build\ACladPlugin.dll' `
  -HarnessDll 'C:\AF-QA\build\AutoCAD.NativeAdapterCheck.dll' `
  -CasesConfig 'C:\AF-QA\fixtures\cassette-cases.json' `
  -OutputDirectory 'C:\AF-QA\runs\cassette-20261008-01' `
  -ProfileName 'AutoCAD-QA-2024' -Language 'ru-RU' -TimeoutSeconds 300
```

`OutputDirectory` должен быть новым абсолютным ASCII-путём. Ограничение относится
к bootstrap SCR; исходный приватный DWG может лежать по Unicode-пути. Скрипт
создаёт копии DWG и обеих DLL, записывает SHA256, уникальный `run_id`, конфиг и SCR,
запускает свой процесс AutoCAD с `/b`. Переменные `AT_NATIVE_CONFIG` и
`AT_NATIVE_RESULT` задаются только дочернему процессу. Производственная DLL и
QA DLL загружаются из копий, никакие AutoCAD reference assemblies не копируются.

В приватном конфиге обязательны `input_sha256` исходного DWG, точный handle
динамической вставки, имена свойств ширины/высоты и `outline_layer`. Последний
указывает слой **единственной видимой замкнутой четырёхвершинной Polyline** контура
кассеты/плитки после native Explode. Все четыре вершины независимо сверяются
с заданным прямоугольником. Если в этом исходнике такого контура нет, не угадывать
слой и не снимать проверку: нужна отдельная реализация независимого геометрического
контракта. `cases` — непустой список `{id, mode, width, height, x, y}` с уникальными `id`.
Размеры и положения указываются явно. Разные DWG/блоки нельзя объединять в один
конфиг только по внешнему сходству; для каждого нужна своя привязка SHA/handle.

Для каждого случая обязателен `mode`: `sample` — вставка по пригодному образцу
с переносом его свойств и внешнего вида; `definition` — вставка по определению
динамического блока без образца (`Te=null`). Это разные производственные ветви:
предупреждение «образец непригоден» ещё не доказывает отказ вставки по отдельно
выбранному определению. Каждая требуемая ветвь должна присутствовать в конфиге
отдельным случаем. В `definition` сравнение переноса цвета/слоя **из образца**
получает `NOT_APPLICABLE_DEFINITION_MODE`, поскольку источника такого переноса нет; размеры,
четыре вершины контура, сохранность исходника и rollback по-прежнему обязательны.

Проба выполняет случаи в откатываемых транзакциях. После неё закрывается только
собственный процесс с тестовым DWG. При таймауте останавливается только сохранённый
процесс этого запуска; поиск и завершение чужих процессов по имени запрещены.
Исходный DWG не изменяется; после выполнения SHA256 исходника и рабочей копии
сверяются повторно. Существующие результаты никогда не перезаписываются.

Результаты остаются в **приватной** папке запуска:

- `native-result.json` — host, hashes, исходный блок, результаты native случаев,
  геометрия и ограничения покрытия;
- `runner-result.json` — запуск процесса, время, статус, причина отказа и hash
  нативного отчёта;
- `native-config.json`, `bootstrap.scr`, `input-copy.dwg`, `payload/` — точные
  входы воспроизводимого запуска.

Exit 0 означает только **ADAPTER PASS**. Exit 1 — ошибка выполнения/проверки;
exit 2 — отсутствующие предварительные условия. Нет AutoCAD, нет результата,
не совпали версия/hashes/run_id/PID, конфиг, количество/порядок/значения/повторы
случаев, оборвался процесс, возник таймаут или
отказал обычный положительный случай — успешного результата нет. Нельзя добавлять
`continue-on-error` или превращать этот результат в green skipped native test.
Приватные DWG, конфиги и подробные отчёты не загружать артефактами публичного CI.

## Что обязательно проверить до полной приёмки

Таблица ниже — **не выполненные проверки**, а обязательное покрытие отдельного
полного GUI стенда. Наличие строк в документе не является доказательством PASS.
Драйвер GUI должен выполнять настоящие команды, выбор и диалоги, а независимая
QA DLL — снимать геометрию/свойства до и после. Вызов внутренних методов через
reflection проверяет только адаптер и не заменяет обычный запуск команды.

| Сценарий | Проверяемый результат |
|---|---|
| Чистый AutoCAD → APPLOAD → ATFNATIVEBUILD → реальный диалог сохранения | Обычный сценарий завершается без отказа; подмена `getfiled` тестовой функцией не допускается |
| Видимость, linear, move/stretch, A/B | Созданы настоящие параметры/действия; изменилась вычисленная геометрия, размеры и марки |
| Пять вставок, выбрать три | Только выбранные три меняются; два прочих сохраняют полный снимок |
| A→B→A→B, повтор одинаковых значений | Нет накопления смещений; базы, размеры и марки согласованы |
| Properties и ручки, масштаб/поворот | Ручное редактирование и трансформации дают ожидаемую нативную геометрию |
| ATFNODEIMPORT, ATFNODEDEMO, ATFNODEEDIT/TEST | Действуют обычные команды; конфликт имён не заменяет чужое определение |
| UI COPY, UNDO/REDO, отмена выбора/диалога | Копия независима, отмена корректна, исходные объекты и чужие операции сохранены |
| Save → Close → Open в новом процессе | Сохранились native свойства, действия, марки и геометрия; повторное редактирование работает |
| UNDOCTL 53/61, DBMOD 0/8/16/24 | Исследован обычный запуск и владелец группы; безопасный отказ не засчитан за успешное построение |
| Ошибка до/после BEDIT и Begin/End | Владение определяется readback; диагностика не затёрта; чужой редактор/Undo не закрыты |
| Заблокированный слой, существующий DWG, неполная команда | Нет перезаписи и частично принятой библиотеки; восстановление либо явный FAIL |
| ATTILE на проблемном Cassette DWG | Обычная раскладка проходит; подтверждены размеры каждого вставленного элемента и отсутствие дрейфа исходного блока |
| ATTILE: 245×35.85 и 821.87×600 в отдельных исходниках | Каждый отказ воспроизводится на своём SHA/handle; первый случай не заменяет проверку второго |
| ATTILE: batch, Esc, перестроение | Отмена не оставляет частичную раскладку; старая раскладка сохраняется до успешного принятия новой |
| ATTILE: пограничные размеры, режимы видимости, scale/rotation | Проверяется нативная переоценка и реальная геометрия, а не только записанные числа |
| Загрузка трёх модулей и лента/библиотеки | Проверены реальные версии, зависимости, команды, предупреждение `ACAD:Фасады` |
| ATFZONE: штриховка, острова, дробные координаты, старые зоны и COPY | Нет утраты проёмов, наложения облицовки на острова и удаления оригинала по скопированной метке; корректна миграция |
| ATFRAME: пять типовых фасадов × два режима построения | Обязательные обычные фасады успешно строятся; отказ поддерживаемого сценария не считается защитой, закрывшей проверку |
| ATFRAME: границы 599/600/601, хлысты 3000+10+290, окна 100/50 | Воспроизведены исторические границы шага/обрезков; резка и концы направляющих у окон соответствуют заданным правилам |
| Параметры: наследование, очистка, отмена, устаревание | Нет возврата очищенного значения и ложной актуальности после изменений; отмена не меняет проект |
| Масса 25→8, композит и крепёж керамогранита | Смена схемы меняет массу/спецификацию; композит не получает чужой крепёж |
| DWG-ведомости и XLSX | Геометрия, количества и экспорт согласованы; служебные марки и метки не попадают в объёмы |
| Инспектор штампа: СПДС, вложения, UTF-8 | Сведения прочитаны из нужных объектов; исходный DWG не изменён и не сохранён инспектором |
| Производительность: 1/5/25 зон | Время чтения, расчёта, отрисовки и записи измерено отдельно на native host; синтетическое время не подставлено |

Начальные snapshots должны содержать handles, матрицы вставки, динамические
свойства, размеры, марки и вычисленную геометрию. Финальный отчёт должен связывать
каждый обязательный случай с точными входами, кодом, host build, журналом и
before/after/reopened DWG. Отсутствующая проверка получает `NOT_RUN`/`BLOCKED`;
обычный поддерживаемый сценарий обязан пройти, сколько бы негативных случаев
ни закончилось ожидаемым отказом.

Для `UNDOCTL=61` отдельно нужен запуск из обычной командной строки: выполнение
через SCRIPT/обёртку меняет командный контекст и само по себе не доказывает
поведение пользовательского сценария. Нельзя завершать неизвестную группу
`UNDO End` ради зелёного отчёта.

## Почему APS/Core Console не заменяют этот полный стенд

APS Automation — реальный AutoCAD Core в облаке. Официальный пример Autodesk
изменяет динамические свойства **готового DWG** через .NET. Поэтому APS подходит
для будущего массового контура геометрии/параметров после подготовки библиотеки.
Но существующий `native_author.lsp` вызывает `vlax-get-acad-object`, `vla-*`,
`GetDynamicBlockProperties`, BEDIT и диалог. Autodesk указывает, что COM/ActiveX
runtime отсутствует в headless Automation; прямой перенос LISP не работает.
Даже адаптированная .NET проба не испытывает UI, grips, выбор и пользовательский
UNDO. RealDWG — библиотека чтения/записи DWG, также не desktop AutoCAD.

APS потребует отдельного приложения, OAuth `code:all`, доступных engine и
подходящего тарифа. Исторически AutoCAD 2024 соответствует
`Autodesk.AutoCAD+24_3`; доступность проверяется GET engines перед запуском.
Никакой WorkItem этим инструментом не отправляется.
