# Чтение структуры штампа

`inspect.lsp` — отдельный диагностический инструмент. Он читает выбранные объекты открытого чертежа; сущности, системные переменные и DWG не изменяет. Записывается только необязательный новый TXT-отчёт. Редактирование штампов не реализовано.

1. В полной версии AutoCAD для Windows загрузить `inspect.lsp` через APPLOAD.
2. На целевом штампе запустить `ATFSTAMPINSPECT` и выбрать **новое** имя `.txt`. При `LISPSYS=1/2` TXT явно создаётся в UTF-8 с BOM (`utf8-bom`). При `LISPSYS=0` диалог файла пропускается и появляется сообщение `F2 only; UTF-8 TXT disabled`: текстовый файл не создаётся. Настройки AutoCAD инструмент не меняет. Существующий путь отклоняется даже после подтверждения перезаписи в диалоге. Отмена или ошибка открытия TXT оставляет вывод только в F2.
3. По русским подсказкам выбрать «Шифр» (`PROJECT_CODE`), «Адрес» (`ADDRESS`), затем «Штамп» — его рамку/объект (`FRAME_OR_STAMP`). Поддерживается выбор вложенных объектов. Enter пропускает текущий выбор; Esc завершает чтение и закрывает частичный отчёт.
4. Если в этом DWG есть титульный лист, отдельно повторить команду на его полях и рамке, выбрав другое имя TXT.
5. Передать для анализа **TXT вместе с полным выводом F2** по всем трём выбранным объектам и их вложенным контейнерам. В режиме F2-only передать вывод F2 и отметить отсутствие TXT. Это частные данные чертежа; не добавлять отчёты в публичный репозиторий.

TXT содержит тип, handle, цепочку владельцев, DXF-коды листа/слоя, фрагменты текста, TAG атрибутов, вложенные контейнеры и исходную матрицу выбора. Из фиксированного списка COM-свойств читаются доступные значения, включая `ObjectName`, `EffectiveName`, обычные и постоянные атрибуты INSERT. Отсутствующее свойство не считается пустым значением. В F2 дополнительно выводится `vlax-dump-object` со значениями свойств и **названиями** методов; перечисленные методы не вызываются. Дополнительные custom/SPDS-свойства могут находиться **только в F2**, поэтому одного TXT недостаточно. Явно вызываются только два метода чтения атрибутов.

SPDS/custom/proxy получают отметку `UNSUPPORTED_CLASS`. Это не означает отсутствия видимого текста: внутренние поля СПДС не декодируются, сходство с TEXT/ATTRIB не доказывает одинаковую структуру. Вложенные координаты остаются исходными; преобразование координат и разрешение внешних ссылок не выполняются. Обход владельцев останавливается при цикле или после 16 уровней. При ошибке COM остаются сведения DXF.

## Что установлено при автономной проверке

Оба изученных DWG — листы 03–10 и 11–20 — получены через GitHub ZIP; соответствие исходным Git blobs проверено. Aspose CAD 26.7 прочитал структуру обоих. В узловом DWG найдены 344 определения блоков, 3324 объекта модели и 10 пространств листов по два объекта.

LibreDWG 0.13.4 выделил 11 записей `SPDSFORMAT` / `mcsDbObjectFormat`. Членство в списке объектов пространства модели и независимое чтение Aspose подтверждают их размещение в модели. Это proxy/custom-объекты, а не обычные INSERT/ATTRIB. Декодированные class ID Aspose и ownerhandle LibreDWG для этих записей противоречат структуре контейнеров и не используются как достоверные данные. LibreDWG сообщил ошибки чтения; его выгрузка не является эталоном. Бизнес-поля СПДС остаются неподдержанными, поэтому обновление по предполагаемым TAG сейчас недопустимо.

В полном PDF из 22 страниц титул визуально присутствует; соответствующего DWG титула среди проверенных материалов нет. Конкретный объект штампа из видео не идентифицирован. Эти материалы не устанавливают его класс и соответствие полей; инспектор предназначен для чтения именно выбранного целевого штампа, без обещания готовых TAG.

## Проверка инструмента

`python tools/stamp_library/test_inspect.py` проверяет структуру Lisp, границу допустимых вызовов, локальные переменные и фактические ветви открытия отчёта через doubles: `LISPSYS`, явный `utf8-bom`, отмену, существующий путь и ошибку открытия. Это **не проверка в AutoCAD**. Загрузка, вложенный выбор, COM, кириллица и фактические байты TXT требуют проверки в целевой среде AutoCAD/СПДС. `LISPSYS=0` не обеспечивает полноценный Unicode; диагностическое сообщение F2-only оставлено ASCII, чтобы ограничение было видно и в старом движке. Изменения системных переменных отсутствуют.
