# Проверка явного исторического решения, 2Б1

Запускать из корня репозитория с Python 3, Shapely и доступным .NET
компилятором/runtime (Windows .NET Framework либо Mono).

```bash
python AFrame/engine/test_frame_solution_selection.py
python tools/solution_catalog_0110/test_settings_contract.py --out <новая-папка>
python tools/solution_catalog_0110/test_solution_ui.py --out <новая-папка-ui>
```

Первый набор проверяет каталог, строгую валидацию, отдельные статусы
номенклатуры/сборки/расчёта, неизменность геометрического пресета и один
подготовленный снимок на операцию. Второй компилирует реальные настройки,
валидатор и producer ведомости, связывает их с Python-движком, проверяет
сохранение, групповой выбор, отказы и свежесть источников перед записью.
Фрагменты CAD-границы извлекаются из текущего FrameCommand и исполняются
на doubles; это не проверка транзакций внутри AutoCAD.

UI-набор выполняет настоящие сценарии WinForms и сохраняет PNG окон.
Windows CI запускает его обязательно и публикует `solution-catalog-ui`.
Linux требует работающего Xvfb; недоступный экран даёт **BLOCKED** и код 2,
а не успешную проверку. Компиляция без открытия окна не заменяет UI-прогон.

Основные наборы включены в `tools/atr_review_3009/run_checks.py`, а UI —
в `.github/workflows/check.yml`. Полная компиляция трёх плагинов выполняется
отдельно через `tools/fixes_3009/compile_facades.py`.

Для четырёх проверок реального эталона в `test_frame_plan.py` задайте
`ATSPEC_TESTDATA` на корень разрешённой приватной копии `atspec-testdata`.
Без неё только этот блок FR-D явно пропускается; оригиналы в публичный
репозиторий не копируются.

Итоговая привязка источников, результатов и ограничений находится в
`docs/solution_catalog_0110/verification_manifest.json`.
