# Источники и границы реестра AFrame — 30.09.2026

Канонический реестр находится в [`frame_rules.py`](../../AFrame/engine/frame_rules.py); [`assembly_catalog.json`](../../AFrame/engine/assembly_catalog.json) — его генерируемый снимок для аудита. Реестр описывает происхождение правил и границы реализации. Он не содержит таблиц допускаемых нагрузок, не рассчитывает геометрию и не удостоверяет соответствие всей системы АТР.

Производитель, серия, редакция альбома, тип несущей схемы, облицовочное изделие и узел крепления — разные измерения. Имя старого пресета `systems.json` не выбирает всю эту комбинацию. Поэтому выходной contract оставляет `manufacturer_id`, `series`, `album_edition` и `approved_node_id` незаполненными: ссылки на изученные альбомы являются основанием сравнения, а не удостоверением выбранного узла.

## Облицовка и узел крепления

- **КГ:** реализована геометрия существующего режима кляммеров. Вектор-1 PDF 108 / лист 11.1 и PDF 109 / лист 11.2 различают видимые/скрытые крепления, кайлы и крепления керамических плит. Общий код `porcelain` не подтверждает все эти узлы.
- **АКП:** поддержанная часть каркаса доступна в режиме `frame`; узел крепления кассеты не реализован. Вектор-5 PDF 135 / лист 11.1 содержит восемь вариантов. Варианты 1/2 связаны с ШП/СП, надпись «любой профиль» в других вариантах не доказывает совместимость всех сочетаний. Кляммеры КГ не заменяют салазки, икли и другие детали АКП. Металлокассеты отдельно: PDF 136 / 11.2 и PDF 138 / 12.1.
- **Клинкер/бетон:** геометрия направляющих и шин происходит из рабочего ТЗ Германа. Марка шины проектная. АТР Вектор-4 отсутствует; совместимость конкретной плитки, сечение шины, соединения и полный расчёт её узла не восстановлены по умолчанию.
- **NordFOX:** отдельная алюминиевая система. PDF/листы 17–20 показывают планки/клипсы и кассетный вариант; 22/24/26/27/30 — неподвижные и подвижные опоры; 81–85 — прямое опирание DT/H на UFOX/UTFOX; 89–92 — оконные узлы. Это не набор стальных пресетов Вектора. Размеры панелей на 45/46 приведены с условиями расчёта, не как универсальный предел.

## Числа и отсутствующие правила

Вектор-1 PDF 53 / 7.1, 55 / 7.3, 62 / 8.1 и 64 / 8.3 показывают зазор 10 мм на конкретных усиленных узлах. Это не подтверждение общего зазора для любого соединения. Размер 200 мм на 8.1/8.3 измерен от верхнего торца нижнего НСП до верхней полки КПК, а не между полками кронштейна.

Проект A: PDF 20 / 3.1 и PDF 59 / расчёт 9/9 обосновывают проектные 1200/800 и оси 608 при конкретных исходных. Исторический ручной пресет не превращает их в пределы следующего объекта. `Standart` сохраняет происхождение геометрических параметров проекта B/КАФТ и последующее рабочее ТЗ. Штатный UI для расчётной вертикальной схемы **явно переключает** запрос на `Вектор-1` в `FrameSettings.SysOverride`; нельзя описывать этот путь как скрытый расчёт Standart по Вектору. Ни legacy-имя, ни такой переход не удостоверяют полный комплект производителя.

Вектор-1 PDF 103 / 10.5 содержит условное дополнительное крепление над проёмом по пожарному заключению. Проект A PDF 48–50 / листы 30–32 различает изделия и варианты, включая вариант без полосы дополнительных кляммеров. Эти условия нельзя заменить глобальным правилом «350 мм для всех». При КГ с проёмами `declared_scope` возвращает заметку об отсутствующем условном усилении по выбранному проектному узлу. Дополнительная средняя направляющая не заменяет полосу с дополнительными кляммерами.

Другие явно незамкнутые области: неподвижные/подвижные опоры, температурные перемещения, деформационные швы здания, полные оконные/угловые/цокольные/парапетные узлы, анкеровка в фактическом основании, полный состав крепежа/вставок/термопрокладок и подтверждённое сечение НСП-2. Существующий геометрический обход проёма или расчёт отдельного профиля не закрывает эти области.

## Узкий программный интерфейс

```python
resolved = resolve_layout_contract(req, system, sub)
# отказ: {"ok": False, "error_code": "E_...", "error": "..."}
# успех: {"ok": True, "contract": {...}}
scope = declared_scope(resolved["contract"], has_openings=True)
# {"metadata": {...}, "notes": [...]}
```

`req` — исходный запрос; `system` — разрешённый старый пресет, допустим `{}` перед `load_system`; `sub` — нормализованный код схемы. Четыре именованных пресета сверяются с `systems.json`. Неизвестное имя, в том числе `{name: "NordFOX"}`, даёт `E_SYSTEM_UNSUPPORTED`, а непустой словарь без имени сохраняется как пользовательские параметры без производителя. Отсутствующий `system`, `None`, пустая строка и `{}` сохраняют существующий выбор по умолчанию `Standart`. Неизвестная схема даёт `E_LAYOUT_SCHEME_UNSUPPORTED`; неизвестная облицовка — `E_CLADDING_UNSUPPORTED`. Проверки геометрии, чисел, частей результата и совместимости расчётной методики остаются у планировщика.

Сам `contract` описывает **запрошенную** область, не факт успешно выполненного расчёта. `calculation_requested` не означает `calculation_passed`. Подключение выполнено в обёртке `frame_plan`: resolver вызывается до геометрического ветвления, метаданные и замечания добавляются ко всем успешным режимам, включая повтор только кляммеров. `frame_engine` сохраняет сведения по каждой зоне; C# записывает весь `design_scope` в ATFRAME. Проверены неизвестные значения, ранний возврат кляммеров и различие наличия проёма у двух зон. JSON не загружается при расчёте. Прямой импорт stdlib-модуля включается в обычный анализ импортов PyInstaller и не требует нового data-файла.

```sh
python AFrame/engine/frame_rules.py --export-catalog AFrame/engine/assembly_catalog.json
python AFrame/engine/test_frame_rules.py
```

Тесты проверяют идентичности и отказы API, положительные контроли трёх схем, непереносимость типа 5, условность заметок, отсутствие изменения входов, работоспособность без чтения внешнего JSON, существование публичных ссылок и точное равенство снимка каноническому реестру. Они не подтверждают исполнение AutoCAD или инженерную достаточность проектного решения.
