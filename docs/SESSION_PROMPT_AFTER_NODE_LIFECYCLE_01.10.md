## Критически важная коррекция управления проектом

Денис указал, что не понимает движения по плану и видит подмену ключевых
задач мелкими проверками. Независимый аудит подтвердил: после 2Б5
не завершены основные инженерные вехи 2В/3А/3Б/4. 2В1/2В2 — диагностика,
2В3 — аудит границы без нового продукта; затем исправлены Esc осей и ПСК
таблицы и укреплена связность существующего программного процесса.

Не называй очередной тест новой ключевой вехой и не оценивай готовность
числом PASS. Используй исходные номера из CURRENT_MILESTONES:
2В=П2, 3А=П3, 3Б/4=П4, согласованный комплект5=П5.
В каждом отчёте: пункт плана → результат для пользователя → что закрыто/
осталось → следующее действие с конечным критерием. Затем SHA/CI/замеры.

Текущий участок — только пункт5: совместное выполнение ранее реализованных
Node и Table commands на тех же канонических источниках. При отсутствии
дефекта продукт не менять ради коммита. Ограничение ownership исправляется
в тестовом адаптере и не выдаётся за продуктовую ошибку.

## Пилот и известные факты

Один пилот: Вектор-1 2015, тип1, керамогранит, узел4.2.1, КР2–ПП–УК–ГП.
Базы0/2/2+L и формула УК с неизвестным h прежние. min30 иных узлов
и165−80=85 не определяют полный допустимый ход пилота.
Физический УК и два подтверждённых интерфейса не назначены;
`physical_assignment=not_asserted`, `MountingStatus=not_confirmed`,
`AutomaticBracketSelectionAllowed=false`, `E_SOLUTION_CALC_UNCONFIRMED`.
Монтаж2В и подтверждённый3А остаются BLOCKED.

Для ограниченного расчёта достаточно одного доказанного монтажного
варианта и применимой упрощённой модели. Не требовать универсальной
модели всех систем или всего диапазона заранее. Но сохранённые источники
пока не задают однозначно и этот вариант. Расчёт одного варианта сам по себе
не разрешает автоматический подбор по диапазону. Подробные основания —
`node_lifecycle_0110/plan_audit.md/.json` и матрицаМ1–М7 в плане.

Новых альбомов, систем и СФТК не начинать. Не запрашивать снова сведения,
которые уже исследованы, и не перечитывать весь архив без новой гипотезы.
Число тестов, UK ID или галочка пользователя не доказывают физическую связь.

## Что именно проверяет общий программный проход

Две зоны1210×1820, плитка600×600/шов10, ручной каркас800/800.
Реальные settings/guards/engines/producers/stores дают12 плит,2ГП/3,64м,
6 условных кронштейнов. Схема имеет слои100+50, поверхность150,
ближайшую поверхностьГП170 и локальный просвет20.
Проект230→240 устаревает оба каркаса; исключение260 справа — отдельную зону.
Сопоставлять зоны по геометрии/источнику, не индексу ответа.

Node и Table commands исполняются на общей DB в одном процессе.
N1fresh → изменение проекта → N1stale → неудачнаяN2 сохраняет N1 целиком
→ успешнаяN2 со своим owner/definition свежая при выдаче, N1stale.
Поздний унаследованный Table-контроль действительно меняет проект до
revision3, поэтому финально обе схемы stale. Источник обратно не сбрасывать.
Ручной импорт и ведомости не считают схемы физическими деталями.

Счётчики команды сняты до инспекции. Node не делает ModelSpace scan
или engine call. Дополнительные ссылки узлов в обходе ведомости считать
честно; линии/подписи определения не должны попадать в ModelSpace.
No-op Commit/Dispose не доказывают native rollback.
Полные команды на doubles не равны внешним диспетчерам/формам/
отрисовке и настоящему AutoCAD.

## Конечный следующий шаг: не раздувать стенды

После текущего сценария и обязательных проверок **не назначать
автоматически новый adapter этап**. Точный отказ заканчивает исследование
пробела, но не считается PASS соответствующей функции.

Оставшиеся native операции перечислены в host_acceptance.md:
настоящие команды/отрисовка, save/open, COPY/SaveAs/remapping, Undo/rollback,
ПСК/таблицы и скорость реального DWG. Они требуют AutoCAD и разрешённого
проверочного комплекта. Их нельзя закрыть всё более сложной имитацией host.

Ключевой инженерный путь остаётся2В → 3А → 3Б/4 → полный комплект.
Продолжать его только по конкретному новому основанию, закрывающему
указанный пробел. На неизменных данных не обещать завершение и не назначать
следующую сессию повторной диагностики. Ограниченный host-проход может
проверить имеющийся режим, но не заменяет инженерную приёмку пилота.
