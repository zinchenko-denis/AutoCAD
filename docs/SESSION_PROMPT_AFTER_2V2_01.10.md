## Что добавлено в 2В2

Тот же единственный пилот: Вектор-1 2015, тип 1, керамогранит,
узел 4.2.1 / PDF 20, КР2–ПП–УК–ГП. После неоднозначности общей опоры
2В1 воспроизведён отдельный пробел: физический кронштейн присутствует
в проверенном составе, но не имеет ни одной ссылки-кандидата ГП.
Теперь «ATFTABLE → Подсистема → Соединения» сообщает конкретный ID и зону.
Деталь остаётся в количествах; строка фиктивного ГП не создаётся.

Обязательная граница воспроизведения: принятый движком резервный вход
с `bracket_step=None`, `bracket_step_corner=None`, уровнем 1500 и зазором
10 создаёт 2 ГП и 1 кронштейн между ними. Полная цепь проверяется реальными
engine → FrameQuantities → validator → table → XLSX. Текущий диалог
ATFRAME задаёт числовые шаги ≥100 и такой вход не создаёт. Не описывать
тест как наблюдавшуюся ошибку обычного пользовательского построения.
Синтетические размеры не являются монтажной рекомендацией.

Eligibility: `role=bracket`, `origin=generated:ATFRAME:brackets`, тот же
`source_run_id` доступного `inventory_only`, одна каноническая выбранная
зона, покрытая паспортом. Сохранённый паспорт ищется по своему исходному
прогону, не по текущему `report.run_id`. Дубликаты ID не умножают сообщения.
Отдельный контроль допустимых разных passport_id одного исходного прогона
выявил зависимость от порядка отчётов; сбор ссылок до дедупликации строк
устранил её. Не возвращать отрицательный вывод только по показанным строкам.
Недоступность, legacy, ручная регистрация и неоднозначная зона не дают
ложного «нет связи». Ручные числовые шаги ATFRAME сами по себе не исключение.

Чистое представление сохраняет индекс общих кандидатов; для отрицательного
вывода собирает все ссылки до дедупликации строк и использует индекс
физических кронштейнов по источнику/зоне; новых CAD-чтений, обхода ModelSpace, PDF,
сети, Python или записи паспорта при просмотре нет. Схемы, количества,
геометрия, COPY и актуальность прежние. Не возвращать квадратичный поиск.
Длинный ID вместе с зоной прежде создавал новую XLSX-ячейку 33201 символ;
теперь части полного ID/зоны связаны номером записи без усечения. Это
техническая защита экспорта, не инженерный предел.

## Сохраняемые инженерные границы

Отсутствие геометрического кандидата не доказывает отсутствия реального
крепления, лишней детали или ошибки монтажа. Наличие кандидата тоже не
подтверждает связь. Каталожный выбор хранит `physical_assignment=not_asserted`;
пара bracket–rail не подтверждает интерфейсы ГП–УК и УК–КР2.

Номинальная цепь 2Б5: основание 0, ПП/опора КР2 2, торец 2+L. Для УК
`x пятки=2+L КР2+L УК−h`, h неизвестно. Металл повторно не прибавлять.
min30 других узлов и расчётные 165−80=85 не задают полный ход пилота.
Расчётная нагрузка на L1 не назначает всем опорам вес/скольжение.
Нужны доказанные отверстия/метизы, перемещения/повороты, грузовые участки,
температурный ход и передача N/Q/M через стык. Заклёпка не означает
абсолютную заделку, нулевой зазор — непрерывную балку.

`MountingStatus=not_confirmed`, `AutomaticBracketSelectionAllowed=false`,
`E_SOLUTION_CALC_UNCONFIRMED` сохраняются. Полный 2В и подтверждённый 3А
закрыты. Это граница переноса источников, не заключение об ошибочности проекта.

## Следующая работа и публикация

Работай самостоятельно по тем же источникам и тому же пилоту. Сначала
воспроизведи новый конкретный пробел сопоставления физических деталей,
монтажных интерфейсов и доказательств. Затем небольшой обоснованный
инкремент либо точный отказ. Новых альбомов не требовать заранее, неизвестные
характеристики не выдумывать. Повтор прежнего отчёта не является этапом.

Проверки CLAUDE, полная компиляция трёх фасадных модулей, синтетика/роли
с явной сверкой неизменных зависимостей, независимая ревизия; после
публикации — зелёный Windows check и просмотр затронутых снимков.
Сохраняй скорость, воспроизведение, причины, ограничения и SHA в GitHub,
обновляй руководство/DOCX/QA, верхние handoff/NEXT, маршрут и хронологию.
Старый PASS не переносить на изменённые зависимости. Native HWND должен
помещаться в WorkingArea; один bitmap этого не доказывает.

Подключённый GitHub API — первый способ чтения/публикации; отсутствие
локального gh auth не требует PAT. Ранее разрешённый браузерный переход
для недостающей операции не нужно согласовывать снова. Не публиковать
приватные оригиналы/рендеры, пароли и токены. Удалённый SHA проверять
непосредственно перед обновлением ветки, без force.

ATableSpec, ABlockGen и main не менять. Каталог/системы/СФТК до живой
приёмки пилота не расширять. Последний установочный выпуск build-104;
новый — только по новой команде Дениса «Собираем». Живой AutoCAD не проверен.
