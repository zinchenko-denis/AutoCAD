## 08.10, вечер: полный регрессионный прогон; нативная приёмка открыта

По новому требованию Дениса передача очередного проверочного задания главному
конструктору приостановлена до собственного нативного прогона. Полностью
перечитаны SESSION_PROMPT, CLAUDE, TESTING, текущий план и связанные ТЗ/разборы
регрессий. В начале локальный и удалённый HEAD совпадали: `12af31a`, рабочее
дерево чистое. Чужие изменения не сбрасывались. Код сохранён в
[`de67913`](https://github.com/zinchenko-denis/AutoCAD/commit/de6791397ddb125597de4aeae3f425b26c21ee90).

**Новый снимок — ATTILE, отдельный отказ от автора узла.** Четыре образца,
один тип «цвет 4», номинал около 245×65. Для обрезка запрошено 245×35,85,
обратно прочитаны высота 36 и ширина 244,99999999999884. Существенная ошибка —
высота на 0,15 мм; погрешность ширины порядка 1,16e−12 мм её не объясняет.
Перед этим есть предупреждение о непригодности повёрнутого/отражённого/
масштабированного образца. Вставка по отдельно выбранному определению остаётся
отдельной ветвью (`Te=null`); по снимку нельзя назначить ей причину отказа образца.
Тип CLR, ограничения параметра и точная версия DLL неизвестны. Нативный шаг
1 мм и совпадение с известными приватными DWG **не установлены**.

**Подтверждённые исправления:**

- ATTILE округлял дробное значение при преобразовании в прежний целочисленный
  тип свойства до вызова AutoCAD. Теперь потеря точности выявляется до записи;
  отказ выводит реальное значение, CLR/API тип, единицы и допустимые значения.
  Это диагностирует неподдержанный размер, но само по себе не обеспечивает
  положительную раскладку 245×35,85 на блоке Германа.
- Ключ кеша прототипов с двумя десятичными знаками смешивал разные размеры,
  например 245,001 и 245,004. Теперь ключ сохраняет точное double-значение;
  повторение одинакового размера по-прежнему клонирует прототип. На 12 расчётных

нормализации, повторного чтения, отмены и владения группой, затем настоящий

**Новая задача оформления:** Герман задаёт шифр и адрес на титуле, команда

В видео крупно показан целевой штамп ведомости: адрес многострочный,
название объекта, название и номер листа — отдельные поля. Титульный
источник, имя блока, TAG и редактор атрибутов не показаны. Подсказка MText
относится к подписи строки ведомости и не доказывает тип полей штампа.
Частные кадры, адрес и исходный чертёж в публичный Git не переносятся.

Готовой команды штампов в просмотренных исходниках нет. Можно использовать
подход снимок → окно → свежая проверка → транзакция из FrameProjectCommand
и приёмы сопоставления атрибутов из ManualQuantityGeometry/ManualQuantityForm.
`project_id` в FrameProjectParameters — GUID, не шифр; строгую инженерную
схему `/1` не расширять реквизитами так, чтобы менять актуальность расчётов.
Проверен инвентарь приватного `atspec-testdata/main`: кандидаты
`projects/lenprospekt_245_22_1_VF/245_22-1-VF_L03-10_raskladki_2026_06_22.dwg`
и `245_22-1-VF_L11-20_uzly_2026_06_05.dwg` в той же папке. README отмечает,
что листов 1–2 «Общие данные» нет. Структура полей этих DWG и совпадение
с шаблоном видео пока не установлены; наличие файла не считать готовым
образцом титула. Повторно запрашивать весь архив не требуется.

План первого результата — один реальный шаблон штампа и два общих поля:

1. В имеющихся приватных исходниках найти подходящий DWG и прочитать типы,
   владельцев и атрибуты титула/штампа. Не угадывать TAG, координаты или
   последнее похожее число; сначала проверить, что шаблон соответствует
   работе отдела. TEXT/MTEXT и атрибуты источника различать явно.
2. Один раз указать две исходные надписи и сопоставить два поля штампа.
   Сохранить привязку и редакцию шаблона внутри этого DWG, отдельно от
   инженерных параметров ATFPROJECT. Источник истины — текущее содержимое
   выбранного титула; удалённую/неоднозначную привязку не заменять догадкой.
3. Команда «Обновить штампы» собирает все листы текущего DWG, показывает
   шифр, адрес и таблицу было/станет. Листы без штампа, несколько кандидатов,
   иной шаблон, поля со ссылками/FIELD и блокировка слоя показываются
   отдельно. Неполное обновление не называть заполнением всех листов.
4. Перед записью перечитать источники и цели после диалога; изменившийся
   снимок показать заново. Записать согласованную группу одной транзакцией
   с одним Undo; сохранить шрифт, высоту, выравнивание и переносы адреса.
   Менять атрибуты нужных вставок, а не общее определение блока. Если поля
   оказались постоянным текстом внутри определения, требуется отдельное
   согласованное решение по шаблону; не затрагивать молча чужие вставки.
   Номер/название листа, стадия, подписи, геометрия и другие DWG не меняются.
5. Синтетика: разные листы и динамические имена, кириллица/длинный адрес,
   пустой источник, дубли TAG, несколько штампов, поле FIELD, заблокированный
   слой, удалённая привязка, отмена/сбой записи, повтор без изменений.
   Живая приёмка: пять листов, две смены реквизитов, сохранность остальных
   полей, новый скопированный лист, Undo и save/open; просмотреть печатный вид.

Скорость: один обход пространств листов на вызов, индекс шаблонов и запись
только изменённых значений; без переключения вкладок, пересчёта фасадов
и постоянного реактора на каждое редактирование. Сначала закрыть живой
запуск узла, затем первый шаблон штампа. Автонумерация, ведомость листов,
пакетная печать и синхронизация нескольких DWG — отдельные следующие задачи,
не заявленные как уже реализованные по этому ролику.
