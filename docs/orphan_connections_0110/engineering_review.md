# Кронштейн без ссылки в геометрическом паспорте: основание 2В2

Дата: 01.10.2026. Проверенная исходная точка анализа:
`1a6066d541ed2f62ac40809e1a87e09e434ab591`.
Область неизменна: один пилот Вектор-1 2015, тип 1, керамогранит,
узел 4.2.1, КР2–ПП–УК–ГП. Продуктовые файлы автором этого разбора
не изменялись. Новых инженерных источников и монтажных правил нет.

## Что действительно воспроизведено независимо

Проверен чистый Python-вызов `frame_connections.build_connection_passport`.
Это проверка построения геометрической описи из подготовленных массивов,
**не полный прогон планировщика, C# producer, CAD или табличного экспорта**.
Вход и наблюдения находятся в `source_facts.json` этого каталога.

В синтетическом примере два ГП имеют общую ось X=100 и отдельные отрезки
Y=0…995 и 1005…2000. Единственный кронштейн имеет индекс 0 и Y=1000.
Получен `inventory_only`, два элемента описи, один кронштейн во входном
массиве и ни одной ссылки `bracket_indices` на него. Сводка сообщает ноль
позиций кандидатов и ноль связей; имеется только общая диагностика
`CONNECTIONS_GEOMETRY_ONLY`. Физический индекс кронштейна не получает
адресного объяснения отсутствия ссылки.

Контроль на тех же массивах с торцами обоих ГП при Y=1000 даёт две ссылки
на индекс 0. Это уже неоднозначность общей кандидатной опоры, выявляемая
2В1. Числа 100/995/1000/1005/2000 — только входы синтетики, не разрешённые
монтажные размеры. Существующее сопоставление координат с 0,5 мм не меняется
и не становится допуском на монтажный зазор.

Этот минимальный пример следует отличать от отдельного engine fallback
fixture, который выполнил участник `contract_gap`: его протокол и сохранённые
вход/выход прочитаны отдельно. Реальный запрос содержит явный выбор пилота,
`rail_std=1500`, зазор 10, `bracket_step=null` и
`bracket_step_corner=null`, отметку 1500 и контур 1200×3000. Движок
возвращает два ГП Y=0…1495 / 1505…3000 и один кронштейн Y=1500 без
ссылок; producer и общий валидатор принимают состав, таблица не упоминает
этот ID. Ответ движка не модифицирован. Это принимаемая API/legacy-ветка;
доступность ввода таких null из стандартного UI не утверждается.
При обычном положительном шаге 800 тот стенд даёт шесть кронштейнов без
такого пропуска. Хеши отдельных peer-протоколов сохранены в
`source_facts.json`. Настоящий документ не присваивает выполнение полной
цепи автору инженерного разбора и не подменяет его чистым минимальным
вызовом builder.

## Разрешённая диагностика

Достаточен проверяемый факт: ID кронштейна присутствует в выбранном
подтверждённом составе, но отсутствует среди ссылок кандидатов опор
действительного паспорта. Можно написать:

> Кронштейн <ID>: в проверенном геометрическом паспорте связь-кандидат
> с направляющей не найдена. Монтажная принадлежность не определена.

Точная формулировка может явно говорить об отсутствии ID среди ссылок.
Нельзя сокращать её до вывода об отсутствии фактического крепления,
лишнем кронштейне, ошибке монтажа или неработоспособности конструкции.
Отсутствие предупреждения также не подтверждает существование реальной
монтажной связи. Вывод не удаляет элемент, не меняет количества или
состав и не назначает ему новую направляющую.

## Область, в которой отрицательный вывод допустим

| Условие | Требование |
|---|---|
| Источник | Пройден прежний контроль ведомости и актуальности; паспорт `aframe_connection_passport/1`, статус `inventory_only` |
| Физическая роль и происхождение | `role=bracket`, `origin=generated:ATFRAME:brackets`; сам префикс ID не доказывает допустимое происхождение |
| Прогон | ID начинается с точного `passport.source_run_id + ":brackets:"`; текущий `report.run_id` может отличаться после сохранённого повтора кляммеров |
| Зона | Ровно одна каноническая зона элемента; она входит в выбранные зоны и область данного паспорта |
| Канонизация зон | Уникальные непустые `zone_ids`; лишь при отсутствии таких значений применяется `zone_id`. Повтор одного значения не образует две зоны; отображаемое `zone_id` не переопределяет непустой канонический список |
| Ссылки | Объединение `bracket_element_ids` всех выбранных членов того же подтверждённого источника; повторные сохранённые копии не создают повторное предупреждение |
| Полнота | Частичная номенклатура ведомости сама по себе не равна отсутствию действительной геометрической описи; статус описи проверяется отдельно |

Чужой исходный прогон, несколько канонических зон, неподходящее происхождение
и невыбранная зона исключаются из такого отрицательного вывода. Нельзя
использовать соседнюю зону для поиска оправдывающей или отсутствующей связи.
Состав без направляющих в чистом builder получает `unavailable`; ноль
ссылок в недоступном паспорте не выдаётся за исследованную геометрию.

Отдельно различаются два случая:

- **Ручные шаги ATFRAME:** результат автоматического построения может иметь
  нормальный физический состав и действительный геометрический паспорт.
  Такая схема подходит для этой диагностики при выполнении условий выше.
- **Ручная регистрация, legacy или неподдержанный паспорт:** отсутствие
  описи означает неизвестность связей. Сохраняется прежнее объяснение
  недоступности; предупреждение о доказанном отсутствии ссылки не создаётся.

Разность множества допустимых физических ID и множества существующих ссылок
строится линейным индексированием. Новый геометрический поиск, обход CAD,
изменение допусков и повторный расчёт для такого вывода не требуются.

## Инженерные источники перенесены с явным происхождением

В этой итерации не выполнялась новая полная ревизия PDF. Использованы
ранее проверенные неизменные первичные документы и выводы из
`docs/mounting_contract_0110/source_facts.json`, `engineering_review.md`
и `docs/nominal_mounting_0110/source_facts.json`. Их хеши/локаторы записаны
в новом `source_facts.json`. Оригиналы, изображения и реквизиты объекта
в этот каталог не копируются.

Сохраняются основные основания 2В1:

- АТР PDF 20 / 4.2.1 задаёт семейства горизонтального узла с УК;
  PDF 19 / 4.1 показывает вертикальный вариант У2/У.
- Расчёт PDF 3/14 не сопоставляет разные условные опоры реальным ID.
- Расчёт PDF 6 использует весовую составляющую на L1; это не автоматически
  вес всей L на единственной назначенной опоре.
- Расчёт PDF 12–13 проверяет связи КР2–УК и УК–ГП совместно по весовой
  и ветровой составляющим; полного назначения кинематики всем ID нет.

2Б5 по-прежнему подтверждает условные номинальные базы 0/2/2+L и
символическую цепь УК с неизвестным h. Допустимый полный перехлёст,
рабочий ход, посадки и отверстия не определяются новым подсчётом ссылок.
Никакая новая ревизия первичных страниц или подтверждение их полноты
настоящим документом не заявляется.

## Что по-прежнему нужно для настоящего монтажного контракта

Физическая пара `bracket ID — rail ID` пока означает кандидатное
сопоставление плоской геометрии. Это не идентификация двух отдельных
интерфейсов **ГП–УК и УК–КР2**, их реального исполнения, отверстий/метизов,
разрешённых перемещений и поворотов, жёсткостей, передачи веса и работы
стыка. Исторический выбор сохраняет `physical_assignment=not_asserted`;
производитель ведомости не назначает `product_id` по совпадению координат.

Следующий инженерный переход требует доказанного отображения этих
интерфейсов и грузовых участков на физические ID. Существующие источники
не позволяют закрыть перечисленные пробелы пользовательской галочкой,
словом «несущий», совпадением марки или наличием единственного кандидата.
Запрос новых материалов не входит в этот инкремент; предел имеющихся
доказательств сохраняется точно.

Полный 2В, подтверждённый 3А и автоподбор остаются закрыты.
`MountingStatus=not_confirmed`, `AutomaticBracketSelectionAllowed=false`.
Не сделано заключение об ошибочности исходного проекта или фактического
монтажа. Проверки реализации, компиляция, UI/CI и публикация фиксируются
другими протоколами и не объявляются выполненными этим разбором.
