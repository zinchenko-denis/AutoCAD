## Команды и область хранения

Проектировщик один раз задаёт полный заявленный выбор пилота для текущего DWG. Только явно привязанные зоны наследуют эти значения или содержат локальные исключения. Отсутствие записи зоны означает прежний непривязанный режим; пустой набор исключений в существующей привязке означает наследование. Пользователь видит итоговое значение и его происхождение; изменение проекта не переписывает незаметно ранее построенный каркас.

Для первого инкремента **один DWG является границей проекта**. Общая внешняя база проектов, синхронизация нескольких чертежей и глобальный последний выбор не вводятся. Наличие проектного выбора по-прежнему не подтверждает совместимость сборки, расчётное сечение или фактически установленное изделие.

| Команда | Назначение | Граница |
|---|---|---|
| `ATFPROJECT` | Задать или изменить общие параметры проекта в текущем DWG | Полный проверяемый выбор решения пилота; без скрытых инженерных значений |
| `ATFZONEPARAMS` | Задать для выбранных зон намерение наследовать или явные локальные исключения | Только фиксированный разрешённый набор полей; источник, редакция каталога и узел зоной не подменяются |
| `ATFRAME` | Прочитать итоговые параметры выбранных зон и использовать проверенный снимок | Не редактирует общие параметры проекта и не принимает молча несовместимую группу зон |

`ATFPROJECT` открывает полный редактор выбора. Первое создание явно; старые настройки ATFRAME и глобальный last не становятся проектом. В `ATFZONEPARAMS` выбирают только проверенную штриховку или марку настоящей зоны ATFZONE; несколько указаний одной зоны учитываются один раз. Произвольные контуры, детали и скопированные метки не становятся владельцами параметров.

В формах первый шаг **«Проверить изменения»** показывает значения и последствия. **«Сохранить проект»** или **«Сохранить зоны»** передаёт результат команде записи; **«Назад»** возвращает к вводу, **«Отмена»** на обеих стадиях не записывает изменения. У привязанных зон `ATFRAME → Решение и каталог…` доступен только для чтения. Инструкция с точными действиями — глава 13 [руководства новичка](facades_beginner_3009/README.md).

Проект хранится внутри DWG, зональная привязка — у канонической штриховки. Чистые структуры `FrameProjectParameters`, `FrameZoneParameters` и `FrameParameterContext` проверяют схемы `aframe_project_parameters/1`, `aframe_zone_parameters/1` и `aframe_parameter_context/1`; общий CAD-слой проверяет идентичность владельца и фактическую запись. Проект и зона имеют собственные редакции. Семантически неизменное сохранение не увеличивает редакцию; групповая запись сохраняет независимую историю каждой зоны.

## Наследование и локальные исключения

Проект содержит полный валидированный выбор пилота. Зональные исключения задаются по полям из фиксированного списка; произвольные JSON-ключи и переход к другой идентичности источника не допускаются. Разрешены ровно 13 путей; источник, редакция каталога, узел и геометрические базы не переопределяются. После применения исключений проверяется всё итоговое решение, а не только изменённое поле.

| Семейство | Разрешённые поля исключений |
|---|---|
| КР2 | `bracket.execution`, `bracket.nominal_width_mm`, `bracket.L_mm` |
| УК | `extender.execution`, `extender.nominal_width_mm`, `extender.L_mm`, `extender.thickness_mm` |
| ГП | `profile.execution`, `profile.a_mm`, `profile.b_mm`, `profile.thickness_mm` |
| Необязательные данные | `geometry.cladding_front_offset_mm`, `geometry.insulation_layers_mm` |

Флажок **«Своё значение»** включает исключение. Даже равное проектному число остаётся собственным значением зоны. Наследование кодируется отсутствием ключа; `set` хранит значение, `clear` разрешён только для двух необязательных полей. Слои заменяются всем списком.

| Состояние поля зоны | Смысл | Поведение |
|---|---|---|
| Локального исключения нет | Наследовать значение проекта | Последующее изменение проекта отражается в итоговом значении зоны и его актуальности |
| Явное локальное значение | Использовать проектное исключение этой зоны | Оно сохраняется при изменении общего значения; его происхождение видно |
| Явно очищено необязательное поле | Для этой зоны значение не задано | Не подставлять значение проекта; отличать от наследования |
| Исключение снято | Вернуться к наследованию | Использовать текущее значение проекта после проверки |
| Очистка обязательного размера | Итоговый выбор неполон | Отказ с указанием поля; прежняя корректная запись сохраняется |

Вынос наружной поверхности облицовки от конструктивной стены и слои утеплителя остаются необязательными заявленными данными. Их явная очистка допустима как «не задано». Вынос не равен прежнему плечу расчёта `FrameSettings.Offset`; утеплитель не задаёт длину кронштейна. Обязательные проектные b/c профиля не получают скрытых значений по умолчанию и не становятся подтверждёнными характеристиками сечения.

Снятие всей привязки зоны отделено от очистки необязательного поля и снятия отдельного исключения. После снятия привязки последний унаследованный выбор не превращается в локальный автоматически.

Отсутствующий проект, старый сохранённый выбор 2Б1, повреждённая запись и неизвестная редакция различаются. Нельзя принять повреждённые данные за пустой проект или молча назначить старому каркасу новые значения. Совместимость со старыми DWG проверяется отдельным сценарием; автоматическая массовая миграция не является исходным допущением.

## Несколько зон и уже построенный каркас

Одна операция `ATFRAME` вызывает движок только для группы с **одинаковым итоговым выбором**. При разных итоговых решениях выдаётся отказ с именами затронутых зон; их перестраивают отдельно или однородными группами. Автоматическая пакетная обработка разнородных решений в 2Б2 не обещается. Одинаковые значения из разных источников наследования сохраняют своё происхождение. Смесь привязанных и непривязанных зон отклоняется. Для редактирования через ATFZONEPARAMS требуется одинаковое исходное намерение зон, то есть одинаковый набор исключений либо отсутствие привязки у всех. Редакции привязок при одинаковом намерении могут различаться; общей редакции группы нет.

Изменение параметров проекта или зоны не запускает автоматическое перестроение всех зон. Сохранённый каркас и паспорт относятся к тем входам, по которым они сформированы. Перед использованием или обновлением результата проверяются итоговые значения, происхождение и версии; устаревший результат не выдаётся за актуальный. На первом этапе изменение проекта консервативно делает все зависимые результаты неактуальными, даже если зона переопределила изменённое поле и её итоговое число совпало. Старые непривязанные результаты 2Б1 не получают зависимость от проекта молча.

Актуальность связывает результат с проектом, владельцем зоны, редакциями, отпечатками содержимого и исходных записей, итоговым выбором и происхождением полей. Проверенный непрозрачный текст записи сравнивается перед записью результата; Common не пересчитывает по нему каталог. В сохранённых настройках каждой зоны находится только её контекст. Общий снимок операции содержит общую ссылку на проект и компактные ссылки зон; полное решение не копируется в каждую строку ведомости.

Полное ATFRAME разрешает текущий выбор из проекта и зон; устаревшие различия прежних деклараций не заменяют эту проверку. Старые записи отдельно проверяются на изменение во время операции. «Только кляммеры» сохраняет каркас, его решение и исходную зависимость; изменение проекта, привязки или её снятие требует полного перестроения, даже если итоговое число совпало.

Отмена диалога, неверные данные и устаревший снимок до записи оставляют прежние параметры. Связанная запись выполняется одной транзакцией после повторной проверки проекта, геометрии зон и ожидаемых записей. Undo и сохранение/повторное открытие требуют живой проверки AutoCAD; модель отката на doubles не заменяет её. Переключение DWG, SaveAs и копирование зон входят в приёмку; перенос не назначает новый проект или привязку автоматически.

## Маленькие проверяемые инкременты

Контракт, ядро, хранение, команды и формы реализованы небольшими инкрементами. Таблица сохраняет критерии перехода; она не является итоговым протоколом PASS. Сквозная ревизия исходников завершена на c4fd140; найденные ошибки и их повторные проверки остаются в истории.

| Инкремент | Конкретный результат | Проверка перехода |
|---|---|---|
| 1. Контракт и воспроизведение | Фиксированный состав проекта/исключений, состояния отсутствия и очистки, версии и правила разрешения | Примеры наследования, исключения, снятия, неполноты и неизвестной редакции с независимыми ожидаемыми результатами |
| 2. Чистое разрешение значений | Детерминированный итоговый выбор и происхождение полей без обращения к CAD | Граничные значения, полный повтор валидатора 2Б1, одинаковый результат при разном порядке зон, отказ неоднородной группе |
| 3. Хранение и актуальность | Раздельные данные проекта, зон и сохранённого результата; атомарная запись | Старые DWG, повреждённые записи, отмена, устаревший снимок, неизменность локальных исключений, изоляция разных DWG |
| 4. Интерфейс и `ATFRAME` | Явные команды проекта/зон, чтение итоговых значений, понятные отказы | Происхождение видно; очистка отличается от наследования; mixed-выбор перечисляет зоны; режим кляммеров не подменяет решение |
| 5. Сквозная ревизия 2Б2 | Одни параметры согласованы с построением и проверкой актуальности ведомостей | Регрессии, компиляция трёх плагинов, синтетика и роли, Windows UI с просмотром снимков, руководство по фактическому поведению |

Завершение 2Б2 означает проверенное управление заявленными параметрами пилота. Оно не закрывает последующие инженерные этапы и не является живой приёмкой AutoCAD.

## Производительность — часть контракта

Сохраняем уроки задержек 26.09b/c и архитектуру ведомостей: один снимок входов на операцию, чистые DTO для разрешения параметров, один неизменяемый каталог и повторная проверка актуальности перед записью. Разрешение значений выполняется по зонам, а не по каждой физической детали. Не вводим повторное чтение каталога, запуск движка или полный обход DWG для каждого поля/зоны. CAD API не вызывается из фоновых вычислений.

Реакторы не выполняют полный расчёт или массовое перестроение. Кеш не переживает изменение входов без явной версии. Для роста числа зон, локальных исключений и деталей отдельно измеряем извлечение, разрешение параметров, проверки, построение и запись; считаем обращения к CAD, объём данных и память. Численных обещаний о скорости живого DWG до измерения в AutoCAD не даём. Техническая база — [FRAME_QUANTITIES_30.09.md](FRAME_QUANTITIES_30.09.md).

## Воспроизведение и найденные ошибки

До правок выполнен [baseline](project_params_0110/baseline.json) на `375f082887a052bcba3d0379bd4946ef39b25604`: восемь наблюдений подтвердили независимые сохранённые декларации без проектного наследования, отсутствие различия между наследованием и очисткой, отсутствие общей проектной зависимости в проверке актуальности. Старый отказ разным локальным решениям и изоляция отмены сохранялись корректно. Отсутствие нового контракта в 2Б1 не объявляется старой ошибкой.

В ходе реализации и независимых прогонов зафиксированы следующие случаи. Итоговые результаты и привязку к финальному коммиту записываем отдельно после полного повтора и Windows CI.

| Случай | Причина и принятое правило | Воспроизведение / регрессия |
|---|---|---|
| Повреждённый ExtensionDictionary читался как отсутствие привязки | Существующий объект неверного типа нельзя считать пустым хранилищем; чтение должно дать отказ | `native_store_probe.cs`: `existing invalid extension dictionary never becomes absent binding` |
| Старые разные решения мешали полному построению привязанных зон | Для полного построения сравниваются текущие итоговые решения проекта/зон; старые записи проверяются отдельно на актуальность | `CommandIntegrationProbe.cs`: `actual generation operation ignores obsolete local disagreement only for explicit current project` |
| Подтверждение нового поколения геометрии терялось как обычное сохранение | Только явный редактор привязки показывает подтверждение нового поколения; перед записью нужны неизменная старая запись и свежий отпечаток геометрии. Обычное использование старой привязки отклоняется | `native_store_probe.cs`: `explicit same-owner generation rebind differs from ordinary stale consumption`; интеграционный сценарий `explicit rebind confirms new generation` |
| Одинаковые исключения ошибочно воспринимались как общая редакция | У зон могут быть разные истории при одинаковом намерении; форма не приписывает всей группе номер первой зоны, запись увеличивает собственную редакцию каждой | `CommandIntegrationProbe.cs`: `actual zone command group keeps independent revision history`; `ProjectUiProbe.cs` проверяет подпись группы |
| После снятия привязки могли пройти только кляммеры | Нельзя превращать старый унаследованный снимок в локальный либо терять его через выбор марки. Нужны проверка канонического владельца, вариант сохранённого контекста только на марке и свежая проверка исходной записи | `CommandIntegrationProbe.cs`: варианты `refuses clamps after explicit detach`, `refuses detached inherited alias even if canonical metadata is absent`, `clamps checks canonical-linked alias provenance` и `saved baseline is separate from current effective scope`; исправления внесены, итоговая ревизия продолжается |
| Сохранённый отпечаток привязки принимался за свежую геометрию | Для привязанного пилота перед записью повторно вызывается существующий `ZoneGeometryGuard`; проверяются владелец и отпечаток независимо от доступности ведомости | `project_params_0110/bound_geometry_reproducer.json`: 33 проверки / 1 воспроизведённый отказ до исправления; после исправления интеграционный набор 33/33 PASS на адаптерах, не в живом AutoCAD |

Пробы находятся в [tools/project_params_0110](../tools/project_params_0110/). Они вызывают настоящий код контрактов, хранилища и команд с doubles для AutoCAD, а не подтверждают запуск в AutoCAD. Нативные формы отдельно требуют Windows-прогона и независимого просмотра каждого снимка; локальная компиляция при недоступном дисплее не считается визуальным PASS.

## Приёмка пилота и сохраняемые ограничения

После завершения правок и ревизии пилот проверяется в живом AutoCAD: ввод параметров, наследование и исключения, формирование и перестроение каркаса, ведомости, отказы при устаревании, Undo, сохранение/открытие и время работы на реальном DWG. Герман проверяет инженерный смысл и эталоны; автоматические тесты и native WinForms не заменяют эту приёмку. Неизвестные данные должны оставаться видимыми на всех этапах.

Расчёт явного исторического выбора 2Б1 остаётся закрытым до подтверждения соответствия сечениям. Геометрические кандидаты опор не назначают fixed/sliding, непрерывность или допустимые усилия. Тип 5 и NordFOX не реализованы; АТР Вектор-4 отсутствует; НСП-2 и ГП-60-40 ограничены до подтверждения сечений; АКП поддерживается как каркас без подтверждённого крепления кассеты. Межэтажный автоматический расчёт закрыт, полная статика vertical/ortho не подтверждена.

Работа ограничена Facades, AClad, AFrame и общим фасадным кодом. ATableSpec и ABlockGen не изменяются. `main` не меняется без отдельного разрешения. Новый установочный выпуск — только по команде Дениса **«Собираем»**; сама разработка 2Б2 разрешением на сборку не является.
