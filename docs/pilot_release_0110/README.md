# Фасадный пилот build 105

> **Исторический комплект build-105.** Ревизия 02.10 выявила ограничения расчёта
> на фасадах с окнами и возможность коротких направляющих с одной опорой в
> ручном режиме. Две пустые стены прежнего маршрута проверяют обмен данными,
> но не служат монтажным эталоном крайних плит. Установленные DLL этого выпуска
> не меняются от исправлений исходников. Перед продолжением смотрите
> [текущий план](../CURRENT_MILESTONES.md) и [новый короткий маршрут](../pilot/PILOT_QUICK_START.md).
> Все три фасадных модуля необходимо обновлять вместе.

Комплект для Германа и проектного отдела по команде Дениса от 01.10.2026
«собираем всё». Цель — проверить существующие функции в AutoCAD 2024,
получить замечания по удобству, геометрии, ведомостям, сохранению и скорости.
Ответы на инженерные вопросы не требуются до начала проверки.

Установочный выпуск: [build-105](https://github.com/zinchenko-denis/AutoCAD/releases/tag/build-105).
Собранный SHA: `c4009838875aa0f225971153bf4b54fe288e8e79`.
Для этого пилота обновляются вместе AFacades, AClad и AFrame.

## С чего начать

1. Установить три модуля по [короткой инструкции](INSTALL_AUTOCAD_2024.md).
2. Открыть [стартовый DXF](assets/Pilot_KG_2zones_source.dxf) и пройти [маршрут П00–П17](PILOT_GUIDE.md).
3. Записывать фактический результат в [форму обратной связи](FEEDBACK_TEMPLATE.md).
4. Для отдельных полей обращаться к [полному руководству Word](../facades_beginner_3009/Facades_Beginner_Manual_30.09.docx) или [PDF](Facades_Full_Manual_build105.pdf).
5. По возможности ответить на [шесть вопросов по одному рабочему узлу](ENGINEERING_QUESTIONS.md). Новые альбомы и описание всех систем не требуются.

Word/PDF версии установки и маршрута и единый архив с тремя бандлами,
инструкциями, формой обратной связи и учебными DXF размещаются в Assets
того же выпуска. Их имена и контрольные суммы приведены в `delivery_manifest.json`.
Бинарные установочные архивы не добавляются в исходное дерево Git.

## Что считается результатом

Первый контрольный вход: две стены 1210×1820 мм, 12 плит,
2 ГП / 3,64 м, 6 условных кронштейнов. Далее — сохранность при изменениях,
проверка источников, вывод, сохранение/открытие и реальный фасад.
Успешные автоматические проверки не проставляют PASS за инженера.
До его протокола живая проверка остаётся NOT_RUN.

Расчёт несущей способности выбранного пилота, автоподбор, полный рабочий
монтажный узел и полный состав крепежа не завершены. Ручные шаги берутся
из принятого проекта/отдельного расчёта. Наличие кнопки или успешная
расстановка не подтверждает инженерную пригодность конструкции.

После пилота нужны исходный и итоговый DWG с соответствующим JSON,
XLSX, заполненный протокол, F2/снимки и минимальные примеры ошибок.
Рабочие файлы объекта передаются через согласованное закрытое пространство.
Публичный GitHub хранит программу, инструкции и обезличенные проверки.

## Проверки выпуска и передача

- `publication_evidence.json` — номера и статусы Windows build/check, исходный SHA, тег и сведения GitHub об архивах.
- `bundle_receipt.json` — десять скачанных ZIP, равенство latest/build-105, состав, DLL/EXE и файлы бандлов.
- `release_extension_receipt.json` — наличие новых команд проекта/зон/узла, классов и модулей каталога внутри выпуска.
- `local_verification.json` — необходимые локальные проверки и неизменность продуктовых исходников.
- `delivery_manifest.json` — состав передаваемого архива и инструкции.
- `handoff_receipt.json` — итог публикации и границы подтверждения.
- `repository_publication.json` — коммит передачи `4cafef1` и успешный Windows check №221; сборка №105 по-прежнему соответствует `c400983`.
