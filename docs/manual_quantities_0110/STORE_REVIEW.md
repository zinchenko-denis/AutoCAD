# Ревизия хранения и актуальности ручных ведомостей Q-06

Исходная точка — `2e0abf2`. Область ревизии: `Common/FacadeQuantityStore.Manual.cs` и его взаимодействие с общим чтением паспортов. Инженерные свойства, расчётные схемы и ограничения систем эта работа не меняет. Приватных образцов и исходных расчётов в проверочные материалы не добавлено.

## Владение и отсутствие двойного счёта

- Ручное назначение хранится отдельно: `AFACADE_MANUAL_QUANTITY` на физическом объекте, индекс в `AFACADE_QUANTITIES/MANUAL_INDEXES/<kind>_<canonical hatch handle>`, независимый якорь `AFACADE_MANUAL_QUANTITY_INDEX_<kind>` на канонической штриховке ATFZONE.
- Индекс хранит точные soft references и digests назначений; назначение — документ, собственный handle, устойчивый `element_id`, ссылку и fingerprint зоны, типизированную физическую деталь и неизменяемое сопоставление. Потеря записи или ссылки не превращается в подтверждённый ноль.
- `MANUAL_RULE_<rule_id>` не перезаписывается другим содержимым. Для изменённого сопоставления требуется новый идентификатор. Номенклатура не восстанавливается из одного имени слоя.
- Повторный импорт того же объекта сохраняет его физическую идентичность. Копия ручной метки получает новую идентичность только при явном импорте. Снятие назначения копии не удаляет членство оригинала.
- Собственные метки AClad/AFrame, включая старые метки и вспомогательную графику с меткой детали, запрещают переклассификацию в ручное назначение. Общий контракт дополнительно запрещает один CAD handle в двух физических деталях.
- Совпадающие разные объекты не удаляются и не вычитаются. Ключи возможных совпадений собираются в словари, без попарного сравнения всего состава. Общий читатель выдаёт предупреждение, в том числе для совпадения ручной и автоматически построенной детали.

## Актуальность и частичный повторный импорт

До записи повторно проверяются зона, документ, сопоставление и полный предпросмотр выбранных объектов, включая отклонённые. Изменение отклонённого объекта, после которого он становится распознаваемым, также требует нового предпросмотра.

При частичном повторном импорте обновляются только выбранные назначения. Остальные сохраняют прежние fingerprints геометрии и зоны. Поэтому новый импорт одного объекта не скрывает удаление соседней детали или устаревание всей зоны. При чтении проверяется весь ручной индекс выбранной зоны, а затем он добавляется к полностью проверенному исходному generated ledger.

Ручной вклад явно имеет статус `partial` и покрытие `manual_geometry_and_user_mapping_only`. Он не расширяет автоматически групповой раскрой облицовки или оценку хлыстов подсистемы. Эти ограничения присутствуют в issues отчёта, а не только в документации.

## Производительность и отмена

Batch import читает и записывает индекс один раз. Снятие выбранных назначений группируется по индексу; проверка членства использует HashSet. Операции импорта не сканируют ModelSpace. Общий читатель использует один существующий проход для проверки generated copies и ручных orphan/copy назначений.

Контексты геометрии, определений блоков, проверенных зон и подготовленных сопоставлений живут только внутри текущей операции чтения. Сопоставление подготавливается один раз на правило; одинаковые диагностические сообщения группируются. Кеш не переносится через диалог или изменение модели.

`PreviewImport` и `ApplyImport` принимают callback отмены. Он проверяется при чтении объектов, подготовке и записи назначений, а также до и после записи индекса. До первой записи выполняется полная подготовка. Отмена во время записи рассчитывает на обычный rollback внешней AutoCAD-транзакции; этот native механизм не имитируется CAD doubles.

## Явное восстановление учёта

- `RemoveManualSelected` снимает только выбранные назначения и не удаляет геометрию. Удаление самой канонической штриховки не создаёт тупика: выбранные собственные назначения можно снять, сохранив остальные записи старого индекса явно недействительными. После снятия последнего назначения старый индекс удаляется.
- `ClearManualZone` очищает выбранный вид учёта зоны. Это отдельная явная ремонтная операция с одним проходом ModelSpace: она находит назначения зоны даже при потере индекса и удаляет только метаданные учёта.
- Повреждённое назначение с нечитаемым JSON можно очистить по сохранившейся authoritative soft reference. Если одновременно потерян индекс и испорчено само назначение, принадлежность неопределима: программа не удаляет предположительно чужие данные автоматически.

## Границы проверки

Исполняемые проверки используют настоящий Store, mapper, geometry adapter и существующие guards с независимыми синтетическими данными. Итоговые количества проверок и хеши входных файлов следует брать из финального manifest этой итерации, а не из промежуточных запусков.

CAD doubles проверяют явные состояния Xrecord, ObjectId, геометрии, определений блока, атрибутов и динамических свойств. Они не доказывают поведение native COPY с remapping, Save/reopen, Undo и rollback транзакций. Эти сценарии, UI и длительные операции с Esc требуют отдельной живой приёмки AutoCAD после ревизии кода.
