## Конкретный пробел и границы воспроизведения

В 2В1 адресно показан кронштейн-кандидат нескольких ГП. Обратный случай
оставался без адреса: физический кронштейн включён в проверенный состав,
но его ID отсутствует во всех ссылках кандидатов опор этого паспорта.
Общее предупреждение о непроверенных закреплениях не позволяло найти ID.

Воспроизводитель `tools/orphan_connections_0110/reproduce_gap.py` использует
действительный движок, C# producer `FrameQuantities`, общий validator,
общую модель таблицы и XLSX. Синтетический принятый движком вход с
`bracket_step=None`, `bracket_step_corner=None`, уровнем 1500 и зазором 10
даёт два отдельных ГП `[0;1495]`, `[1505;3000]` и кронштейн на Y=1500.
Паспорт `inventory_only` содержит оба ГП, но не содержит ссылок на этот
кронштейн. **Это резервный engine/API-вход; текущий диалог ATFRAME передаёт
числовые шаги не меньше 100 и такой вход не создаёт.** Не утверждается,
что наблюдался соответствующий пользовательский DWG или ошибка монтажа.
Размеры здесь — только геометрический тест, не допустимые монтажные размеры.

Независимое геометрическое воспроизведение описано отдельно в
`orphan_connections_0110/engineering_review.md`; его нельзя выдавать за
второй полный сквозной прогон. Базовое и исправленное воспроизведения
одного входа сохраняются с хешами. Планировщик и критерии координатного
совпадения ради теста не менялись.

## Пользовательский результат

В `ATFTABLE → Подсистема → Соединения` общая адресная запись содержит
физический ID кронштейна и зону: ID есть в проверенном составе, но
отсутствует среди ссылок кандидатов опор этого паспорта. Монтажная
принадлежность, наличие и тип крепления не определены.

Проверяются только созданные ATFRAME кронштейны того же `source_run_id`
с одной канонической выбранной зоной, покрытой доступным паспортом
`inventory_only`. Источник сохранённого паспорта может отличаться от
текущего `report.run_id`: сравнивать нужно происхождение физических ID.
Копии отчётов и повторные ссылки не создают повторных предупреждений.

Независимая ревизия воспроизвела дополнительную границу валидатора:
разные ID паспортов одного исходного прогона в разных отчётах могут
содержать разные ссылки одного ГП. Сбор ссылок после дедупликации строк
давал зависимость отрицательного вывода от порядка отчётов. Ссылки
теперь собираются до дедупликации; оба порядка проверяются. Это отдельный
принятый валидатором DTO-контроль, не заявленный сценарий обычного producer.
Исправлена именно достоверность нового отрицательного вывода; правила
выбора уже существующих строк при конфликтующих копиях не перерабатывались.

Недоступный паспорт, старый источник без паспорта, ручная регистрация,
другая зона/источник и неоднозначный многозонный элемент не превращаются
в «нулевую связь». Прежняя недоступность сохраняется. Ручные числовые шаги
самого ATFRAME не равны ручной регистрации: при действительном паспорте
они проходят общие правила.

Кронштейн остаётся в физических количествах. Новая строка ГП для него
не создаётся; существующие строки направляющих и общий вывод
предпросмотра/DWG/XLSX сохраняются. Отсутствие кандидата не означает
лишнюю деталь, отсутствие реального крепления или монтажную ошибку.
Отсутствие предупреждений не является инженерным PASS.

Ревизия также нашла новую ячейку длиной 33201 символ при допустимом
валидатором синтетическом ID исходного прогона из 13000 символов и зоне
из 20000. На том же входе прежняя таблица не превышала лимит Excel.
Для длинного предупреждения введена техническая «Запись N» с отдельными
нумерованными частями полного ID и зоны; значения не усекаются, повторяющиеся
части и пары Unicode сохраняются. Обычная формулировка прежняя.
Граница длины текста техническая и не является монтажным ограничением.

## Скорость и область изменения

Изменение находится в чистом представлении `ConnectionTableData`.
Существующий индекс общих кандидатов сохранён. Для отрицательного вывода
собирается множество ссылок всех доступных выбранных паспортов до
дедупликации строк ГП; физические кронштейны индексируются по источнику и зоне. Выполняется проход состава и покрытых
областей паспорта, затем разность ID. Нет поиска всех кронштейнов для
каждой направляющей и повторной выдачи списка соседей в каждой строке.
Счётчики операций и масштабные проверки фиксируются вместе с результатом.

Дополнительных CAD-чтений, ModelSpace scan, Python/PDF/сети при просмотре
нет. Схемы DTO/Xrecord, запись, проверки COPY/свежести, геометрия и количества
не меняются. Стендовые времена не являются временем живого AutoCAD.

## Инженерный результат и следующий шаг

Использованы только существующие источники и их ранее установленные
границы. Идентичность физической детали не подтверждает интерфейсы
ГП–УК и УК–КР2, крепёж, отверстия, степени свободы и жёсткость.
`physical_assignment=not_asserted` остаётся честным описанием каталожного
выбора. Кандидатная пара bracket–rail не становится подтверждённой сборкой.

Сохраняются номинальные базы 2Б5 и неизвестное h; min30 других узлов не
задаёт весь диапазон 4.2.1. Не определены распределение веса, рабочие
температурные перемещения, непрерывность и передача N/Q/M через стык.
`MountingStatus=not_confirmed`, `AutomaticBracketSelectionAllowed=false`;
`E_SOLUTION_CALC_UNCONFIRMED` не снимается. Исходный проект не объявляется
ошибочным. Полный 2В и подтверждённый 3А остаются закрыты.

Следующий агент должен на актуальном снимке воспроизвести новый предметный
пробел того же пилота: сопоставление реальных физических ID, интерфейсов
связей и источников. Затем — небольшой доказанный инкремент или точный
отказ. Не повторять этот отчёт как новый этап и не назначать неизвестные
характеристики. Каталог не расширять до живой приёмки пилота.

Исходники/тесты/доказательства публикуются только в `feat/auto-reactor`.
ATableSpec, ABlockGen и main не меняются. Build-104 прежний; новый выпуск
только по новой команде «Собираем». Живой AutoCAD пока не проверен.
