# Исправления предметных правил AFrame — 30.09.2026

Основание: `docs/REVIEW_30.09.md` и `docs/review_3009/Domain.md`. Здесь отделены исправленные ошибки от временных границ поддержанного расчёта. Изменения ATableSpec и ABlockGen не выполнялись. Общий статус фиксации и публикации — в `docs/FIXES_30.09.md`.

## Исправлено

1. **Масса облицовки сохраняется при смене типа каркаса.** `FrameSettings.SetSubType` больше не заменяет 25 на 8 и обратно. Восстановление неполных старых настроек также не выбирает массу по признаку «межэтажная». Явно сохранённые значения, включая 8 кг/м², остаются исходными данными пользователя. Проекты, где 8 уже было записано прежней версией, требуют проверки фактической массы: автоматически отличить прежнюю ошибку от правильного ручного значения нельзя.
2. **Коэффициент веса задаётся материалом.** `CalcDict` передаёт `gamma_clad`, описание в форме показывает его. Рабочие значения: КГ/клинкер — 1.1, АКП — 1.2. Для бетонной плитки сохранён рабочий коэффициент 1.1; его применимость к конкретному изделию остаётся предметом инженерного подтверждения. Это значения переданной методики/рабочего пресета, а не универсальное утверждение нормативной достаточности. В Python `cladding_gamma` даёт ту же классификацию; `frame_plan` применяет её для прямых запросов без C#. Явный корректный коэффициент в расширенном расчётном запросе сохраняется.
3. **Композит не получает кляммеры керамогранита.** В форме уточнено «композит (АКП)». Режимы «подсистема и кляммеры» / «только кляммеры» недоступны для новой команды и отклоняются валидатором; старый выбранный режим не заменяется молча, показывается предложение выбрать «только подсистему». Движок также отказывает таким запросам. Геометрия и расчёт поддержанного каркаса остаются доступны; узел крепления АКП в результат не включён.
4. **Непригодные числовые исходные отвергаются.** `resolved_inputs` разрешает значения из явных входов/каталога, проверяет конечность и допустимый знак расчётных величин, положительные характеристики сечения, целое число заклёпок, ненулевые плечи знаменателей. `report` и `calc_chain` используют эту проверку. NaN/Infinity, отрицательная грузовая ширина, нулевой пролёт/фактор, 1.5 заклёпки не дают расчётного результата. Строковые числовые характеристики пользовательского профиля нормализуются в отдельной копии до арифметики; непарсируемая строка даёт понятный `ValueError`, не `TypeError` внутри формулы.
5. **Расчёт получает воспроизводимый снимок исходных данных.** Новый `resolved_inputs` возвращает копию словаря с разрешёнными `w0`, коэффициентом материала, `ry`, районом гололёда, количеством заклёпок, плечами анкера и остальными входами. Этот снимок используется AFrame при формировании отчёта и повторной проверке. Исходный словарь не изменяется.

## Граница поддержанного сечения НСП

Выбор НСП ранее влиял на подпись/видимость выданного профиля отдельно от расчётного выбора сечения. Аудит не установил, какое конкретно сечение соответствует НСП-2, и не объявлял отдельную доказанную аварию НСП-2. Однако положительный расчёт другого сечения не подтверждает выбранный профиль.

Для НСП-1 имеется явное соответствие в переданной методике: `НСП-1 (69-60-1,2)` с расчётными характеристиками этого сечения. Связь закреплена в планировщике. Для НСП-2 автоматический расчёт ограничен до получения однозначного соответствия марки, толщины и характеристик сечения; форма объясняет причину. Ручной режим с отдельным инженерным расчётом сохранён. В его описании прямо указано, что программа не проверяет несущую способность по ручному шагу.

Это адресная граница, а не запрет всех нормальных расчётов. Контрольный прямоугольник 6000×6000 мм, оси через 600 мм, перекрытия 0/3000/6000 мм; КГ 25 кг/м², II/B/30 м, вынос 230 мм, анкер 3000 Н:

| Схема | Результат текущего движка | Шаг рядовой / угловой, мм |
|---|---|---:|
| Вертикальная | Успех | 800 / 500 |
| Межэтажная, НСП-1 | Успех | 350 / 200 |
| Ортогональная | Успех | 800 / 500 |

Исторические примеры клинкера/АКП из предметной рецензии теперь могут законно получить отказ при ограничении реальным НСП-1. Тесты сохраняют те же входы и проверяют фактический коэффициент, пришедший в настоящий `frame_calc.report`, совпадение с явно заданным коэффициентом и отсутствие выданного каркаса при отказе. Таким образом, два одинаковых отказа сами по себе не подменяют проверку исправления.

## Что не объявляется решённым

Не введена новая «строгая нормативная методика» без инженерного обоснования. Проверки отдельных профилей/анкера/соединений не равны расчёту всех узлов НВФ. Для АКП нужен выбранный узел крепления; для НСП-2 — подтверждённое сечение; для бетонной/клинкерной плитки — актуальные данные изделия, шин и соединений. Геометрические изменения, фактические пролёты и опирание описаны в приложении исправлений AFrame. Полный комплект документации производителя этой правкой не заявляется.
