# AFrame — исправления ревизии 30.09.2026

Проверка относится к исправленным исходникам после ревизии `e2a4e4d`. Изменения ограничены фасадными модулями; общий статус фиксации и публикации — в [FIXES_30.09.md](../FIXES_30.09.md). Предметные настройки и расчётный helper описаны отдельно в [Domain.md](Domain.md).

## Поведение и воспроизведения

1. **Фактический этажный пролёт.** `frame_plan.py:_max_floor_span` берёт максимальный интервал заданных/автоматических этажей с учётом границ стены. Явный короткий `calc.rail_len` не уменьшает фактический пролёт. Старый случай стены 5000×11000 с отметками 0/3000/6000/10000 теперь передаёт расчёту **4000 мм**, получает `E_CALC_NOT_PASSED` и не выдаёт элементов. В нормальном контрольном случае 3600×6000 с отметками 0/3000/6000, II/B/15 м, 8 кг/м², выносом150 и анкером3000 Н остаются расчётные шаги **550/300 мм**.
2. **Сечение связано с выдачей.** Для расчётной межэтажной НСП-1 проверяется НСП-69-60-1,2 по подтверждённому соответствию; НСП-2 без подтверждения сечения получает отдельный отказ. Ортогональная проверяется по ZП-40-20-1,2, чьи Wx/Jx/A меньше обоих выдаваемых вертикальных сечений. Для вертикальной при разных победителях оптимизации в поле/углу выбирается одно проходящее в обеих зонах сечение; отсутствие общего варианта — отказ. Выбор вертикальной марки не переопределяет межэтажное/ортогональное сечение.
3. **Проверка выданных шагов.** После расстановки `_verify_calc_spacing` собирает соседние кронштейны каждого непрерывного элемента, сравнивает интервалы с выбранным пределом и повторяет существующую расчётную цепочку на максимальном фактическом шаге. Результат записан в `calc_report.layout_verification`. Отклонение — `E_CALC_LAYOUT`, без элементов. Этот контроль обнаружил ещё одну реальную ошибку: ось у окна 1586 мм переносилась на1490 мм, в угловую полосу шириной1500, но сохраняла рядовой шаг; выходило575 при пределе500. Теперь шаг каждого смещённого куска выбирается по его фактической оси. Все шесть соответствующих дампов полного прогона ролей повторно дают `ok=true`.
4. **Минимум опор НСП в расчётном режиме.** Проверяются геометрические пересечения каждого выданного куска НСП с выданными НГП, с допуском половины термозазора+1 мм. Менее двух разных отметок — `E_CALC_TOPOLOGY_UNSUPPORTED`. Стена3600×6000 с единственной отметкой3000 имела по одной такой опоре у кусков [0,2995] и[3005,6000]; теперь отказ. Та же стена с отметками0/3000/6000 проходит. Ручной режим с проектными параметрами сохранён. Это геометрическая проверка пересечений, **не расчёт прочности соединения**.
5. **Пустые локальные оси/ряды.** `frame_engine.py` отличает отсутствующий ключ от явного пустого массива во всех трёх маршрутах подготовки зон. В исходном примере зонаА с `rows_y=[]` имеет **0 кляммеров** и отдельно, и вместе с соседней зоной; прежде совместный выбор давал9.
6. **Собственные короткие направляющие.** C# сохраняет `ATFRAME_RAIL`: направление, роль куска, локальные координаты относительно габарита и параметры блока. Чтение собственных объектов не использует старый фильтр «высота≥3ширин». Перенос/COPY восстанавливает текущие координаты из текущего габарита; изменение размера/поворота/масштаба блока требует полного перестроения до повтора кляммеров. Неоднозначные прямоугольники старой сборки без метки также требуют однократного полного перестроения; прежние элементы не удаляются. Исходный случай: **6 направляющих**, включая три длиной140 мм при ширине60, и **21→21 кляммер** при повторе; раньше21→15.
7. **Роли кусков и F16.** `rails` несут `clamp_role=regular/window/flank`; C# передаёт её в `rails_fixed`. Объединяются только куски одной роли. Для старых данных оконная роль определяется до продления короткого остатка до верха стены. Независимый вертикальный контрпример теперь даёт **55→55 одинаковых кляммеров**. Полная синтетика проверяет оба пути — с ролью и без неё; исключение F16 для прохождения не требуется.
8. **Шины без опоры.** После существующих конструктивных продлений/добавлений направляющих остаточные куски без направляющей или стыки без опоры дают `E_UNSUPPORTED_SHINA`. Исходный фронтон4800×6000 с рядом5900 и шиной длиной160 мм получает `unsupported_counts={pieces:1,joints:0}` и пустой выход. Это ограничение неподдерживаемого узла, а не «успешная схема с INFO». Решение: изменить проектные шаги/границы либо разработать узел; автоматическое инженерное решение не выдумывается.
9. **Прямые расчётные входы.** Явные0, отрицательные числа, NaN/Infinity для `b`, `b_corner`, `rail_len`, `max_step` больше не превращаются в умолчания. Сохранены явный `gamma_clad=0` и нецелое число заклёпок до проверки helper — они корректно отклоняются. Полные разрешённые исходные сохраняются в `calc_report.inputs`.
10. **Отмена выбора точек.** Esc в списках углов/перекрытий прекращает ATFRAME до запуска движка и удаления. Enter завершает список и продолжает команду.

Дополнительно устранено переиспользование переменной `parts` в плиточной ветке: сводка прямого `frame_plan` сохраняет строковый режим.

Основные места кода: `AFrame/engine/frame_plan.py:807` — фактический пролёт; `:994` — итоговая проверка шагов; `:1038` — повтор кляммеров; `:2196` — шаг смещённой стойки; `:2504` — отказ по шинам; `:2528` — опоры НСП; `:2541` — покрытие расчёта. `AFrame/engine/frame_engine.py:262,282,330` — сохранение пустых локальных списков; `AFrame/src/AFramePlugin/FrameCommand.cs:1690,1715` — запись/чтение меток направляющих, `:944` — вывод покрытия.

## Контракт отказа и сохранность прежней схемы

`frame_plan` возвращает `ok=false`, понятное `error` и точный `error_code`. `op_frame` добавляет `failed_zone`; ни один такой ответ не содержит непустых `rails`, `hrails`, `brackets`, `clamps`, `fittings`. При отказе любой зоны общий запрос не выдаёт частичную схему. В C# проверка `ok` и чтение метаданных существующих направляющих предшествуют транзакции удаления/построения.

| Код | Условие | Диагностика |
|---|---|---|
| `E_CALC_NOT_PASSED` | Не прошла цепочка или неправильные исходные | Текст причины и поля/узла |
| `E_CALC_LAYOUT` | Выданные интервалы не укладываются в подтверждённую цепочку | Фактический шаг и предел |
| `E_CALC_TOPOLOGY_UNSUPPORTED` | У НСП менее двух геометрических пересечений с НГП | `unsupported_counts.nsp_pieces`, список координат и `support_y`, `calc_inputs` |
| `E_UNSUPPORTED_SHINA` | Кусок шины/стык остался без опоры | `unsupported_counts.pieces/joints`, координаты кусков |
| `E_NSP_SECTION_UNCONFIRMED` | Расчёт НСП-2 без подтверждённого сечения | Предложение НСП-1 либо ручного проектного режима |
| `E_COMPOSITE_FASTENERS_UNSUPPORTED` | АКП с режимом all/clamps | Предложение режима «только подсистема» |

## Граница проверки

`calc_report.method.coverage` и командная строка AutoCAD явно сообщают: проверены указанные расчётные цепочки и выданные шаги. Монтажные узлы, консоли, горизонтальные НГП/СП и проект в целом требуют отдельной проверки конструктора. Пересечение НСП×НГП не доказывает несущую способность соединения. Подбор общего профиля и слабейшего Z не является новой универсальной методикой для всех производителей.

AutoCAD2021/2024 здесь не запускался. Живые COPY/Undo/SaveAs, динамические блоки и воспроизведение меток в DWG требуют приёмки в AutoCAD. C# test doubles подтверждают исполнение конкретных методов и не названы полноценным испытанием хоста.
