# Актуальность зон и раскладок — 30.09.2026

Проверка одной площади и габарита пропускала изменение формы стены и перенос проёма. Выбор одной MText-марки обходил даже эти проверки. В контрольном фасаде 4000×3000 мм перенос окна 800×1000 мм сохранял площадь 11,2 м², но старая геометрия приводила к выдаче двух кронштейнов и двух кляммеров внутри нового положения окна.

## Изменения

- **ATFZONE** записывает на штриховку и марку контрольный снимок геометрии: исходные полилинии, зарегистрированные проёмы, фактические границы штриховки, её связи, рассчитанные части и данные отчёта. Проверяется принадлежность носителя. Снимок создаётся в той же транзакции; если свежая геометрия не подтверждена, построение откатывается.
- **ATFTABLE** проверяет каждый выбранный носитель до объединения строк. Старые, изменённые, скопированные и неоднозначные зоны останавливают формирование таблицы/файла. Слой берётся у проверенной штриховки. Парапетный путь не переведён на новый формат этой правкой.
- **ATCLAD/ATTILE** проверяют полный набор частей файла `_fzones.json`, исходные полилинии и штриховку, включая автоматически добавленные участки прежней общей раскладки. Ошибка одного участка останавливает весь запуск. Частичная замена общей группы A+B, в том числе при переходе между командами, не удаляет оставшуюся часть.
- **Раскладка** хранит снимок всего исходного набора запуска: наружные контуры, проёмы и версии зон. Перед сохранением метки источники проверяются повторно. Каноническая штриховка зоны хранит последнюю версию раскладки; старая марка не может передать прежние оси после нового запуска с другими параметрами.
- **ATFRAME** подтверждает источник осей до их чтения, принимает только проверенные части зоны и требует полный набор сохранённых источников раскладки. Пропущенное ранее учтённое окно или часть A+B вызывает отказ до изменения подсистемы. Ручной путь по полилиниям без меток сохранён.

Общий код находится в `Common/` и включается исходником в каждый из трёх проектов. Новая общая DLL, зависимость бандлов друг от друга и изменение JSON-контракта `facade_zone/1` не вводятся.

Сравнение контуров учитывает вершины и дуги, а также циклическую смену начальной вершины и обратный обход с правильным знаком bulge. Геометрический допуск — 0,001 мм. Хеш используется для целостности и версии записи; соответствие текущему чертежу доказывается отдельным численным сравнением. Короткая замыкающая дуга не отбрасывается как обычный микрозазор.

## Работа с существующими чертежами

Для старых зон без проверяемого снимка нужно повторить ATFZONE по исходному контуру и всем проёмам. Старые штриховку и марку удаляют вручную, сохраняя исходные полилинии; команда не обещает автоматическую замену всех старых носителей. Затем обновляют раскладку и подсистему. Руководство предлагает новичку начать с отдельной чистой версии исходников.

Снимок раскладки намеренно охватывает весь набор одного запуска. Поэтому ATFRAME может потребовать выбрать все его исходные объекты, даже если отдельные зоны геометрически независимы. Альтернатива — создать самостоятельную раскладку нужного участка. Выбор только части не считается подтверждением отсутствующих проёмов.

Копия общей раскладки по полилиниям требует особой осторожности: пока сохранены совместно скопированные плитки, автоматическая частичная замена запрещена. Работают в копии DWG, вручную отделяют и удаляют только скопированные плитки, затем выбирают весь набор исходников с окнами. Для старых меток без проверяемых ссылок используют новые самостоятельные исходные контуры после проверки и очистки копии. Оригинал программа не использует для автоматического добора копии.

## Проверка и её пределы

Исполняемые проверки и точные результаты хранятся в `geometry_logs/`. Чистые C#-тесты проверяют геометрическое сравнение. Адаптерные тесты исполняют настоящие guards с заменами CAD API и используют результаты настоящего Python-движка для свежей одиночной и объединённой зоны. Проверки потребителей исполняют методы AFrame с контролируемыми результатами guards. Отдельная проба настоящего RemoveData подтверждает удаление старой метки и её снимка геометрии при переключении раскладки, включая оставшийся без метки снимок (41/41). Полная компиляция трёх плагинов выполняется отдельно с официальными AutoCAD.NET 24.0.0/net48 references.

Эти проверки не запускают AutoCAD. Нужна живая приёмка создания ассоциативной штриховки, изменения её границ, COPY полного комплекта/одной марки, повторной раскладки через марку и штриховку, Undo, SaveAs, отмены и сохранения DWG. Реальные снимки окон AutoCAD в этой среде не получены.

Новое, ещё не включённое в ATFZONE окно не обнаруживается по сохранённым ссылкам автоматически: его надо выбрать при повторном создании зоны. Файл `_fzones.json` остаётся отдельным от DWG; несовпадение вызывает отказ, но совместная атомарная запись двух файлов и полная согласованность при Undo/SaveAs этой правкой не реализованы.

Поддержка дуговой раскладки не добавлена. Команды AutoCAD отклоняют сырой контур с дугой до передачи движку, чтобы неподдерживаемое отверстие не исчезло при определении вложенности. Для прямого JSON/CLI-вызова AClad остаётся отдельный воспроизведённый дефект сырого дугового проёма; два ожидаемых отрицательных результата в `test_clad_source_completeness.py` обозначают этот предел явно. Полная зона с дуговым проёмом отклоняется целиком. Это не заявление о полной поддержке произвольных входов CLI.

Изменения относятся только к фасадам. `ATableSpec/` и `ABlockGen/` не изменены; `main` и установочные выпуски не затронуты.
