# Руководство начинающего пользователя фасадных модулей

Откройте **[Facades_Beginner_Manual_30.09.docx](Facades_Beginner_Manual_30.09.docx)**. В руководстве 47 страниц, 20 глав и 10 схем: от первого запуска AutoCAD и подготовки контуров до зон, раскладки, подсистемы, ведомостей и исправления типовых ошибок.

**Эта редакция относится к исходникам после build-bundle #104; этапы 2Б1 и 2Б2 ещё не включены в установочный выпуск.** Сначала прочитайте раздел «Какой версией пользоваться» и сверьте `SOURCE_COMMIT.json`. Для выпущенного build-104 сохранено [руководство этапа 2А на 42 страницах](https://github.com/zinchenko-denis/AutoCAD/blob/60f3b3587c8d09780e5c7a703f010de690f73e2b/docs/facades_beginner_3009/Facades_Beginner_Manual_30.09.docx). Обновлять AFacades, AClad и AFrame необходимо вместе.

В главе 8 описаны **ATFTABLE → Облицовка** и **ATFTABLE → Подсистема**: выбор области, группировка, предпросмотр с примечанием, DWG/XLSX и обновление выбранной таблицы. Для облицовки отдельно показан раскрой; для подсистемы — фактические детали, длины, итоги по категориям и отдельная оценка хлыстов, которая не является закупкой. Объяснены известный ноль, неполнота, проверка всех источников, сохранение прежней выдачи при Esc и режим только кляммеров. Разделы 8.7–8.8 описывают «Ручные → Импорт/Исключить»: явный образец и свойства, проверку всех выбранных объектов, совместный учёт, копии, изменённые и утраченные детали. Раздел 8.9 описывает новый вид «Подсистема → Соединения»: геометрические кандидаты опор, интервалы и свободные концы с явными неизвестными сведениями об узлах. Первый паспорт ограничен предустановкой «Вектор-1», вертикальной схемой и керамогранитом; основной бетонный учебный пример получает явное объяснение отсутствия паспорта. Обычный вид «Элементы» выбран по умолчанию. Полная закупочная спецификация остаётся следующим этапом.

Глава 13 обновлена после проверки статической схемы: межэтажный расчёт недоступен до подтверждения модели соединений и непрерывности; ручная геометрия требует отдельного проекта. Для вертикальной и ортогональной систем проверяются фактические геометрические опоры каждого куска вертикального профиля и применённый класс пролётов. Даже успешный ограниченный расчёт не подтверждает статическую модель всего каркаса. Действия при отказах добавлены в главу 16.

Новый подраздел главы 13 описывает **ATFRAME → Решение и каталог…**: явный выбор Вектор-1 2015, типа 1, листа 4.2.1; отдельные исполнения и параметры КР2/УК/ГП; проектные b/c без скрытых значений. Вынос наружной поверхности и слои утеплителя отделены от плеча расчёта. Описаны отказ расчётного режима, сохранение выбора с перестроенной зоной, смешанный выбор зон и чтение без изменения при повторе только кляммеров. Выбор не подтверждает совместимость сборки, прочность, фактический монтаж или закупку; параметры проекта и зон описаны в следующем подразделе 2Б2.

Глава 13 также описывает **ATFPROJECT** и **ATFZONEPARAMS** для того же пилота Вектор-1: явное создание проекта в одном DWG, привязку настоящих зон ATFZONE, флажок «Своё значение», наследование и явную очистку необязательных полей. Показаны просмотр перед записью, отмена, снятие привязки, отдельная обработка разных решений и полное перестроение после изменения зависимостей. ATFRAME читает привязанные параметры; автоматического пересчёта всех зон нет. Для 2Б2 сохранены все инженерные ограничения 2Б1.

## Учебные файлы

| Файл | Для чего |
|---|---|
| [01_source_rect.dxf](assets/01_source_rect.dxf) | Первое упражнение: стена6000×6000 мм и два окна |
| [02_source_gable.dxf](assets/02_source_gable.dxf) | Второе упражнение: фронтон со скатами |
| [03_reference_rect.dxf](assets/03_reference_rect.dxf) | Геометрический результат прямоугольного примера для сравнения |
| [04_reference_gable.dxf](assets/04_reference_gable.dxf) | Геометрический результат облицовки фронтона для сравнения |

Скопируйте исходные DXF в свою учебную папку. Откройте в AutoCAD и сохраните как DWG. Выполняйте команды по руководству; файлы `reference` открывайте отдельно для сравнения. Они не содержат служебных меток плагинов, поэтому не служат готовыми проектами для повторного расчёта. Элементы подсистемы в учебном примере заданы ручными шагами и не являются монтажным решением.

Изображения — учебные схемы из ответов движков, а карты полей сохраняют базовый интерфейс до каталога 2Б1. Новые поля 2Б1 и 2Б2 описаны текстом. Это не снимки работающего AutoCAD. Происхождение и техническая проверка описаны в [SOURCES_AND_QA.md](SOURCES_AND_QA.md).

## Для продолжения разработки

- `manual_content.md` — редактируемый текст.
- `generator.py` — генерация десяти изображений, четырёх DXF, запросов/ответов и проверок геометрии; нужны matplotlib, Shapely и ezdxf. Продуктовые движки остаются без этих зависимостей.
- `build_manual.py` — сборка Word через python-docx и Pillow. После изменения текста или изображений нужно заново собрать документ, отрендерить и проверить каждую страницу.
- `SOURCE_COMMIT.json` связывает итоговый Word с коммитом продукта и проверенными хешами исходников. `assets/source_manifest.json` сохраняет исходные данные на момент генерации.
- `replay_examples.py` повторяет пять сохранённых учебных запросов без изменения рисунков и DXF. Для новой ревизии задавайте `--out` с новым путём. Проверка этапа 2Б2 — `../project_params_0110/manual_examples.json`; предыдущие проверки 2Б1, 2А и статической ревизии сохранены отдельно.

Регенерация выполняется из корня репозитория:

```bash
python docs/facades_beginner_3009/generator.py
python docs/facades_beginner_3009/build_manual.py
```

Состояние исправлений и живые проверки, которые предстоит провести в AutoCAD, перечислены в [FIXES_30.09.md](../FIXES_30.09.md). Применимость расчёта к фактическому каркасу разобрана в [STATIC_MODEL_REVIEW_30.09.md](../STATIC_MODEL_REVIEW_30.09.md).

Блок облицовки описан в [CLADDING_QUANTITIES_30.09.md](../CLADDING_QUANTITIES_30.09.md). Проверки этапа 2А сохранены в `../catalog_connections_0110/verification_manifest.json`; ручных ведомостей — в `../manual_quantities_0110/verification_manifest.json`; подсистемы — в `../frame_quantities_3009/verification_manifest.json`; первоначального блока облицовки — в `../quantities_3009/verification_manifest.json`.
