# Отмена ручного ввода осей ATFRAME

Исходный дефект воспроизведён на `b64eb0aedccb41ba5cb1e253c9eddf69142284b3`:
после точки X=600 статус `Cancel` завершал цикл так же, как `None` (Enter).
При обычных ручных шагах 800 мм оба пути давали одинаковый запрос и ответ
реального движка: одна направляющая и четыре символа кронштейнов.

Исходный файл `AFrame/src/AFramePlugin/FrameCommand.cs` побайтово сверен с
`git show` указанного коммита. SHA-256:
`944d50dc7db753b931437691ca116a5cb6b07f6e84a7507265936b535274ad80`.
Полная копия исходного файла и сборочные бинарники здесь не хранятся.

Исправление добавляет отдельный `Cancel → сообщение → return` перед прежним
условием завершения по Enter. После исправления `OK → Cancel` заканчивает
извлечённый участок; запрос движку не создаётся. `OK → None` по-прежнему
даёт одну направляющую и четыре кронштейна. Первоначальные Cancel и пустой
Enter также заканчивают участок. Два существующих оператора `Mode == "frame" → rowsY.Clear()` также
извлекаются дословно: рассчитанные ряды 605/1210/1815/2420 очищаются перед
передачей реального `rowsY` в запрос, как в исходной команде.
Проверены фактические `FrameSettings`,
их сохранение/восстановление и `Validate(false)`: керамогранит, ручной шаг
800, оси по точкам, историческое заявление единственного пилота Вектор-1
2015 / тип 1 / узел 4.2.1, режим только подсистемы, без запроса углов и этажей.

`before/` — исходное поведение, 38 проверок воспроизведения дефекта;
`after/` — исправленное поведение, 33 проверки. Разница числа проверок
обусловлена отсутствием продолжения и запуска движка после исправленной отмены.
`regression_sensitivity.json` подтверждает, что обычный режим проверки
`--expect fixed` отвергает сохранённый исходный блок с кодом возврата 1
на утверждении `axis continuation matches fixed: point_cancel`.

Manifest содержит байтовые хеши репозиторных зависимостей и всех JSON
результатов. `command_source` в исходном manifest указывает фактический
scratch-файл сеанса; его независимая привязка к Git находится выше и в
`regression_sensitivity.json`. `actual_segment_sha256` и `continuation_rows_segment_sha256` считаются от текста
с нормализованными LF после `read_text`; хеш сгенерированного C# файла —
от его фактических байтов. Сгенерированный файл остаётся в scratch/CI build.

Воспроизведение из корня репозитория при доступном Mono либо Windows
.NET/net48 (тот же `probe_runtime`, что в остальных native проверках):

```bash
axis_tmp_dir=$(mktemp -d)
git show b64eb0aedccb41ba5cb1e253c9eddf69142284b3:AFrame/src/AFramePlugin/FrameCommand.cs > "$axis_tmp_dir/FrameCommand.cs"
python tools/limited_pilot_0110/test_axis_cancel.py --source "$axis_tmp_dir/FrameCommand.cs" --expect broken --out "$axis_tmp_dir/before"
python tools/limited_pilot_0110/test_axis_cancel.py --out "$axis_tmp_dir/after"
# Ожидаемый отказ fixed-проверки на исходном продукте: exit 1.
python tools/limited_pilot_0110/test_axis_cancel.py --source "$axis_tmp_dir/FrameCommand.cs" --expect fixed --out "$axis_tmp_dir/sensitivity"
```

Исполняется точный извлечённый блок ввода осей с явными prompt doubles.
Проверка структуры исходного `RunCore` связывает его выход с расположенными
далее захватом источников, вызовом движка, блокировкой записи CAD и fresh guard.
Полная команда, клавиша Esc в живом AutoCAD и откат CAD-транзакции здесь
**NOT_RUN**. Исправление предотвращает продолжение до этих стадий; оно не
выдаётся за проверку отката. Инженерный допуск остаётся **BLOCKED**.
