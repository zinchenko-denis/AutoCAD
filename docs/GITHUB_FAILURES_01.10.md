## Что произошло

GitHub API подтверждает run [36827058283](https://github.com/zinchenko-denis/AutoCAD/actions/runs/36827058283),
номер 203, статус `failure`. В подписи снимка указан `pull_request`,
тогда как API этого запуска сообщает `event: push`; идентификация сделана
по номеру запуска, SHA и упавшему шагу, а не по подписи интерфейса.

Компиляция и проверки ведомостей/соединений прошли. Шаг

Это дефект компоновки программы; подтверждений ошибки доступа к GitHub
в этом уведомлении нет. Последующие шаги были пропущены из-за отказа проверки.

## Правила дальнейшей работы

1. Сверять уведомление с фактическими run ID, SHA и логом шага. Старое письмо
   само по себе не доказывает отказ текущей ветки.
2. Различать ошибки программы, инфраструктуры запуска и авторизации.
   Разрешение доступа не исправляет неуспешный тест.
3. Сохранять отказ, причину, исправление и новый результат. Не стирать
   неуспешную историю и не ослаблять проверку ради её прохождения.
4. Для UI сверять реальную видимую область Windows и просматривать PNG:
   совпадения внутренних размеров WinForms оказалось недостаточно.
5. Публиковать только проверенный код рабочей ветки. Документальное
   подтверждение может следовать отдельным коммитом и ссылаться на точный
   проверенный продуктовый SHA. Новый установочный выпуск — только по
   отдельной команде «Собираем»; `main` не изменять.

Эти проверки не являются живой приёмкой AutoCAD. Полный сквозной пилот
сначала ограничен одной вертикальной системой и одним альбомом — см.
[маршрут](FACADE_COMPLEX_ROADMAP_30.09.md).

## Новый срез 2Б2: публикация прошла, запуск CI не появился

Исходники `b1b4230a4cfb5f53bc6e31f63254cc9dc80789f6` опубликованы в
`feat/auto-reactor`; git fetch подтвердил SHA и точное равенство дерева.
Локально прошли 52 группы, компиляция трёх фасадных плагинов и восемь полных
сценариев. Повторные запросы API для этого SHA возвращали ноль workflow runs,
check runs и check suites. Это **не неуспешный тест**: запуска ещё нет.
Причина не установлена; утверждать отказ прав или общий сбой GitHub нельзя.

У коннектора есть чтение запусков и повтор существующих jobs, но нет
`workflow_dispatch`. Повтор старого #205 проверил бы старый код, поэтому
он не выдаётся за проверку 2Б2. Проверки и права workflow не ослаблялись.
Нужно запустить `check` на `feat/auto-reactor`, убедиться в правильном SHA,
дождаться завершения и просмотреть все 10 прежних и 11 новых снимков окон.
Правила браузерного инструмента требуют отдельного разрешения пользователя
для перехода от недостаточного коннектора к браузеру; автоматического
перехода или запроса нового токена не выполнялось.

Операции публикации в этой сессии прошли без повторного подтверждения.
Это не обещание бессрочного режима «разрешать всё». Точный незакрытый статус
сохранён в `project_params_0110/github_publication.json`; следующая сессия
должна начать с него, не с расширения каталога.

## 01.10: разрешённый браузерный запуск проверки 2Б2

Денис явно разрешил дальнейшее использование браузера для необходимых
действий этого проекта, когда подключённый GitHub API не предоставляет
операцию. Повторно спрашивать это же разрешение не требуется. Это не
обещание бессрочной авторизации и не разрешение отключать защиту аккаунта.

Сессия браузера первоначально не была авторизована, хотя API уже работал.
Вход выполнен через защищённую форму и подтверждение устройства самим
пользователем. Один запрос GitHub Mobile истёк; штатный повтор с последующим
подтверждением завершился успешно. Секреты, идентификаторы сеанса и снимки
входа в репозиторий не сохраняются.

В авторизованном интерфейсе запущен именно `check`, ветка `feat/auto-reactor`:
[run 36839324289 / №206](https://github.com/zinchenko-denis/AutoCAD/actions/runs/36839324289),
`workflow_dispatch`, SHA `6bd91ead2c03e0f7220cc2db02ce2d6c88148774`.
Этот коммит отличается от продуктового `b1b4230` только документацией.
Запуск нового workflow подтверждён UI и API; прежний запуск не переиспользован.
Итог CI и независимый просмотр PNG фиксируются отдельно в паспорте 2Б2.
`main`, права workflow, настройки безопасности и установочные выпуски
этим действием не изменены.

Запуск №206 завершился с `failure`: три фасадные компиляции прошли,
но два случая `SettingsContractProbe` отклонили повтор одного и того же
выбора (1000 разных корней и 100 псевдонимов одного корня). До WinForms
проверка не дошла; PNG отсутствуют. Краткое свидетельство —
`project_params_0110/ci_206_failure.json`. Это ошибка сравнения данных в
проверяемом коде, а не запрос дополнительных прав GitHub.

Прежний `FrameSolutionSelection.Same` сравнивал JSON-строки типизированных
объектов; порядок свойств reflection не является смыслом выбора решения.
Исправление сравнивает все поля непосредственно, точно и без сериализации
внутри сравнения. Не допускается округление размеров или пропуск различий
в источнике, редакции, составе и порядке слоёв. В следующем Windows-запуске №207 диагностика воспроизвела этот механизм:
20/200 сравнений одного объекта дали разный порядок полей при одинаковых
значениях. Новое сравнение прошло 70 проверок, включая оба прежних отказа.
Исходные отличающиеся JSON именно №206 не были записаны; эта граница
доказательства сохранена в `ci206_equality_review.json`.
