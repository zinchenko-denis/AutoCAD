## Смысл нового прохода

Прежние роли заканчивались геометрическими движками, а store-тесты
частично использовали отдельно собранные отчёты. Поэтому их нельзя было
называть одним приёмочным проходом. Новый стенд должен переносить одни
реальные запросы/ответы, ID, версии и зависимости через общий процесс
с одной базой CAD doubles. Снимок источников снимается до расчёта;
новые зависимости нельзя прикрепить к старому ответу.

Вход — две отдельные стены 1210×1820 мм, плиты 600×600 и швы10;
обычный ручной каркас 800/800. Независимые ожидания: 12 целых плит,
4,32 м² установлено при площади зон 4,4044 м²; две направляющие
по1820 мм и шесть условных кронштейнов. Это новый синтетический вход,
не частный проект и не прежний бетонный урок 6000×6000.
Сопоставление зон выполняется по исходным контурам/геометрии, не индексу.

Для каждой зоны — отдельные ATTILE/ATFRAME операции в одном проекте.
Так проверяется независимость их run ID: изменение проекта230→240
делает устаревшими оба зависимых каркаса; исключение наружной облицовки260
только справа не меняет прежний актуальный run слева. Количества остаются
прежними, поскольку заявление не назначает физическую монтажную сборку.
У общей операции на две зоны область свежести была бы общей — это
другое предусмотренное поведение, не ошибка адресного обновления.

Схема использует явные плоскости150/170 и локальный просвет20 мм.
Настоящие Snapshot/Geometry/Drawing/Mounting работают на том же
разрешённом контексте. Извлечённый дословный predicate актуальности
не равен исполнению полного ATFNODE command/store/renderer в общей базе.
Физического УК, подтверждённых product ID и двух монтажных интерфейсов
по-прежнему нет; количество кандидатов не является комплектностью.

## Исправление отмены

В настоящем FrameCommand воспроизведено: после одной ручной оси
`OK → Cancel` продолжал команду как `OK → None` (Enter).
Добавлен ранний выход на Cancel до источников расчёта, движка и CAD prewrite.
Enter продолжает прежний разрешённый путь. Проверка исполняет точный
осевой блок и существующую очистку rowsY режима frame с настоящими
FrameSettings; полная команда и native Esc этим не исполняются.

Этот контроль отделён от основного потока: после ATTILE оси уже есть,
поэтому ручной запрос там не появляется. Человеческий контроль выполняется
на исходной замкнутой полилинии без ATTILE, с тем же явно выбранным пилотом.
Его 1ГП/4 кронштейна на другом входе не смешиваются с основными 2ГП/6.
Before replay и чувствительность регрессии к старому коду сохранены
в `limited_pilot_0110/axis_cancel/`; продуктовый diff должен быть узким.

## Честные границы и следующий шаг

Успех доступного адаптерного потока не закрывает полный П5 или живую
приёмку. Табличные модели и реальные XLSX отличаются от AutoCAD Table
в DWG. JSON roundtrip отличается от Save/Close/Open. Ручное копирование
Xrecord со старыми ссылками отличается от native COPY/remapping/SaveAs.
Transaction.Commit/Dispose у QuantityCadDoubles пустые: rollback CAD
на них не доказан. Файловый rollback XLSX проверяется отдельно.

Следующий доступный программный участок определяется по матрице
`LIMITED_PILOT_ACCEPTANCE_01.10.md`: связать оставшийся жизненный цикл
узла/табличной команды с тем же фиксированным входом, сначала воспроизведя
его конкретный пробел. Не заменять это ещё одной серией предупреждений
о кандидатах. Используй уже существующие command/store probes и
ограничивай адаптеры реальным сценарием; при отсутствии host явно
фиксируй NOT_RUN. Человеческий маршрут находится в
`limited_pilot_0110/human_acceptance.md` и не является протоколом приёмки.

П2–П4 плана остаются инженерно закрыты: реальные сборки и два интерфейса,
монтажные посадки/диапазоны, отверстия/метизы, кинематика/температура,
грузовой путь и работа стыка не выводятся из совпадения марок или min20.
Номинальные базы0/2/2+L и неизвестный h сохраняются; min30 других узлов
и165−80=85 не назначают полный ход4.2.1. Вес наL1 не задаёт все реакции.
`MountingStatus=not_confirmed`, `AutomaticBracketSelectionAllowed=false`
и `E_SOLUTION_CALC_UNCONFIRMED` сохраняются. Ограниченная живая приёмка
сама по себе не разрешает расширение каталога; нужна полная приёмка
пилота либо отдельное изменение цели Денисом.

## Скорость, проверки и публикация

Один проверенный DTO-снимок на фазу операции, индексы ID/ссылок;
никаких CAD API в чистом расчёте/фоне, новых полных ModelSpace обходов
или пересчёта из реактора. Не переносить кеш через диалог/изменение DWG.
Замеряй стадии и счётчики на одинаковом входе; время стенда не называется
временем AutoCAD. Исправление Cancel не добавляет чтений и предотвращает
ненужное продолжение после отмены.

Перед кодовым коммитом — адресное воспроизведение, актуальный полный
набор CLAUDE, компиляция трёх фасадов и независимая ревизия. Full-synth
переиспользуется только после точной сверки зависимостей: прежние44
не включают FrameCommand, но обязательный набор/compile и применимость
руководства включают его. Затем Windows check точного SHA, проверка
артефактов и затронутых UI-снимков. Руководство не пересобирается ради
даты; после изменения продукта нужна предметная проверка применимости,
а не ложное утверждение, что все его входы неизменны.

Код, проверки, воспроизведение, причины и ограничения сохраняются в
`feat/auto-reactor`; handoff/NEXT/CLAUDE, план, хронология и промт обновляются.
Первый способ публикации — подключённый GitHub API, с проверкой удалённого
родителя непосредственно перед fast-forward. Отсутствие gh auth не требует
PAT. Приватные оригиналы/рендеры и секреты не публикуются.

ATableSpec, ABlockGen и main не менять. Новые системы/альбомы/СФТК
не начинать. Выпуск — только по новой команде Дениса «Собираем».
Подтверди восстановленное состояние и продолжай следующий конкретный шаг.
