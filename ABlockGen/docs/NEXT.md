# ABlockGen — состояние и хэндофф (ЧИТАТЬ ПЕРВЫМ)

> **Это проект ABlockGen (быв. VitrageGen; имя — решение Дениса 13.07:
> английское, «построитель блоков», парно к ATableSpec) — генератор
> витражей/конструкций из блоков, сосед ATableSpec в монорепо
> `zinchenko-denis/AutoCAD`. НЕ путать с LD/физикой.** Это ОТДЕЛЬНАЯ
> программа (свой бандл ABlockGen.bundle, своя DLL ABlockGenPlugin, свой
> движок) — с ATableSpec связана только блочным контрактом и общим репо
> (монорепо: общий CI и тест-данные — решение 11.07). Мандат ATableSpec —
> `ATableSpec/docs/NEXT.md` (грабли среды/сборки/push — ТАМ, здесь не
> дублируются и обязательны к прочтению). Ветка общая: `feat/auto-reactor`.

## TL;DR
- **Что:** чертёж АР (DWG/DXF) → витраж/светопрозрачная конструкция ИЗ БЛОКОВ.
  Отдельная программа со своим бандлом и py-движком (гибрид-паттерн ATableSpec:
  тонкий C# + замороженный exe, JSON через временные файлы).
- **Зачем отдельная:** направление данных обратное (ATableSpec: блоки→таблица;
  здесь: геометрия→блоки), движок отчётов заморожен и в бою, риск-профили и
  релизные циклы несовместимы. Решение зафиксировано 11.07.
- **Связка:** блочный КОНТРАКТ (`docs/CONTRACT.md`) — генератор выпускает ту же
  номенклатуру (слои RF-*, ИМЯ/ПРОФ/ДЛИНА/МАРКИРОВКА/РАЗМЕР_ЗАП, анонимно-
  динамические вставки), которую ATableSpec ест без правок. Acceptance связки:
  «сгенерил витраж → спецификация и раскрой сходятся».
- **Статус (13.07, старт проекта):** Э1-скелет ПОЛНОСТЬЮ написан: движок +
  45 юнитов + 33 сверки с эталоном (зелёные локально), C#-команда ATVITRAGE
  (mcs --parse чистый; полная компиляция — CI check), бандл-манифест, CI
  расширен. НЕ выкладывалось, Алексей не видел. Рантайм в AutoCAD не проверялся.
- **Статус (13.07b, Э3-прототип по реальному АР):** Денис прислал «Проба 3.dxf»
  (АР-витраж Revit-вставками + ручной КМД-эталон Алексея) с workflow:
  «Укажите блок стоек → блок ригелей → конструкцию» → каркас. РЕАЛИЗОВАНО:
  движок `vitrage_recognize.py` (32 юнита + 23 D2-сверки: распознанный план
  == ручной каркас Алексея, оси ≤0.5 мм, ДЛИНА байт-в-байт), команда
  **ATVITRAGEAR** (`RecognizeCommand.cs`), единый CLI `vitrage_engine.py`
  (op: plan|recognize). Файл — `atspec-testdata/dxf/ar/Проба_3.dxf`.
  Правила распознавания — CONTRACT.md §Э3. Заполнения/двери/окна Э3 НЕ ставит —
  каркас only (двери/окна вставляют утилиты Алексея; его постановка).
- **Статус (13.07c, решения Дениса по развилкам + доделки):** Э1 — всё как
  реализовано (отметки списком мм; марки по типоразмерам; ДЛИНА ригеля =
  осевой шаг подтверждён; обвязочные — списком). Имя: **ABlockGen**.
  Э3-решения: (A) **опциональный образец ВЕРХНЕГО ригеля** — третий запрос
  ATVITRAGEAR (Enter — обычный): вся верхняя отметка идёт этим блоком
  В СВЕТУ между телами (как Р31/Р33 эталона); (B) деталировка — дефолт
  (исходное определение, «0», пишем только ИМЯ/ПРОФ/ДЛИНА); (C) марки —
  всегда с 1; (D) разрывы вертикалей — сливать (note); (E) **сборка полос
  из ГОЛЫХ ОТРЕЗКОВ** заложена сразу: `segments[]` в запросе, пары
  параллельных отрезков (40..120 мм, перекрытие > max(w,50)) → полосы,
  дедуп дублей; C# шлёт LINE и ломаные полилинии сегментами, замкнутые
  ≤5 вершин — bbox-полосой, дуги пропускает. Итог: **47 юнитов + 34
  D2-сверки — план с rigel_top воспроизводит ручной каркас Алексея
  ПОЛНОСТЬЮ (все 11 ригелей, включая верхние в свету, ДЛИНА байт-в-байт);
  R11 — тот же витраж «голыми линиями» распознаётся идентично.**

## Этапность (решение 11.07; каждый этап — рабочий продукт)
- **Э1 (ТЕКУЩИЙ): полуавтомат БЕЗ распознавания** — проём рамкой/контуром +
  диалог параметров (шаг стоек, отметки ригелей, ярусы, блоки) → сетка
  стоек/ригелей/заполнений ВХОЖДЕНИЯМИ существующих определений блоков чертежа
  (как Алексей руками; свои определения НЕ выдумываем).
- **Э2:** автозахват габарита проёма кликом внутрь контура.
- **Э3:** членение по нарисованным импостам АР.
- **Э4:** пакетно по фасаду.
- Гейт Э2/Э3 — **2–3 реальные АР-подложки от Алексея** (DWG→DXF; класть в
  `atspec-testdata/dxf/ar/`). Наблюдение: в эталоне есть АР-слои
  `_АР_ВИТРАЖ_*` со структурой (см. CONTRACT.md) — если реальные АР такие,
  Э3 сильно упрощается; но источник один, вердикт рано.

## Архитектура (гибрид — как ATableSpec)
- `src/ABlockGenPlugin/` → `ABlockGenPlugin.dll` (net48, AutoCAD.NET 24.0.0,
  JavaScriptSerializer, WinForms). Файлы: `Plugin.cs` (IExtensionApplication,
  минимум), `VitrageCommand.cs` (ATVITRAGE), `VitrageForm.cs` (диалог).
- `engine/vitrage_engine.py` — единый CLI (op: plan → vitrage_plan.build_plan,
  recognize → vitrage_recognize.recognize); при релизе замораживается в
  `vitrage_engine.exe <req.json> <out.json>`. Движок ЧИСТЫЙ (никакого DXF):
  вся работа с чертежом — на стороне C#. Файлы: `Plugin.cs`,
  `VitrageCommand.cs` (ATVITRAGE, Э1), `RecognizeCommand.cs` (ATVITRAGEAR, Э3),
  `VitrageForm.cs` (диалог Э1).
- Поток ATVITRAGE: GetPoint+GetCorner (проём, UCS→WCS) → список определений
  блоков чертежа → диалог (предвыбор эталонных 17_07_24/17_06_01/СТП) →
  JSON-запрос → exe → JSON-план → вставка вхождений одной транзакцией
  (= один undo): BlockReference + динсвойства ДО атрибутов (растяжка меняет
  представление; атрибуты сеются из br.BlockTableRecord ПОСЛЕ установки dyn).
- JSON-план: `inserts[] = {kind, block, layer, x, y, rot, dyn{}, attrs{}}` —
  C# вставляет один цикл без ветвлений по kind; `summary`, `notes[]`.

## Правила Э1 (в движке, доказаны эталоном — см. CONTRACT.md)
- Оси стоек: крайняя = край проёма + тело/2; далее шаг слева направо
  (остаточный последний пролёт + note) ЛИБО n_cols равных долей.
- Ярусы стоек: список длин + зазор (терморазрыв 10); пусто = вся высота.
  Несходимость сумм с высотой проёма — note, считаем как задано.
- Ригели: на каждой отметке (осевые Y от низа, список пользователя) в каждом
  пролёте; «Длина» и атрибут ДЛИНА = ОСЕВОЙ шаг пролёта.
- Заполнения: ячейки светов; свет < min_fill (50) — пропуск (щель);
  РАЗМЕР_ЗАП = округл(свет)+fold(15), Х кириллическая (U+0425).
- Марки: по типоразмерам (одинаковый размер = одна марка): С{n}/Р{n}/Сп{n},
  шаблоны в диалоге.

## Развилки — ЗАКРЫТЫ Денисом 13.07 (решения)
Э1: (1) отметки ригелей — СПИСКОМ мм (как реализовано); (2) марки —
по типоразмерам, л/п и типы заполнений НЕ тянем; (3) ДЛИНА ригеля =
осевой шаг — ПОДТВЕРЖДЁН по эталону; (4) обвязочные — списком отметок;
(5) имя — **ABlockGen** (переименовано 13.07).
Э3: (A) опциональный образец верхнего ригеля — СДЕЛАНО (третий запрос,
Enter — обычный); (B) деталировка — дефолт, СДЕЛАНО; (C) марки всегда
с 1 — так и было; (D) разрывы — сливать (дефолт), так и было;
(E) полосы из голых отрезков — ЗАЛОЖЕНО сразу (`strips_from_segments`).
Открытым остаётся только вопрос ПРАКТИКИ (не кода): как Алексей решает,
ГДЕ нужен верхний ригель-в-свету — уточнится на его рантайм-проверке.
