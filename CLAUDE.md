# AutoCAD — плагины для фасадов

Этот файл Claude Code читает сам в начале каждой сессии (локальной и облачной).
Общение — по-русски, простыми словами, без внутренних кодов; числа сначала
проверить, потом писать. Честность важнее лести.

## Производительность фасадного комплекса

- Решение Дениса 01.10: сначала пройти весь цикл на одном пилоте — Вектор-1, альбом 2015, тип 1, керамогранит, узел 4.2.1 / PDF 20 (КР2 + УК + ГП). До живой приёмки этого пути в AutoCAD не расширять каталог на остальные системы/альбомы и не начинать реализацию СФТК. Существующие области и их отказы сохранять; архив целиком заново не описывать.
- В журнале сохранять не только итог, но и воспроизведение, причину сбоя, исправление, проверенный коммит и оставшиеся ограничения. Успешный CI не заменяет просмотр снимков UI и живой AutoCAD. Разбор уведомлений GitHub — `docs/GITHUB_FAILURES_01.10.md`.
- Скорость и память — обязательные критерии новых расчётов/ведомостей. История медленных проектов 26.09b/c находится в `AClad/docs/NEXT.md`; прототипы, пакетное клонирование и неассоциативные заливки не отменять.
- Сначала воспроизводить задержку и отделять CAD-извлечение/проверку, чистый расчёт, отрисовку и запись паспорта. Стенд без AutoCAD не доказывает время живого DWG.
- Чистое ядро работает с DTO. Не обращаться к CAD API из циклов расчётных вариантов и фоновых потоков. Не запускать полный пересчёт/обход DWG из реактора.
- Общие источники проверять один раз в пределах read-only операции; кеш не переносить через диалог или изменение DWG. COPY и повреждённые ссылки не пропускать ради скорости.
- Паспорт каркаса хранит уникальные источники один раз, новые Entry v2 обоих видов содержат типизированный report; опубликованные cladding Entry v1 остаются читаемыми. Не возвращать вложенную строковую сериализацию больших отчётов и повторную BuildRows в UI.
- Явный исторический выбор — отдельное заявление источника, не установленное изделие. Один неизменяемый каталог на операцию; неизвестные размеры/редакции отклонять. Каталожные b/c не назначают расчётное сечение, вынос до наружной облицовки не подменяет плечо расчёта. Глобальный last не переносит проектный выбор в другой DWG.
- Геометрический паспорт соединений использует координатные индексы и ID того же снимка элементов; не копировать полную геометрию и не искать все кронштейны для каждой направляющей. Совпадения остаются кандидатами, fixed/sliding и непрерывность не угадываются.
- Ручной импорт: явное соответствие образца, один снимок CAD → чистый mapper → свежая проверка → пакетная запись индекса зоны. Не угадывать длину по наибольшему dynamic double или общему bbox; COPY не включать без явного импорта. Один общий ModelSpace scan, словари дублей, кеш подготовленных правил на операцию.
- Масштаб проверять по зонам, деталям и разным типоразмерам; считать CAD-обращения, память, размер записи и число обходов. Времена этапов выводить одной сводкой, без сообщений на каждую деталь. Фиксировать оставшийся технический долг, подробнее `docs/FRAME_QUANTITIES_30.09.md`.

- Схема ATFNODE не является физической деталью; собственный ключ `AFRAME_NODE_GEOMETRY` запрещает её ручную перерегистрацию в ведомости. Проверка читает только свой блок/определение/зону/проект. Не возвращать полный обход ModelSpace или запуск Python для размерной цепочки. Источник min20 — ближайшая поверхность ГП и явно определённая наружная поверхность утеплителя/мембраны; не вынос наружной облицовки.

- Монтажный отчёт ATFNODE использует уже проверенный снимок. Нельзя переводить положительный просвет в пригодность сборки, вычислять вынос как сумму L КР2/УК или объявлять совместимость номиналов без источника. Новые размерные базы вводить только после проверки первичного узла, без переноса проектных плеч расчёта. В 2Б5 условная номинальная цепь 0/2/2+L подтверждена размерными стрелками; h и ход остаются неизвестными. min30 типов 2/3 и проектные 85 мм не превращать в разрешённую регулировку пилота.

ATTILE/ATFRAME/ATFZONE — прогон под mono (`AClad/tools/attile_ui`, `AFrame/tools/frame_ui`,
`Facades/tools/zone_ui`, команды сборки в шапке UiCheck.cs). Запрос движку из окна ATFRAME —
`FrameSettings.EngineParams` (его же зовёт `tools/roles_synth.py` через
`AFrame/tools/roles/RolesDump.cs`): новые поля окна — туда, не в FrameCommand.
После успешного push также дождаться зелёного CI `check`; при красном —
прочитать аннотации. Компиляция и CAD doubles не заменяют живой AutoCAD.

## Сборка («Собираем» — только по слову Дениса)
- Облако (Claude Code cloud): `gh workflow run build.yml --ref <ветка>`, затем
  `gh run list --workflow build.yml --limit 1` → `gh run watch <id> --exit-status`.
  Пушить в другие ветки (build-trigger, main) из облака нельзя — прокси пускает
  push только в рабочую ветку сессии. Если запуск workflow прокси отклонит —
  попросить Дениса нажать «Run workflow» в GitHub Actions (build-bundle, ветка).
- Локально / claude.ai с токеном: ветка `build-trigger` = рабочая ветка + патч
  `branches: [ main, build-trigger ]` в build.yml, force-push (подробно —
  `AClad/docs/NEXT.md`, записи «Собираем»).
- Выкладку проверять СКАЧИВАНИЕМ: `gh release download build-<N>` и `latest`,
  архивы должны совпасть байт в байт; DLL и движки внутри — новые.
- К сборке — PDF Герману (генераторы `*/docs/make_build*_*.py`), в конце
  записи в NEXT.md.

## Облачная сессия: GitHub
- Денис 01.10 явно разрешил использовать браузер для необходимых действий этого проекта, которых нет в подключённом API. Не запрашивать повторно согласие на тот же переход. Браузер и API имеют отдельные сессии авторизации; проверку личности выполняет пользователь через защищённый вход. Это не разрешение отключать защиту аккаунта и не гарантия бессрочной авторизации. История запуска `check` и его фактических результатов — `docs/GITHUB_FAILURES_01.10.md`.
- Актуальное окружение ChatGPT Work (01.10): чтение и публикация выполняются подключённым GitHub API; git fetch доступен. В этой сессии create_blob/tree/commit и update_ref рабочей ветки работали без повторного запроса разрешений. Это наблюдение не гарантирует бессрочную авторизацию приложения и не разрешает обход её ограничений.
- Письмо о `check: failure` сначала сопоставлять с run ID и SHA: это может быть уже исправленная ошибка теста прежнего коммита, а не проблема доступа. Не отключать проверки/уведомления и не повышать права workflow ради зелёного статуса. Для текущего кода дождаться нового CI и сохранить причину прежнего отказа.
- Абзацы ниже описывают другое, историческое окружение Claude/Anthropic. Его proxy-ограничения не переносить автоматически на действующее подключение ChatGPT.
- Токен в облаке НЕ нужен и не поможет: весь GitHub идёт через прокси Anthropic,
  он пускает только репозитории, подключённые к сессии при старте, а push —
  только в рабочую ветку сессии.
- Ошибка «not in this session's authorized repository set» / «Use add_repo» —
  репозиторий не подключён к сессии. Изнутри не лечится: попросить Дениса
  открыть новую сессию с этим репозиторием (и atspec-testdata) в списке.
- Работа облачной сессии приходит отдельной веткой — её сливают в
  `feat/auto-reactor` (PR или локально).
- Окружение: `tools/cloud_setup.sh` (вставить в поле Setup script окружения).
